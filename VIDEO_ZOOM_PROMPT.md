# Задача: видео в просмотрщике постов — немое превью, по клику — медиапросмотрщик со звуком и контролами

Ты работаешь в проекте `/var/www/html/posta` (Posta). Это доработка §4 из `LAYOUT_CENTER_VIDEO_PROMPT.md`. Владелец передумал:
**звук и панель управления прямо в плитке поста не нужны.** Новое поведение — как в ленте Telegram/X:

1. В просмотрщике постов (оверлей и встроенный лист «Подбора») видео **играет само, без звука, по кругу** — живое превью. Никаких контролов на плитке.
2. **Клик по видео** → открывается медиапросмотрщик (зум, `js/viewer.js`) **с той же секунды, сразу со звуком**, с прогресс-баром и прочими кнопками.
3. **Закрыл зум** → превью в посте продолжает играть без звука **с того места, где остановился в зуме**.

Ничего не коммить. Сервер (PHP) не трогай.

## 2. Что сделать

### 2.1 Плитка видео в посте (`post-view.js`)
- Играющая плитка — `<button type="button" class="pv-cell pv-cell-video" aria-label="Видео N из M — открыть со звуком">` с `<video>` внутри
  (`muted`, `autoplay`, `loop`, `playsInline`, `preload="metadata"`, `poster`, `disablePictureInPicture`, **без** `controls`).
  Кнопка, а не div: фокус с клавиатуры, Enter/пробел открывают зум, ловушка фокуса оверлея её подхватит.
- В углу плитки — маленькая метка 🔇 (`aria-hidden`), чтобы было видно, что звук выключен. При наведении — лёгкий намёк:
  по центру полупрозрачный круг с 🔊 / «▶ со звуком» (на телефоне не показывать — наведения нет).
- **Клик** (одно касание на телефоне): `video.pause()`, запомнить `video.currentTime`, `openGallery(media, i, box, ctx, { start: currentTime })`.
- Остальные видео альбома (не первое) — как сейчас: постер с «▶ 0:42»; клик по ним — тоже сразу зум со звуком с нуля (превью не запускать).
- `prefers-reduced-motion: reduce` — превью не играет (постер с «▶»), клик → зум.
- Свайп оверлея по-прежнему не срабатывает от касаний по `.pv-mosaic` (проверь, что короткое касание по видео — это клик, а не свайп).

### 2.2 Старт с той же секунды (`post-view.js` → `viewer.js`)
- `openGallery` принимает `{ start }` и кладёт в элемент видео поле `start` (только в тот элемент, по которому кликнули).
- `viewer.js`: при показе видео, если у элемента есть `start > 0`, — в `onloadedmetadata` выставить `video.currentTime = Math.min(start, duration - 0.1)`.
  Поле одноразовое: при листании галереи ←/→ и возврате на этот ролик он идёт с нуля (как сейчас). Остальной код показа не меняй.
- Звук: зум уже ставит `muted: false, volume: 0.33` и зовёт `play()` в том же клике — браузер разрешит воспроизведение со звуком.
  Проверь, что `play()` действительно вызывается синхронно из обработчика клика (без `await` перед ним), иначе Chrome заблокирует звук.

### 2.3 Возврат из зума с той же секунды
- `viewer.js` `close()`: **до** `stopVideo()`, если показывалось видео, — `window.dispatchEvent(new CustomEvent('viewer-video-closed', { detail: { src, time: video.currentTime } }))`.
  `src` — тот адрес, который пришёл в элементе галереи (не `currentSrc`, он может быть абсолютным / запасным).
- `post-view.js`: слушает это событие; если `view.zoomTile` — играющая плитка и её ролик совпадает по `src` (или по `fallback`) —
  `video.currentTime = time` и `video.play()` (без звука). Совпадения нет (в зуме долистали до другого файла) — просто продолжить превью с того места,
  где оно стояло. Сделай это рядом с `watchZoomClose()`, слушатель — один на модуль, не на каждую плитку.
- Если пока зум был открыт, пост сменился или лист перерисовался (плитка уже не в DOM) — ничего не делать.

### 2.4 Контролы зума на телефоне — только проверить
Панель `#video-controls` видна при наведении, на паузе и при фокусе (`app.css:1290`). На телефоне наведения нет, а клик по кадру закрывает окно.
Проверь на стенде 390 px, что до кнопок можно дотянуться (видео играет → панель видна или появляется по касанию). Если нельзя —
минимальная правка: на устройствах без наведения (`@media (hover: none)`) панель видна всегда. Больше в зуме ничего не переделывай.
