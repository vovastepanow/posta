# Задача: большая карта тем и хэштегов (до ~1000 тем и словарь хэштегов) для современного контента

Ты работаешь в PHP-проекте `/var/www/html/posta`. Проект подбирает картинки, видео и посты из соцсетей по теме,
которую выбирает пользователь. Локальные модели (Ollama: умная `SMART_MODEL` qwen ~9B для картинок, `bge-m3`
для эмбеддингов) оценивают каждую запись. Темы лежат в `lib/topic_tree.php` (`TOPIC_TREE`), метки записи
(`tags`) — это ключи частных тем дерева, их ставит модель полного анализа.

Сейчас в дереве ~22 общие темы и ~110 частных. Этого мало: нет целых пластов современного контента.
Пример, который назвал пользователь, — **«нижний интернет»**. Такие вещи должны быть в карте — темой или хэштегом.

Цель: **подробная карта современного контента** — до ~1000 частных тем и словарь хэштегов (десятки тысяч,
верхняя граница 100 000), и чтобы это **работало на слабом железе**, а не просто лежало в файле.

## Что выяснено (2026-10-23 — перепроверять не нужно)

- `content_tags_prompt_list()` вставляет **все** частные темы в промпт полного анализа, а `content_tags_schema()`
  делает из них `enum` JSON-схемы. При 1000 тем это ~10 000 токенов промпта на каждую картинку и тяжёлая
  грамматика у Ollama. Видеокарта 3 ГБ, умная модель на 94% считается на CPU — **так делать нельзя**.
- `topic_ai_classify()` перечисляет в промпте **весь** реестр тем. При 1000 тем — то же самое.
- 100 000 хэштегов нельзя дать модели списком. Их можно только **искать в словаре** (SQL / массив) по тому,
  что модель написала сама, и по тексту подписи.
- Записи уже хранят `tags` с ключами вида `humor.absurd`, `money.crypto`. На них опираются `content_is_adult()`
  (`lib/content.php`, 18+ по флагу `nsfw` ветки), `lib/quality.php` (вкус по `tags[0]`), UI (`renderTags`).
  **Все существующие ключи частных тем остаются** — названия можно уточнить, ключи нет.
- `topic_similarity()` уже умеет эмбеддинги `bge-m3` на CPU (`num_gpu: 0`). Эндпоинт `/api/embed` принимает
  массив строк — можно считать пачками.
- Твой инструмент WebSearch работает (капчу DDG/Bing получает **сервер**, а не ты). Пользоваться им для
  исследования трендов можно и нужно. Из PHP-кода проекта в поисковики не ходить.

### Что такое «нижний интернет» (сверь через WebSearch, дополни)

Мем-термин русского интернета (2024–2025): странный, нелепый, низкокачественный, «проклятый» контент из глубин
сети — шакальные картинки и видео, сюрреалистичные и бессмысленные ролики, старые странные видео, cursed-фото,
кривые эдиты, контент «для своих», над которым смеются ироничнее, чем над обычным мемом. Противопоставляется
«верхнему интернету» — вылизанному мейнстриму. Рядом: брейнрот (в т.ч. «итальянский брейнрот» 2025),
шитпост, cursed images, лиминальные пространства, «бэкрумс», аналоговый хоррор, ИИ-слоп.
Это пример уровня детальности: **тема** — «Нижний интернет» (ветка интернет-культуры), а **хэштеги** —
`нижний_интернет`, `шакалы`, `cursed`, `проклятые_картинки`, `странные_видео` и т.д.

## Что делаем (коротко)

1. Дерево становится **данными**: ветки в отдельных файлах `lib/taxonomy/<ветка>.php`, ~30–35 веток,
   ~1000 частных тем. Глубина по-прежнему **два уровня** (ветка → частная тема); для UI у частной темы может быть
   поле `group` (подзаголовок внутри ветки), это не третий уровень реестра.
2. Словарь хэштегов — **таблица SQLite** `hashtags`, засев из файлов `data/taxonomy/hashtags/<ветка>.tsv`.
   Каждый хэштег привязан к 1–3 частным темам.
3. Полный анализ больше **не получает список частных тем**. Модель выбирает 1–2 **ветки** (короткий enum)
   и пишет 3–8 **своих** хэштегов. PHP по словарю и эмбеддингам переводит это в частные темы `tags` (как раньше,
   те же ключи) и канонические `hashtags`. Лишних вызовов модели нет.
4. Неизвестные хэштеги копятся в кандидатах, CLI-команда раскладывает их умной моделью пачками (с лимитом).
5. Выбор темы пользователем находит и тему, и хэштег («#скибиди», «нижний интернет»).

Делай части строго по порядку. После каждой части — её проверка. Не прошла — чини, дальше не иди.

## Общие правила

- **Не делай git commit.** Пользователь проверит сам.
- **Перед первой записью в базу:** `cp data/posta.sqlite data/posta.sqlite.bak-taxonomy`.
- **НЕ открывай сайт** (`http://localhost/...`) ни curl, ни headless Chrome: каждая загрузка без куки создаёт
  пользователя и запускает парсер, который нельзя остановить без sudo. Всё проверяй через `php` в CLI.
- **Модели.** Полный анализ — только умная модель (`SMART_MODEL` / `ANALYSIS_MODEL`). **Не переводи** работу
  на быструю 2B. Эмбеддинги — `TOPIC_EMBED_MODEL` строго на CPU (`num_gpu: 0`), как в `topic_similarity()`.
  Вызывай модели только там, где это прямо сказано, и с указанным лимитом.
- **Не трогай файлы, которые не названы в задаче** (в рабочем дереве много чужих незакоммиченных правок).
  Если без правки другого файла не обойтись — правь минимально и упомяни в отчёте.
- Если `QUALITY_PROMPT.md` или `TOPICS_SEARCH_PROMPT.md` сейчас не доделаны (проверь по коду: есть ли
  `lib/quality.php`, ветка `expert` в дереве) — сначала скажи об этом в отчёте и не ломай то, что они ввели.
- Код в стиле проекта: короткие функции, комментарии по-русски одной строкой, без классов, SQL через `db_*`.
- Тексты интерфейса — по-русски, понятные владельцу канала, без слов «эмбеддинг», «таксономия», «скоринг».

## Часть A. Структура данных (без моделей)

1. Создай `lib/taxonomy/` — по файлу на ветку, каждый `return [...]` массив ветки в **том же формате**, что
   сейчас в `TOPIC_TREE` (`key`, `title`, `format`, `nsfw`, `about`, `aliases`, `children`). Порядок веток —
   в `lib/taxonomy/_order.php` (18+ и «Жесть» первыми, «Разное» последней).
2. В `lib/topic_tree.php` замени константу на функцию `topic_tree(): array` (static-кэш, собирает файлы по
   `_order.php`). Замени все `TOPIC_TREE` на `topic_tree()`. Перенеси текущее дерево в файлы **без изменений** —
   на этом шаге ничего не меняется по смыслу.
3. Новые необязательные поля частной темы: `group` (подзаголовок для UI), `nsfw` (переопределяет флаг ветки,
   например пошлое внутри «Мемов»), `hint` (короткое «не путать с …», для двусмысленных). Добавь их в
   `topic_normalize_entry`, `topic_tree_seed`, `content_tag_catalog` (`nsfw` частной темы ?? `nsfw` ветки).
4. CLI `php tools/cli.php taxonomy-check` — валидатор без моделей и без записи в базу. Ругается и выходит с кодом 1:
   - ключ не по шаблону `^[a-z_]+\.[a-z0-9_]+$`, повтор ключа;
   - **пропал ключ, который уже есть в записях** (`SELECT` по `tags` из `history_items`, `pool_items` — список
     используемых ключей) — это главная проверка, ключи нельзя терять;
   - повтор названия или синонима после `topic_norm()` — **во всём дереве** (синоним одной темы = название другой —
     ошибка: `topic_lookup` найдёт не то);
   - пустой `about`, `about` длиннее 140 символов;
   - в ветке меньше 2 или больше 80 частных тем; нет частной `<ветка>.other`;
   - для хэштегов (после части B): повтор, хэштег ссылается на несуществующую тему, хэштег совпадает с названием
     **другой** темы, мусорные хэштеги (короче 2 символов, только цифры, стоп-слова: `контент`, `пост`, `видео`,
     `фото`, `картинка`, `интересное`, `топ`, `лучшее`, `прикол` без уточнения).
   Печатает сводку: веток, частных тем, хэштегов, по веткам.

**Проверка A:** `taxonomy-check` зелёный на перенесённом старом дереве; `php -r` — `content_tag_catalog()`
совпадает со старым до символа (сравни `json_encode` до и после переноса); `seed-topics` ничего не меняет.

## Часть B. Наполнение: темы (без моделей проекта, с WebSearch)

Это основная работа. Делай **по одной ветке за раз**: файл ветки → `taxonomy-check` → следующая.

### Как думать о наполнении

- Карта отвечает на вопрос **«о чём этот пост и для какого канала он годится»**. Проверка полноты:
  возьми список категорий каталогов Telegram-каналов (TGStat — ~50 категорий), разделы VK, популярные
  хэштеги и тренды TikTok / Reels / Shorts / X 2024–2026 (WebSearch). Каждая заметная ниша должна найти себе место.
- **Современность — главное.** Обязательно покрой интернет-культуру как отдельную ветку (`internet`,
  «Интернет-культура»): нижний интернет; брейнрот и итальянский брейнрот; шитпост; скибиди и мемы поколения
  альфа; сигма / NPC / «чилл гай» и прочие мем-персонажи; копипасты и пасты; ИИ-слоп и нейромемы; дипфейки;
  эдиты и фанкамы; POV-ролики; стримерская культура и клипы со стримов; тренды и челленджи TikTok;
  «скуфы», «альтушки», «тюбики» и прочие субкультурные типажи; лиминальные пространства и бэкрумс;
  аналоговый хоррор и ARG; интернет-драмы и разборки блогеров; ностальгия по старому интернету (2007–2015).
  Найди через WebSearch, **что ещё** актуально в 2025–2026 — не ограничивайся этим списком.
- Ещё ветки, которых сейчас нет или они слишком бедные (решай по исследованию, это ориентир, не догма):
  «Эстетики и вайбы» (core-эстетики, y2k, old money, дарк академия, вейпорвейв, синтвейв, кор-тренды);
  «Аниме и манга» (или расширение `screen` — но `screen.anime` остаётся); «Дом и уют»; «Здоровье и тело»;
  «Отношения и психология» отдельно от экспертного; «Авто» подробнее (марки как хэштеги, а не темы);
  «Военное и оружие» (без жести — жесть остаётся в `shock`); «Религия»; «Города и регионы»
  (городские паблики); «Объявления и вакансии»; «ASMR и релакс»; «Лайфхаки»; «Обзоры и распаковки».
- **Тема или хэштег?** Тема — то, под что можно вести **канал** или собирать подборку (≥ сотни постов в месяц
  в соцсетях): «Нижний интернет», «Лиминальные пространства», «Котики-мемы». Хэштег — конкретика внутри темы:
  персонаж мема, тайтл, игра, марка, порода, блюдо, город, имя блогера (`тралалеро_тралала`, `berserk`,
  `доберман`). Сомневаешься — хэштег.
- **Не дроби искусственно.** «Мемы про понедельник» — хэштег, не тема. Цель «до 1000» — потолок, а не план.
  Хорошо: 700–1000 тем, у каждой ясно, чем она отличается от соседей. Плохо: 1000 тем, из которых треть —
  перефразы.
- `about` — **что видно на картинке или написано в посте**, ≤ 140 символов, 1 предложение (он идёт в промпты
  и в эмбеддинг). Для текстовых веток (`judge: text`) — о чём текст. Не «посты про …», а признаки:
  «Шакальные, пережатые, нелепые картинки и видео без понятной шутки; странное ради странного».
- `aliases` — как это называют люди: сленг, английское название, транслит, частые опечатки (2–6 штук).
  Синонимы не должны пересекаться с другими темами (валидатор проверит).
- `hint` — только где реально путают: у «Нижнего интернета» — «не обычный мем: смешно от нелепости и
  низкого качества»; у «Абсурдного юмора» — обратное.
- 18+: ветки `adult` и `shock` можно уточнить (фетиши — хэштегами, не темами), но **не расширяй их в первую
  очередь**. Главное там — чтобы модель надёжно ставила ветку, остальное вторично.

**Проверка B:** `taxonomy-check` зелёный, сводка по веткам. Выпиши в отчёт 30 случайных частных тем
(`about` + `aliases`) и сам перечитай их глазами: если две темы не различить по `about` — объедини.

## Часть C. Наполнение: словарь хэштегов (без моделей проекта, с WebSearch)

1. Миграция в `lib/db.php` (по образцу существующих): таблица `hashtags`
   (`tag TEXT PRIMARY KEY` — канонический, `topics TEXT` — JSON ключей частных тем (1–3), `kind TEXT`,
   `nsfw INTEGER`, `uses INTEGER DEFAULT 0`, `added_at INTEGER`) и `hashtag_aliases`
   (`alias TEXT PRIMARY KEY`, `tag TEXT`). Индексы по `tag` в aliases. И `hashtag_candidates`
   (`tag TEXT PRIMARY KEY`, `count INTEGER`, `last_seen INTEGER`, `branches TEXT`, `sample TEXT` — описание
   одной записи, где встретился).
2. Формат канонического хэштега: строчные буквы, без `#`, слова через `_`, ё → е (`нижний_интернет`).
   Собственные имена — как пишут в сети (`berserk`, `cs2`, `тралалеро_тралала`). Нормализация одна на всё:
   функция `hashtag_norm()` (в новом `lib/hashtags.php`), ей же нормализуются синонимы и ответы модели.
3. Файлы `data/taxonomy/hashtags/<ветка>.tsv`, строка: `tag<TAB>темы через запятую<TAB>kind<TAB>синонимы через |`.
   `kind`: `concept` (понятие, сленг), `meme` (мем/персонаж/формат мема), `entity` (тайтл, игра, бренд, марка,
   клуб), `person` (блогер, звезда, спортсмен), `place`, `species` (порода, вид), `food`, `event` (праздник,
   турнир, сезонное), `format` (pov, asmr, распаковка, туториал), `mood` (уютное, кринж, вайб).
   Синонимы: слитное написание (`нижнийинтернет`), английский вариант, транслит, сленг.
4. CLI `php tools/cli.php seed-hashtags` — читает все `.tsv`, upsert в таблицы, повторный запуск ничего не
   меняет; печатает счётчики. Никогда не удаляет хэштеги, у которых `uses > 0`.
5. **Наполнение.** По ветке за раз, порядок: `internet`, `humor`, `games`, `screen`/аниме, `music`, `celebs`,
   `animals`, `food`, `style`/эстетики, `sport`, `cars`, `tech`, `money`, `expert`, остальное.
   - Концепты и сленг: 30–100 на частную тему.
   - Сущности: игры, тайтлы аниме/фильмов/сериалов, исполнители, блогеры и стримеры (СНГ и мировые),
     клубы, марки авто, породы, блюда, города — **реальные и узнаваемые** (то, что люди правда ставят
     хэштегом). Сущности и дают основной объём словаря.
   - Ориентир объёма: 20 000–50 000 качественных хэштегов на этом шаге. **Не добивай до 100 000 мусором** —
     остальное вырастет из кандидатов (часть E). Каждый хэштег без привязки к теме или «для количества» —
     вред: он размывает подбор.
   - `taxonomy-check` после каждой ветки.

**Проверка C:** `seed-hashtags` дважды подряд — второй раз 0 изменений; `taxonomy-check` зелёный;
`php -r` — `hashtag_lookup('#НижнийИнтернет')`, `hashtag_lookup('нижний интернет')`, `hashtag_lookup('cursed')`
находят один и тот же канонический тег и его тему.

## Часть D. Анализ записи: ветки + свои хэштеги → частные темы (эмбеддинги на CPU, умная модель с лимитом)

1. **Векторы частных тем.** CLI `php tools/cli.php taxonomy-embed`: для каждой частной темы строка
   `«Ветка › Тема. about. Синонимы: …»` → `bge-m3` пачками по 32, `num_gpu: 0`. Храни в
   `data/taxonomy/topic_vectors.json` (ключ → вектор, плюс `sha1` текста: пересчитывать только изменённые).
   Функция `taxonomy_vectors()` со static-кэшем.
2. **Схема и промпт анализа.** В `content_analysis_schema` / `content_analysis_prompt` и во втором месте
   (текстовые посты) замени `tags` на:
   - `branches`: 1–2 ключа **веток** (enum по веткам, это ~30–35 строк в промпте вместо ~110). Список веток —
     с коротким `about` каждой. Правило про 18+ сохрани: видно обнажённое тело или секс — обязательно `adult`.
   - `hashtags`: 3–8 коротких хэштегов по-русски (или как принято в сети для имён): что изображено, какой мем
     или персонаж, какой формат, какое настроение. Пример в промпте один, общий (не про текущую тему).
   Неизменная часть промпта **остаётся в начале** (кэш префикса Ollama) — текст про ветки не зависит от темы.
3. **`content_tags_resolve(array $branches, array $hashtags, string $description, string $caption): array`**
   в `lib/hashtags.php` — без вызовов умной модели:
   - хэштеги модели → `hashtag_lookup` → голоса за их темы (вес 3);
   - n-граммы (1–3 слова) из описания и подписи, плюс `#хэштеги` из подписи → словарь (вес 1);
   - один вызов `bge-m3` (CPU) на `description + hashtags` → косинус с векторами частных тем **выбранных веток**
     (вес = близость × 4, только выше порога; порог подбери на проверке, константа в `config.php`);
   - итог: до `CONTENT_TAGS_MAX` ключей частных тем, первый — главный; **из каждой выбранной ветки — хотя бы
     одна частная** (нет кандидатов — `<ветка>.other`). Это критично: `content_is_adult` смотрит на флаг
     `nsfw` частной темы, ветку `adult` нельзя потерять.
   - возвращает `['tags' => [...], 'hashtags' => [канонические найденные], 'unknown' => [не найденные]]`.
   - эмбеддинги недоступны — работает только на словаре, не падает.
4. Запись хранит `tags` (как раньше) и новое поле `hashtags` (канонические, до 8). Добавь `hashtags` туда же,
   где сохраняются и отдаются `tags` (`lib/parser.php`, `lib/content.php`, `lib/ai.php`), `uses` у найденных
   хэштегов +1. `unknown` → `hashtag_candidates` (count +1, last_seen, ветки, sample — описание до 200 симв.).
5. `content_tags_from_text` (дометка старых записей) переведи на ту же схему.

**Проверка D:** возьми 20 записей из `history_items` с описаниями разных тем (мемы, коты, бизнес, игры, 18+).
- Сначала **без модели**: прогони `content_tags_resolve` на их описаниях и старых тегах как «ветках» —
  таблица «старые метки → новые метки + хэштеги».
- Потом **с моделью, не больше 6 вызовов полного анализа** на 6 картинках из кэша медиа: ветки, хэштеги,
  итоговые метки, время ответа до и после (промпт должен стать **короче**, время — не больше прежнего).
- 18+ запись из базы обязана получить `adult.*` в `tags`.
- Отчёт: где новые метки точнее, где хуже. Хуже на большинстве — подбирай веса/порог, не иди дальше.

## Часть E. Рост словаря из кандидатов (умная модель, только по команде)

1. CLI `php tools/cli.php hashtags-curate [--limit=N]` (по умолчанию 100 кандидатов, `count >= 3`):
   пачками по 25 кандидатов в умную модель (текст, без картинок): для каждого — `synonym` существующего тега
   (дай модели 10 ближайших по словарю/эмбеддингам), `new` с 1–3 частными темами (дай частные темы его веток),
   или `junk`. JSON-схема с enum по переданным вариантам. Результат — в таблицы, `junk` помечается и больше не
   предлагается. Печатает, что сделал.
2. **Не запускай это из парсера и по крону** — видеокарта занята парсером пользователя. Только вручную.
   В отчёте напиши пользователю, как и когда запускать.

**Проверка E:** один запуск с `--limit=25` на реальных кандидатах (если их меньше 25 — добавь тестовые с
префиксом `тест` и убери за собой). Покажи 25 решений модели; явные ошибки — поправь промпт (не больше 3 итераций).
