# Задача: опубликованный пост = лайк, и он исчезает из «Предложки»

Ты работаешь в проекте `/var/www/html/posta` (Posta). Владелец: «надо, чтобы по постингу пост отмечался как лайкнутый и исчезал из предложки».

Сейчас публикация ничего не меняет в оценках: пост из «Подбора» остаётся в карточке без голоса, пост из «Предложки» остаётся в «Предложке»
(его можно опубликовать второй раз по ошибке), запись из «не знаю» так и остаётся «не знаю».

Ничего не коммить. Модели не вызывать.

## 1. Что есть сейчас (выяснено 2026-10-23)

- Все кнопки «🚀 Запостить» ведут в `postItemToTelegram(item, { scheduledTs, channel, onDone })` (`js/content.js:597`): «Подбор» (`:55`, `:80`, `:642`, `:644`),
  «Предложка» (`js/tabs.js:127`, `:141` — читалка статьи), календарь (`js/calendar.js:1013, 1143, 1172, 1209, 1221`).
  Редактор `openPostEditor` → `onSubmit` → `publishToTargets(post)` (`:579`) → `publishToTelegram` (`:541`) по каждому каналу → `api('telegram_publish')`.
- **Сервер не знает, какая запись публикуется**: в форму уходят текст, медиа (`src`), канал, режим, время — ключа записи нет.
- Сервер: `handle_telegram_publish` (`handlers/account.php:403`) — режимы `now` (сразу), `native` («Отложенные» Telegram через аккаунт),
  `queue` и `slot` (наша очередь `outbox`). Успех записывается `published_add` (`lib/telegram.php:403`, `lib/db_access.php:329`).
- Голоса: `apply_vote($pool, $image, $vote, …)` (`handlers/content.php:227`) — переносит запись из пула в историю (`history_append`,
  коллекции `CONTENT_VOTE_COLLECTIONS`), `vote()` на клиенте (`js/content.js:219`) после голоса показывает следующую карточку.
- «Предложка» — `PROPOSAL_COLLECTIONS = ['liked', 'undecided']` (`config.php:195`), `proposal_items` (`handlers/content.php:241`) пропускает записи
  с `proposal_hidden`. Скрытие — `handle_proposal_hide` (`:271`): ставит `proposal_hidden` через `update_history_proposals` (`:332`) **и удаляет файлы из кэша медиа**.
- Ключ записи — `content_image_key($r)` (`lib/content.php:5`); клиент шлёт его как `item.image` (см. `proposal_hide` в `js/tabs.js:132`).

## 2. Что сделать

### 2.1 Ключ записи в публикацию
- `postItemToTelegram` знает запись — передай её ключ до сервера: в объект поста (`record: item.image`, проверь, что это тот же ключ, что
  `content_image_key` на сервере, и для «Подбора», и для «Предложки», и для статей/текстовых постов) → `publishToTelegram` → поле формы `record`.
- Публикации без записи (свой контент, зеркало, пост из календаря без записи, «Свой контент») — поля нет, ничего не меняется.

### 2.2 На сервере после успеха
В `handle_telegram_publish`, **только после успешной** публикации или постановки в очередь/«Отложенные» (любой режим) и только если пришёл `record`:
`content_mark_posted($key)` (новая функция в `lib/`, обработчик тонкий):
1. Запись в **пуле** пользователя (пост из «Подбора») → как голос «лайк»: та же логика, что `apply_vote(..., 'like', ...)` — запись уходит в `liked`.
2. Запись в истории в `undecided` → перенести в `liked` (с теми же полями; время голоса — сейчас).
3. Запись уже в `liked` → ничего не переносить.
4. Во всех случаях — `proposal_hidden = true` и `posted_at = time()` (новое поле, пригодится календарю и статистике).
5. Запись в `disliked` / `complaints` (опубликовали то, что раньше не понравилось) — перенести в `liked` тоже: публикация важнее старого голоса.
- **Файлы медиа не удалять** (в отличие от `handle_proposal_hide`): пост может стоять в очереди `outbox` на будущее и брать файлы из кэша.
  Проверь, откуда очередь (`queue`/`slot`) берёт медиа при отправке — если из кэша записи, файлы нужны до публикации. Чистку оставь существующим механизмам.
- Публикация в несколько каналов — `publishToTelegram` вызывается на каждый канал: отметка должна быть идемпотентной (второй вызов ничего не ломает).
- Ответ `telegram_publish` дополни полем `marked: 'liked' | 'already' | null`.
- Всё — в одной транзакции с изменением пула/истории (`db_tx`, как в соседних функциях). Ошибка отметки **не должна** превращать успешную публикацию в ошибку:
  поймать, записать в журнал, вернуть успех публикации.

### 2.3 На клиенте после успеха
- «Подбор»: если опубликована текущая карточка — показать следующую, как после лайка (переиспользуй то, что делает `vote()` после ответа, без второго запроса голоса).
  Если в «Подборе» опубликовали медиа через зум (`onPost`) — то же самое.
- «Предложка»: убрать карточку из списка сразу (как после «Скрыть» в `js/tabs.js:132`), без перезагрузки всей вкладки.
- Календарь: после публикации/планирования запись не должна снова предлагаться в пуле календаря (проверь, откуда календарь берёт кандидатов —
  если из «Предложки», это получится само; если нет — исключи записи с `posted_at`).
- В журнал: «Пост отмечен лайком и убран из «Предложки».» — одна строка.

### 2.4 Отмена
Если владелец удаляет запланированный пост в календаре (пост ещё не вышел) — запись возвращается в «Предложку» (`proposal_hidden` снять, `posted_at` убрать,
в `liked` остаётся). Найди, где удаляется пост из очереди / «Отложенных», и есть ли там ключ записи; если ключа там нет — сохрани его в записи очереди
при постановке (поле `record`). Если для `native` («Отложенные» Telegram) связь потерять нельзя без больших переделок — опиши в отчёте и не делай.

## 3. Проверка

- **Не открывай сайт** (`http://localhost/posta/`) в curl/headless как нового пользователя — запустится парсер. Сервер — через CLI/`php -r`
  на копии БД (`cp data/posta.sqlite` в scratch, подмени путь так, как это делают существующие `tools/test_*.php`). Боевую БД не менять.
- Тест `tools/test_posted_liked.php` по образцу других `tools/test_*.php`: запись в пуле → отметка → в `liked`, `proposal_hidden`, `posted_at`, из пула ушла;
  запись в `undecided` → в `liked`; повторная отметка ничего не меняет; запись в `disliked` → в `liked`; неизвестный ключ → `null`, без ошибки;
  отмена (2.4) → снова видна в `proposal_items`.
- Публикацию в Telegram в тесте **не делать** — вызывай `content_mark_posted` напрямую. Где именно она вызывается в `handle_telegram_publish` — покажи в отчёте.
- Клиент: стенд с подменой `api` (как в прошлых задачах), сценарий «Предложка → 🚀 → успех» — карточка исчезла; «Подбор → 🚀 → успех» — следующая карточка.
- `php -l`, консоль браузера без ошибок.
