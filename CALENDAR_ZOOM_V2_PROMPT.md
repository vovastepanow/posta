# Задача: календарь — предел приближения 3 дня и часы, которые растут вместе с зумом

Ты работаешь в проекте `/var/www/html/posta` (Posta), вкладка «Календарь». Файлы: `js/calendar.js` (масштаб, колесо, `computeGeo`),
`js/calendar-model.js` (чистые функции: `zoomAround`, `snapDays`, `hourWindow`, `shiftHourWindow`…), `js/calendar-drag.js` (жесты),
`index.html` (кнопки масштаба, ~стр. 436), `tools/test_calendar.mjs` (тесты модели).
Плавный зум колесом, доводка к целым дням и заморозка часов на время жеста уже сделаны (см. `CALENDAR_ZOOM_PROMPT.md`) — **не переписывай
этот механизм**, только расширь его. Перетаскивание, панель поста, предложку, список и телефонный вид не трогай.

## Что хочет владелец

1. **Максимальное приближение — 3 дня, а не 1 день.** Один день во всю ширину не нужен.
2. **Зум колесом равномерно увеличивает и масштаб часов.** Сейчас при приближении растёт только ширина дней, а высота часа почти не
   меняется (окно часов всегда вписано в высоту сетки, а на 1 дне вообще становится 0–24 и часы *мельчают*). Нужно: каждый щелчок колеса
   «внутрь» делает дни шире **и** часы выше, на одну и ту же долю шкалы; «наружу» — наоборот. Как зум карты, только по вертикали чуть слабее.

## Как сейчас устроено (выяснено 2026-10-23, перепроверять не нужно)

- Пределы: `zoomLimits()` (`js/calendar.js:131`) → `{ min: 1, max: PHONE.matches ? 3 : 31 }`. Прилипание `snapDays` в модели.
- Высота часа: `computeGeo` (`js/calendar.js:357`) берёт окно часов `base = hourWindow(...)` (или `state.frozenHours` во время жеста),
  сдвигает его на `state.hourShift` через `shiftHourWindow` и считает `ppm = height / ((eh - sh) * 60)` — окно всегда целиком в высоте сетки.
- `visibleHours` (стр. 349) передаёт `fullDay = state.fullDay || days <= 1.01` — на одном дне окно 0–24.
- Вертикальный сдвиг часов уже есть: перетаскивание фона по вертикали (`host.panHours`), автопрокрутка у края при перетаскивании
  карточки (`host.shiftHours`), `state.hourShift` зажимается `shiftHourWindow` в [0, 24].
- Кадр анимации `stepZoom` тянет `state.zoom` к `state.target`; после паузы `settleZoom` → `snapView`; в конце `finishZoom`.

## Что сделать

### A. Предел 3 дня

1. `zoomLimits()` на компьютере: `{ min: 3, max: 31 }`. Телефон (`PHONE.matches`) — **как было** (`min 1, max 3`), у него свой вид.
2. Кнопка «День» → «3 дня»: в `index.html` `data-cal-zoom="3"`, текст «3 дня». Неделя и Месяц без изменений.
3. `zoomName`: 3 → «3 дня» (сейчас было бы «3 дн.»); 1 оставь для телефона.
4. Сохранённый масштаб из `localStorage` меньше 3 при загрузке зажимается через `clampDays` (проверь, что это уже происходит).
5. Убери `|| days <= 1.01` из `visibleHours` — окно 0–24 теперь только по кнопке «Круглые сутки».
6. Тексты: комментарий в шапке `calendar.js` («до одних суток»), подсказка (`calendar.js` ~1055–1058: «до одних суток во весь экран» →
   «до трёх дней»), `index.html:444` «колесо мыши — масштаб до суток» → «колесо мыши — масштаб». Комментарии про «День/Неделя/Месяц» поправь.
7. «−/+» (`cal-out`/`cal-in`), щипок, пресеты — всё уже идёт через `zoomLimits()`, отдельно ничего не надо; проверь.

### B. Вертикальный масштаб часов следует за зумом

Принцип: **одна шкала зума**. Положение на ней `t` — по логарифму дней (именно по логарифму, тогда каждый щелчок колеса — одинаковый шаг):

```
t = ln(31 / days) / ln(31 / 3)        // 0 — месяц, 1 — 3 дня
vz = VZOOM_MAX ** t                   // во сколько раз час выше, чем при «окно вписано»
span = clamp(baseLen / vz, MIN_SPAN_H, baseLen)   // сколько часов видно по вертикали
```

где `baseLen = eh - sh` окна `hourWindow` (или 24 при «Круглых сутках»). Начни с `VZOOM_MAX = 2.4`, `MIN_SPAN_H = 4`
(вынеси в константы модели — владелец может захотеть подкрутить). Ориентиры при таких числах, окно 8–20 (12 ч):
месяц — видно 12 ч, неделя — ≈ 7 ч, 3 дня — 5 ч. При «Круглых сутках» (24 ч): месяц — 24, неделя ≈ 14, 3 дня — 10.
Если неделя по умолчанию выглядит слишком «крупно» (видно меньше 6 часов при обычном окне) — уменьши `VZOOM_MAX` до 2 и напиши в отчёте.

1. **Чистая функция в модели**: `hourSpan(baseLen, days, { min, max })` → видимая длина окна в часах по формуле выше. Пределы `min/max`
   берутся из `zoomLimits()` (на телефоне `max = 3`, там `t` считай от его пределов или просто верни `baseLen` — сетки на телефоне нет).
2. **`computeGeo`**: после получения `base` считает `span = hourSpan(...)` от **текущего кадра** `state.zoom.days` (а не от цели) —
   тогда высота часа анимируется вместе с шириной дней, тем же `stepZoom`, без отдельной анимации. Окно = `[sh, sh + span]`,
   где `sh = base[0] + state.hourShift`, зажатое в [0, 24] с сохранением длины (`shiftHourWindow` для этого годится: передай ему
   `[base[0], base[0] + span]`). `ppm = height / (span * 60)`.
3. **Точка под курсором остаётся под курсором и по вертикали.** Колесо: запомни в `zoomAtClient` ещё `cursorY` (от верха области часов,
   т.е. `clientY - rect.top - HEAD_H`, зажатое в [0, height]) в `state.cursorY`. В каждом кадре `stepZoom`, перед перерисовкой: час под
   курсором до кадра `h = sh + cursorY / (ppm * 60)`; после смены `days` новый `span'`; новый `sh' = h - cursorY / height * span'`;
   `state.hourShift = sh' - base[0]` (зажим в [0, 24] сделает `shiftHourWindow`). То есть удобнее всего — функция в модели
   `zoomHoursAround([sh, eh], cursorFrac, newSpan)` → новое `[sh, eh]` в пределах [0, 24], с тестами.
   Для «−/+», пресетов и «Сегодня» якорь по вертикали — середина сетки (`cursorY = height / 2`).
4. **Пресеты** («3 дня/Неделя/Месяц») по-прежнему сбрасывают `hourShift = 0`, но окно тогда **центрируется на базовом окне**
   (середина `hourWindow`), а не прижимается к его началу: при 3 днях видно середину рабочего дня, а не 8:00–13:00. Сделай это через
   тот же расчёт (например, `hourShift = (baseLen - span) / 2` для целевого числа дней) — и так же при включении «Круглых суток».
5. **Заморозка**: `state.frozenHours` по-прежнему фиксирует *базовое* окно на время жеста; `span` от неё не зависит (он от `days`), это нормально.
   В `finishZoom` базовое окно пересчитывается — если оно изменилось, сохрани видимую середину (пересчитай `hourShift` так, чтобы час
   в центре сетки остался тем же), иначе сетка прыгнет по вертикали после доводки.
6. **Прокрутка часов колесом над осью часов.** Раз часы теперь не помещаются, нужен простой способ их листать кроме перетаскивания фона:
   колесо над левой колонкой `.cal-axis` (и Alt + колесо над сеткой — по желанию) двигает `hourShift` на `dy / (ppm * 60)` часов, плавно
   через `scheduleRender`, а не масштабирует. `preventDefault` — только если окно реально сдвинулось (у края 0 или 24 — страница
   прокручивается). Подсказку (`calendar.js` ~1058) дополни строкой «Колесо над часами — листать часы».
7. **Признак, что часы обрезаны**: если `sh > 0.01` или `eh < 23.99` и окно короче базового — у верхнего/нижнего края колонки часов
   тонкая тень-градиент (класс на `.cal-body`, например `is-cut-top` / `is-cut-bottom`, стиль в `css/app.css` рядом с блоком `.cal-*` ~1478).
   Без новых кнопок.
8. Подписи часов (`axisNode`) и сетка (`--hour-px`, `is-half`, `is-tenth`) уже считаются от `ppm` — проверь, что получасовые и
   10-минутные линии включаются на 3 днях, а прилипание при перетаскивании (`snapTarget`, `pxPerMinute: geo.ppm`) по-прежнему работает.
9. Перетаскивание карточки у верхнего/нижнего края (`calendar-drag.js:~275`, `shiftHours`) — должно листать часы и при приближении; проверь.
