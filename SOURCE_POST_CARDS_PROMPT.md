# Задача: карточка кандидата в источники — посты вместо файлов и просмотрщик постов

Ты работаешь в PHP/JS-проекте `/var/www/html/posta`. На вкладке «Источники» показывается кандидат в источники
(канал Telegram, паблик VK, лента RSS, ОК, TikTok, тред Двача/4chan) — карточка `#source-card-wrapper`
(`index.html`), логика в `js/sources.js` (`renderSource`). Сейчас в карточке **мозаика отдельных файлов**:
картинки и видео из всех постов вперемешку, без текста, плюс свёрнутый блок «Тексты постов».

Пользователь хочет: **в карточке — карточки постов** (медиа поста вместе с его текстом, датой, просмотрами),
**по клику — просмотрщик постов**, похожий на просмотрщик медиа: листаешь посты целиком, видишь медиа и текст.

## Что выяснено (2026-10-23, по коду — перепроверять не нужно)

- Сервер уже отдаёт посты, а не файлы: `build_source_preview()` в `handlers/sources.php` → `posts`
  (у поста: `images`/`image`, `video`, `video_unavailable`, `video_page`, `video_pending`, `text`, `url`,
  `posted_at`; набор полей зависит от площадки) и для Telegram ещё `text_posts` (посты без медиа). Постов до
  `SOURCE_PREVIEW_POSTS` = 20 (TikTok 8, Двач/4chan 6).
- Текст поста обрезается на сервере до `SOURCE_PREVIEW_TEXT_MAX` = 300 символов — для просмотрщика мало.
- Просмотры Telegram парсятся (`lib/sources.php`, ~строка 220: `views`, `reactions` по id поста), но в посты
  превью **не попадают** — используются только для `view_rate`.
- Клиент сам разбирает посты на файлы: `mosaicItems()` (раскладка по «раундам», дедупликация
  `mediaFileKey`/`mediaDedupeUrls` из `js/media-dedupe.js`, картинки раньше видео), затем `buildTile`,
  `placeTiles`, `layoutMosaic`, `attachVideo` (очередь — не больше 3 видео сразу), `watchPending` (ролик
  TikTok/Shorts докачивается, `js/video-pending.js`), `sourceGallery` → `openViewerGallery` (`js/viewer.js`).
  Большие видео Telegram, которые веб-версия не отдаёт, — `BIG_VIDEO_NOTE` и ссылка на пост.
- Тексты — отдельный `<details id="source-texts">` (`renderTexts`, `textPostCard`).
- Под карточкой — строка охвата `renderCoverage` («Показано: N медиа из M постов · страниц канала: K»).
- Просмотрщик медиа (`js/viewer.js`, разметка `#image-viewer` в `index.html`): шапка с именем файла, «Пост ↗»,
  🚀, сцена с зумом и перетаскиванием, стрелки галереи, свои кнопки видео, Esc/клик по фону — закрыть.
  Он показывает **файл**, не пост: текста там нет.
- Похожий «телемагазинный» вид карточек уже есть в «Предложке» (`proposalCard` в `js/tabs.js`,
  `.proposal-*` в `css/app.css`). Если в коде уже есть общие помощники из `ARTICLE_CARDS_PROMPT.md`
  (`shortText`, `clampText`, `cardKind`) — используй их, не пиши вторые.
- Дизайн — вариант **K «День / Эфир»** (CSS-переменные темы в `css/app.css`, обе темы). Новую палитру не вводи.
- Ниже по вкладке есть «Источники темы» (`topicSourceCard`) с маленьким всплывающим окном `openSourcePreview`
  (только картинки `source.preview`). Это часть E, не главное.

## Общие правила

- **Не делай git commit.**
- **НЕ открывай сайт** (`http://localhost/...`) ни curl, ни headless Chrome: каждая загрузка без куки создаёт
  пользователя и запускает парсер, который нельзя остановить без sudo. Интерфейс — на стенде (часть F).
- Модели (Ollama) в этой задаче не нужны.
- Запросы к площадкам (t.me и т.п.) — только для фикстур стенда, через существующие PHP-функции из CLI,
  не больше 10 запросов.
- Трогай `js/sources.js`, новый `js/post-viewer.js`, `index.html` (разметка карточки кандидата и просмотрщика),
  `css/app.css`, `handlers/sources.php`, при необходимости `lib/sources.php` (только чтобы отдать просмотры
  в посты). Остальное в рабочем дереве — чужие незакоммиченные правки.
- Стиль проекта: короткие функции, комментарии по-русски одной строкой, DOM через `el()`, текст с площадок —
  **только `textContent`**, никакого `innerHTML` с чужими данными. Тексты интерфейса — по-русски.

## Часть 0. Прочитай целиком

`js/sources.js`, `js/viewer.js`, `js/video-pending.js`, `js/media-dedupe.js`, разметку `#source-card-wrapper` и
`#image-viewer` в `index.html`, `build_source_preview` и соседей в `handlers/sources.php`, сбор постов Telegram в
`lib/sources.php` (`telegram_channel_media_posts`, `telegram_posts_from_html`, разбор `views`/`reactions`),
`proposalCard` в `js/tabs.js`, стили `.source-*`, `.proposal-*`, `.image-viewer*` в `css/app.css`,
`SOURCE_PREVIEW_PROMPT.md` и `SOURCE_PREVIEW_MORE_PROMPT.md` (что там сделано — не откатывай: дедупликация,
20 постов, большие видео, несколько страниц канала).

## Часть A. Данные постов (PHP)

1. Пост превью в ответе получает единый вид для всех площадок (собери в одной функции
   `source_preview_post(array $p)` в `handlers/sources.php`):
   `text` (до `SOURCE_PREVIEW_TEXT_MAX`, подними до **2000**), `url`, `posted_at`, `media` —
   `[{kind: 'image'|'video', src, poster, page, pending, unavailable}]` в порядке поста, и `views`,
   `reactions` (число), `comments` — что площадка даёт, иначе `null`.
2. Telegram: просмотры и реакции из уже разобранной страницы (`views`, `reactions` по id поста) — положи в
   посты. Лишних загрузок не добавляй.
3. `text_posts` Telegram сливаются с `posts` в одну ленту на сервере (у текстового поста `media: []`), по
   `posted_at` от новых к старым. Старые поля (`images`, `video`, `text_posts`…) оставь, пока клиент на них
   смотрит, — после части B убери то, что больше никто не читает (`grep` по `js/`).
4. Размер ответа: проверь `strlen(json_encode(...))` для канала с 20 длинными постами — должно быть меньше
   ~150 КБ.

**Проверка A:** `php -r` из CLI — `build_source_preview` для одного канала Telegram из `catalog_sources`
(текстовый и мемный), одного RSS и одного VK (если подключён): сколько постов, сколько с медиа, у скольких есть
`views`, длина текстов. Сохрани ответы как фикстуры `tools/fixtures/source_preview_*.json` для стенда.

## Часть B. Лента постов в карточке кандидата

Вместо `#source-grid` / `#source-strip` / `#source-more` / `#source-texts` — один блок `#source-posts`:

1. **Карточка поста** (`sourcePostCard(post, index)`):
   - медиа: одна картинка — во всю ширину карточки (соотношение по картинке, но не выше ~1.25 ширины,
     `object-fit: cover`); альбом — мини-мозаика до 4 с плашкой «+N»; видео — постер со значком и длительностью,
     если известна; ролик, который докачивается, — как сейчас («Видео загружается…»); большое видео Telegram —
     значок «внешнее видео»;
   - текстовый пост без медиа — текст крупнее, на подложке (как `.text-post`), до 8 строк;
   - текст поста — 3–4 строки с обрезкой по границе слова, переносы строк сохраняются;
   - низ: «3 ч назад», `👁 12,4K`, `❤ 230` (что есть), «альбом · 5», ссылка «↗» на пост.
2. **Раскладка:** сетка карточек — 3 колонки на широком экране, 2 на среднем, 1 на телефоне (390 px). Колонки
   ровные (обычная CSS-сетка, без JS-раскладки «по размеру картинки» — она больше не нужна). Сначала 6 постов,
   кнопка «Ещё N постов» показывает остальные.
3. **Видео в ленте** играют сами без звука **только видимые** (IntersectionObserver), не больше 3 одновременно
   — перенеси очередь `attachVideo`; ушло из вида — пауза. Докачка роликов (`watchPending`) — как сейчас, по
   готовности карточка поста становится видео.
4. **Медиа не загрузилось** — карточка остаётся, вместо медиа плашка «Файл недоступен» (пост всё равно
   показывает, о чём канал). Пост без текста и без живого медиа — убирается.
5. Дедупликация — как сейчас (`mediaFileKey`): одинаковый файл в двух постах показывается один раз, во втором
   посте он пропускается; пост, у которого не осталось медиа и нет текста, не показывается.
6. Строка охвата: «Показано N постов из M · из них с медиа K · страниц канала P». Пустой канал —
   существующий текст «В канале нет картинок и видео — только текст.» больше не нужен: текстовые посты видны.
7. Старый код мозаики (`mosaicItems`, `buildTile`, `placeTiles`, `layoutMosaic`, `rankOf`, `sourceGallery`,
   `renderTexts`, `textPostCard`, обработчик `video-ready` для плиток) — перепиши под посты или удали, если
   больше нигде не используется (`grep -rn` по `js/`). Стили, которые больше не нужны, — удали.

## Часть C. Просмотрщик постов (`js/post-viewer.js`)

`openPostViewer(posts, index, { sourceName, sourceUrl })`. Окно поверх приложения, как `#image-viewer`, но
показывает **пост целиком**.

1. **Раскладка.** ПК (≥ 900 px): слева медиа поста (тёмная сцена), справа колонка 360–420 px — имя источника,
   дата, просмотры/реакции, **полный текст** с прокруткой, «Открыть пост ↗». Телефон: медиа сверху (до ~60%
   высоты), текст под ним, всё листается одной прокруткой. Текстовый пост без медиа — текст крупно по центру.
   Шапка: «Пост 3 из 20», ✕.
2. **Листание постов:** стрелки по бокам окна, клавиши ← / →, на телефоне свайп влево/вправо по окну.
   **Медиа внутри поста** (альбом): точки под медиа, свои маленькие стрелки на медиа, клавиши ↑ / ↓; на
   телефоне — тап по левой/правой половине медиа. Счётчик «2 / 5» на медиа.
3. **Видео** в просмотрщике — со звуком (громкость как в `viewer.js`, 0.33), по кнопке/тапу. Пояснения про
   ролики, которые качаются, и большие видео — те же тексты и та же логика, что в `viewer.js`
   (`videoFields`, `videoPageFor`, `watchVideo`) — **переиспользуй**, не копируй. При листании видео
   останавливается.
4. **Зум:** клик по картинке (или кнопка ⤢) открывает существующий просмотрщик медиа (`openViewerGallery`) на
   файлах этого поста — там уже есть зум и перетаскивание. Закрыли его — вернулись в просмотрщик поста на том же
   посте.
5. Закрытие: ✕, Esc, клик по фону, «назад» браузера (через `history.pushState` при открытии и `popstate`).
   Фокус — внутрь окна при открытии, обратно на карточку поста при закрытии; прокрутка страницы под окном
   заблокирована. `role="dialog"`, `aria-modal`, подписи у кнопок.
6. Соседние посты подгружаются заранее (картинки следующего и предыдущего — `new Image()`), видео — нет.
7. Клик по карточке поста в ленте открывает просмотрщик на этом посте; клик по «↗» — пост на площадке
   (просмотрщик не открывается).

## Часть D. Вид

- Карточки постов — в стиле карточек «Предложки» (обводка, жёсткая тень, скругление из переменных),
  но легче: это «примеры постов» внутри большой карточки источника, а не самостоятельные карточки.
- Просмотрщик — тёмная сцена в обеих темах (как `#image-viewer`), колонка текста — поверхность темы.
- Обе темы (день / эфир), ширины 390, 768, 1280 px. Длинные слова и ссылки в тексте не ломают вёрстку
  (`overflow-wrap: anywhere`). Нет горизонтальной прокрутки страницы.

## Часть E. «Источники темы» (только если A–D прошли)

`topicSourceCard` открывает по клику маленькое окно `openSourcePreview` с картинками `source.preview`.
Посмотри, что сервер кладёт в `preview` (только адреса картинок или посты). Если посты есть или их легко
отдать из уже загруженных данных без новых запросов к площадкам — открывай `openPostViewer`, а
`openSourcePreview` удали. Если для этого нужны новые запросы к площадкам — не делай, опиши в отчёте.

## Часть F. Стенд и проверка (без сайта, без моделей)

1. `tools/stand/source-posts/index.html`: `css/app.css` и модули `js/` по `file://`; `window.fetch` подменён
   заглушкой, отдающей фикстуры из части A (мемный канал с альбомами и видео, текстовый канал, RSS). На стенде:
   карточка кандидата для каждой фикстуры и кнопки «открыть просмотрщик на посте N».
2. Снимки `google-chrome --headless=new --screenshot`: лента (1280 и телефон 390 через `iframe width=390` —
   headless Chrome не даёт окно уже 500 px), просмотрщик на посте с альбомом, на видео, на текстовом посте —
   в обеих темах. Посмотри снимки сам и поправь вид, до 3 итераций.
3. Синтетическими событиями: ← / → листают посты, ↑ / ↓ — медиа альбома, Esc закрывает, `popstate`
   закрывает, после закрытия фокус на карточке поста. Проверяй по состоянию (`dataset`, индексы), каждый
   сценарий 3 раза (у `--dump-dom` бывают артефакты `requestAnimationFrame`).
4. `node --check` для JS, `php -l` для PHP.
