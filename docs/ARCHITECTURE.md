# Posta — архитектура (Go)

С 2026-10-29 бэкенд Posta написан на Go; PHP и Python удалены. Фронтенд (`web/`) — ES-модули без сборки, JSON API прежний:
`GET|POST /index.php?action=<действие>` (и то же самое по `/api/<действие>`), POST требует заголовок `X-Posta: 1`.

## Процессы

Один бинарник `posta`:

| Команда | Что делает |
|---|---|
| `posta serve` | HTTP API + статика `web/` + медиа; внутри — сборщики пользователей (горутины), публикатор, очередь роликов, радар, ночные задачи |
| `posta migrate` | применяет миграции Postgres и ClickHouse |
| `posta import-sqlite <файл>` | переносит данные из старой `data/posta.sqlite` |
| `posta <команда>` | служебные команды (бывший `tools/cli.php`): `posta help` покажет список |

Сборщик больше не отдельный процесс на пользователя: открытая вкладка запускает горутину сборщика, закрытие вкладки
(или 150 с без heartbeat) отменяет её `context`. Одновременно — не больше `MaxParallelParsers`.

## Хранилища

**Postgres** — всё, что меняется транзакционно и читается приложением: пользователи, сессии, вход, каналы и их секреты,
настройки, пул, история оценок, очередь публикаций, журнал опубликованного, каталог источников, голоса и находки подбора,
реестр тем, кэши оценок (`analysis_cache`, `screened_cache`), итоги каналов (`source_verdicts`), биллинг, зеркала, лиды радара, `kv`.

**ClickHouse** — потоки событий и аналитика (только дописываются, читаются агрегатами): вызовы моделей с токенами и
стоимостью (`ai_calls`), голоса пользователей (`votes`), итоги быстрой оценки и анализа (`screening`), журнал сборщика
(`parser_log`), публикации (`publish_events`). ClickHouse необязателен: без него события пишутся в журнал и теряются,
приложение работает.

Каталог источников и реестр тем держатся в памяти процесса под мьютексом и сохраняются построчно (diff), а не
перезаписью всех таблиц, как было в PHP: параллельные сборщики больше не затирают изменения друг друга.

## Модели

`internal/llm`: провайдеры `ollama` и `openrouter` за общим интерфейсом. Задачи разделены по ролям:

| Роль | Задача | Нужно |
|---|---|---|
| `prescreen` | быстрый отсев мусора по картинке | vision, дёшево, logprobs желательно |
| `analysis` | полный анализ записи по теме (JSON) | vision, structured output |
| `judge` | «есть ли шутка», выбор подтемы | vision, короткий ответ |
| `smart` | профиль темы, классификация, план подбора, проверка канала | сильная модель, редко |
| `text` | пачки текстовых записей, подписи постов | текст, JSON |
| `radar` | классификация сообщений радара лидов | текст, дёшево |
| `translate` | перевод (если выбран режим перевода моделью) | текст |
| `embed` | сходство тем | эмбеддинги |

Для каждой роли в админке («Управление → Модели») задаются провайдер, модель и резерв. Режимы-пресеты: «Локально»,
«OpenRouter», «Смешанно». Дневной бюджет OpenRouter в долларах: при превышении роли с резервом переходят на Ollama.
Стоимость считается по `usage` ответа OpenRouter и пишется в ClickHouse.

## Пакеты

- `cmd/posta` — точка входа и команды.
- `internal/config` — константы (бывший `config.php`) и настройки сервера из окружения / `posta.env`.
- `internal/db` — Postgres (pgx), миграции.
- `internal/ch` — ClickHouse, асинхронная запись событий.
- `internal/llm` — провайдеры моделей и маршрутизация по ролям.
- `internal/secret` — шифрование секретов (совместимо с прежним форматом libsodium).
- `internal/tgclient` — личный аккаунт Telegram (MTProto, gotd/td) вместо Telethon.
- `internal/posta` — предметная логика (темы, источники, сборщик, подбор, публикация…), файлы повторяют прежние модули.
- `internal/web` — HTTP-сервер и обработчики действий.
