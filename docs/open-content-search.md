# Posta: открытый поиск контента

Цель: 100 уникальных пригодных постов для востребованного запроса при наличии
запаса; редкий запрос — частичная выдача и пополнение. Темы нужны как задания
сбора, не как обязательные метки публикаций.

1. Общий индекс public_posts: FTS, затем pgvector (проверить расширение на
   сервере). Сохранить приватность, ограничения источников и проверку качества.
2. Дешёвые текстовые/визуальные представления, OCR и доступные транскрипции;
   отдельная очередь для медиа без текста. VLM по необходимости, кэш по ревизии
   материала и модели; пригодность отдельно по версии профиля.
3. Плоские задания сбора: стартовые популярные запросы и реальный спрос;
   переиспользовать одинаковые задачи парсеров, не объединять профили авторов.
   Дефицит считать по уникальным пригодным постам. Различать неразобранные медиа,
   дубли, слабый поиск, нехватку источников и бюджет. Полезность источника
   оценивать относительно запроса.
4. Обратная связь: тема, интерес, повтор, качество, реклама. Сохранять
   подтверждения условий; неизвестное не равно отказу.
5. Слепое сравнение старого и нового поиска: новости Москвы, мемы про
   электромобили, схемы амигуруми, SMM, отрицания, медиа без текста.
   Независимые метки пригодности, уникальные годные в топ-10/20/100,
   аудит пропусков, время, стоимость и живое пополнение несколько дней.
6. Удалять дерево, наследование, глобальные тематические хэштеги после проверки.
   Рубрики канала сохранить. ClickHouse — аналитика, PostgreSQL — оперативные
   решения.

Первый шаг добавляет FTS и кандидатов из общего публичного каталога параллельно
старому пути. Pgvector, визуальный поиск, новый планировщик и отмена старой
классификации пока не реализованы. FTS-совпадение не является вердиктом.

## Гибридный поиск (этап 2)

Добавлены версионированные текстовые эмбеддинги: бесплатный Nemotron через
существующий маршрут OpenRouter, 512 компонент, нормализация, кэш и отдельные
суточные квоты. Обновление содержания инвалидирует вектор транзакционно.
При доступном pgvector создаётся HNSW; иначе используется точное скалярное
произведение нормализованных векторов. Отсутствие модели не блокирует FTS.
Оригинальный запрос и ограниченные поисковые варианты объединяются с векторной
выдачей через RRF; векторные кандидаты не отбрасываются по отсутствию слов.
Оценка пригодности всё ещё выполняется существующим сборщиком.

Это текстовый слой, не визуальный: мемы без подписи, аудио и видео требуют
отдельной ветки индексации. Ограничения квоты и скорости пока консервативны;
качество на реальных редакционных запросах не измерено.
