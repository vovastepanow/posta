# Проверка открытого поиска

Цель — сравнить старый отбор по метке дерева с поиском по общему индексу.
Команда не изменяет БД, не обращается к AI и не использует личные пулы.

`posta inventory-benchmark "SMM и блогинг" <старый-ключ-темы> <новый-каталог>`

Обе выдачи и контрольная псевдослучайная выборка снимаются в одной read-only
repeatable-read транзакции. Старый вариант использует последние 7 дней и точную
метку темы; открытый — действующие текстовый и медиа-индексы. Это сравнение
кандидатов, не конечной персональной выдачи. Для теста также векторного поиска
передайте четвёртым аргументом JSON с `model` (точная версия индексированных
эмбеддингов) и `vector` (512 значений запроса). Вектор передаётся готовым,
команда не вызывает провайдера; векторный отбор точный, не ANN.

Сохраните `ranks.json` отдельно от независимого оценщика. Ему передайте только
`blind.json` с запросом, исходным публичным URL и текстом каждого уникального
поста. Медиа нужно проверить по оригиналу, нельзя считать обложку доказательством
содержания ролика. Если материала нет или смысл неясен, оставьте relevant=null.
Независимые ответы: массив `[{"id":"...","relevant":true}]`.
Нельзя размечать по результату старого или нового алгоритма.

`posta inventory-benchmark-score <ranks.json> <labels.json>`

Отдельно выводятся точность на размеченных результатах, покрытие разметки и
полнота на объединённой размеченной выборке для top-10/20/100. Отсутствующие
метки не превращаются в отрицательные. Полнота по всему интернету не измеряется.
Выборка ограничена текущим публичным каталогом. Цель — накопить объективные
сравнения на широких, узких, многозначных запросах, с фото и видео, и только
потом отключать старую обязательную таксономию. Пока реальных независимых меток
и контрольного прогона на production нет.
