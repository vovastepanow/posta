# Posta ML: собственная локальная модель — эксперимент

Первый слой: обучаемый CPU-классификатор текста публикаций с тремя классами:
`relevant` (пост непосредственно по теме), `adjacent` (смежная тема),
`irrelevant` (не по теме).

Реализация: `internal/postaml`, команды: `cmd/posta-ml`.
Никаких GPU, PyTorch, Python, OpenRouter или новых платных подписок.
На Xeon E5-2680 v3 / 16 ГБ ОЗУ обучение и инференс выполняются на CPU.
Это **не** большая языковая модель, не поддерживает картинки и не анализирует
рекламность/повторы: для этого нужны отдельные слои.

## Главное правило данных

**Нельзя обучать на решениях Nemotron как на истине.**
Нам нужны отдельно проверенные примеры постов: метки должны выставляться
после просмотра исходного материала. Действующие статусы источников
`rejected`/`probation` не являются достоверной разметкой.

Данные — JSONL, один объект на строку:

```json
{"source_id":"telegram:example","text":"Содержательный текст публикации длиной более 25 символов","label":"relevant","reviewed_by":"independent-auditor"}
```

Разрешённые метки: `relevant`, `adjacent`, `irrelevant`.
Для честной минимальной контрольной выборки требуется не менее пяти
разных источников с преобладанием каждого класса; реальная оценка качества
потребует сотен/тысяч отдельно проверенных публикаций.

## Запуск (локально или на сервере)

```bash
go run ./cmd/posta-ml train -data reviewed-posts.jsonl -model posta-local.json
go run ./cmd/posta-ml predict -model posta-local.json -text "Разбор SMM-кампании и аналитики охватов..."
```

Обучение происходит без интернета. Команда выводит качество на **отложенных
источниках, не встречавшихся при обучении**: точность, macro-F1, точность
и полноту класса relevant, матрицу ошибок. Инференс всегда помечен
`advisory_only: true`.

## Следующие обязательные этапы

1. Собрать из нового аудиторского экспорта Posta публикации и ссылки на
   оригиналы. Данные из старого реестра могут быть неполными; нельзя
   автоматически считать их метки верными.
2. Независимо разметить по смыслу тексты, а затем — медиа отдельным слоем.
   Выделить «нехватка данных» и «смешанный источник», не смешивать с отказом.
3. Сравнить модель и Nemotron на идентичных источниках; измерить ошибки в
   обе стороны и долю случаев, переданных более сильной модели.
4. Включить модель в **теневой режим** только после подтверждения качества.
   Не изменять реальные статусы по её предсказанию без отдельной проверки.

Код пока **не подключён к действующему автопилоту**. Текущий маршрут
Nemotron и установленные бюджетные ограничения остаются прежними.
