# Классификация и безопасная перепроверка (v14)

Классификация тем отделена от оценки релевантности публикации. При недоступности
классификатора или неоднозначном ответе успешный анализ сохраняется с
`tags_classification_pending=true`, без неподтверждённых тематических меток.
Обязательные метки безопасности сохраняются; обнаруженный чувствительный текст
не отправляется в дополнительный внешний запрос.

Классификатор дважды выбирает темы из полного меню (второй раз в обратном порядке),
не видя предыдущего ответа. Несовпадение означает неопределённость. При совпадении
выполняется смысловая проверка определений и буквальных цитат. Невалидный JSON,
неполная проверка и недостаток содержания также означают неопределённость,
а не отсутствие тем. Согласие одной модели с самой собой не доказывает правильность:
качество и долю неопределённых результатов необходимо измерять отдельно.

Для медиа сначала получается описание видимого содержания без списка тем, затем
применяется тот же текстовый классификатор. Подпись не обязана быть длинной, если
содержание есть в изображении. Бессодержательная обложка видео не доказывает
содержание ролика. Полноценный текст обрабатывается без изображения. В публичном
каталоге новый путь не извлекает кадры или звук видео; такие записи без достаточного
текста/сохранённого описания остаются непроверенными. Нейтральное описание изображения
тоже может содержать ошибки; этот путь ещё требует полноценной проверки на реальных
изображениях.

Все запросы классификации и описания изображений используют `FreeOnly`, в том числе
резервные цели. Денежные бюджеты платных запросов остаются отдельным механизмом.
Запросы роли classify сериализованы в процессе. Ответ shared TPM 429 не повторяется
немедленно; используется существующая пауза маршрутизатора. Это не устраняет
ограничения поставщика. HTTP 403 — отдельная, не установленная здесь причина.

## Команда аудита

```sh
go run ./cmd/posta audit-classifications data/backups/classification-audit-v14-20261112 --limit=25
```

Без параметра `--limit` проверяется не более 25 ещё не завершённых записей.
`--limit=0` снимает ограничение партии. `--snapshot-only` сохраняет только снимок,
не отправляя содержимое моделям. Используется настроенный бесплатный маршрут;
непроверенный резерв автоматически не включается.

Первый запуск атомарно сохраняет `snapshot.jsonl` с записями пула и каталога,
устойчивыми ключами и текущими метками, до внешних запросов. Снимок и журнал имеют
права 0600. Это локальные данные, включая чувствительные записи: снимок не является
файлом для отправки внешнему поставщику. Модель получает только содержание
нечувствительной записи, без идентификаторов пользователей и метаданных базы.

Повторный запуск с тем же каталогом продолжает проверку **того же снимка**, а не
свежего состояния базы. Завершённые `agrees`, `proposal`, `sensitive_skipped` и
`safety_review` не повторяются. Неопределённые и недоступные результаты допускают
повторную проверку. Для свежего состояния базы нужен новый каталог снимка.
Повреждённый журнал/снимок вызывает ошибку, а не молчаливое удаление данных.
Параллельный запуск в одном каталоге запрещён файловой блокировкой.

Аудит чередует пул и каталог, а в каталоге — источники и типы содержимого. На запись
выделяется 90 секунд; после трёх недоступных результатов подряд проход прекращается.
`review.jsonl` содержит предложения, причины неопределённости, модели и безопасные
детали ошибок. Аудит не меняет метки в базе. Ключи и исходные метки снимка позволяют
восстановить их при отдельной согласованной операции; автоматического отката всей
строки с перезаписью новых данных нет.

`reclassify-saved` сохраняет прежние метки и спорные предложения отдельно, проверяя,
что запись не изменилась параллельно. Подтверждённые метки можно автоматически
добавить только записи с явной пометкой ожидания, без существующих тематических
меток и без признака ручной проверки. Существующие и вручную проверенные темы
не заменяются при расхождении. Предыдущие метки сохраняются в
`tags_before_reclassification_v14`.

## Проверки

```sh
GOCACHE=/tmp/posta-go-cache go test ./internal/... ./cmd/...
POSTA_ROOT="$PWD" POSTA_TEST_CLOUD=1 \
  POSTA_CLASSIFIER_TEST_MODEL=baidu/ernie-5.5-flash-preview:free \
  POSTA_CLASSIFIER_TEST_DELAY=15s \
  go test ./internal/posta -run '^TestContentClassificationRealPosts$' -count=2 -v
```

Внешний тест является явной отправкой контрольных текстов в OpenRouter.
Недоступность модели должна учитываться отдельно от верных и неверных ответов;
провал всего набора из-за 429 не является оценкой точности классификации.

Исправленная подготовка экспериментального набора, полные видео со звуком и
раздельная оценка ошибок описаны в [проверке v2](classification-benchmark.md).
Она не отправляет запросы и не меняет рабочий классификатор.
