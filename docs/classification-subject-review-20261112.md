# Разбор лишних меток и исправление принятия результата

## Результат

Разобраны пять публикаций из сохранённого финального опыта. У двух корректных
ответов (попытки 3 и 5) — 17 назначений меток, не 17 независимых публикаций.
Одно обоснование опирается только на хештег; остальные 16 буквально присутствуют
в указанном источнике. Буквальность не доказывает, что цитата подтверждает тему.
Два повреждённых ответа не восстановлены для автоматического использования;
у одной попытки нет текста ответа. Новых модельных вызовов нет, расход $0.

## Правило предмета

Метка требует утверждения о специфическом аспекте своего определения: факта,
объяснения, действия или вывода. Название отрасли участника, его должность,
инструмент, хештег и возможное применение — контекст. Вторая метка требует
собственного раскрытого аспекта; запрета на две настоящие темы нет. Короткая
новость может быть полноценным тематическим материалом без всех подробностей.

Это редакционное правило текущего исправления. Старый эталон и исторические
показатели не пересчитаны под новые определения.

## Исправления в приложении

1. Проверка темы теперь требует `basis=subject/context/uncertain`, `aspect`
   (какое утверждение о теме раскрыто), `matches` и цитату. Boolean и совпавшей
   строки больше недостаточно для принятия ответа. Контекст с `matches=true`,
   отсутствие объяснения, неизвестные/повторные строки остаются неопределённостью.
2. Убран дефект «отклонена одна метка — теряются все». Полный корректный ответ
   проверки с явным отклонением контекста сохраняет подтверждённые темы.
   Неопределённость, пропуск строки или повреждённый ответ по-прежнему дают pending;
   их нельзя трактовать как разрешение молча удалить дополнительную тему.
3. Локальная проверка доказательства исключает совпадения только внутри хештега,
   имени аккаунта или URL. Если слово есть также в обычном тексте, оно не запрещено.
   Это проверка происхождения цитаты, не семантический классификатор.
4. Уточнены границы маркетинга, продаж, офисной жизни и бухгалтерии. Полные
   определения и границы передаются проверяющему этапу. Первичный выбор по-прежнему
   использует краткое меню; локальный поиск кандидатов ещё не интегрирован.
5. Правило предмета действует и на выбор, и на проверку. Число запросов не увеличено:
   прежние два выбора и проверка, с одним существующим повтором при плохой цитате.

Новый ответ модели может всё равно ошибочно назвать контекст предметом или придумать
убедительное объяснение. Новые поля не являются доказательством смысла сами по себе.
На старых ответах нет новых полей; дописывать их задним числом и выдавать за результат
модели нельзя. Поэтому рост точности реальной модели здесь не измерен.

## Воспроизводимость

Отдельный инструмент `tools/classification_evidence_audit.py` не имеет отправителя,
не изменяет метки и не принимает восстановленные обёртки. Для каждой цитаты сохраняет
источник, статус и запрет автоматического применения; входы связаны SHA256.

```sh
python3 tools/classification_evidence_audit.py \
  --request data/backups/classification-final-choice-v3-20261112/schema-request.json \
  --responses data/backups/classification-final-choice-v3-20261112/responses.jsonl \
  --output data/backups/classification-subject-review-20261112/evidence-audit.json
GOCACHE=/tmp/posta-go-cache go test ./internal/... ./cmd/... ./tools/classification-taxonomy
python3 -m unittest discover -s tools -p 'test_classification_*.py' -v
git diff --check
```

Тесты приложения проверяют сохранение верной темы при отклонении лишней,
допустимость двух настоящих тем, pending при неопределённости/противоречии/старом
ответе без новых полей, выдуманную цитату и происхождение цитат. Ответы в этих тестах
подставные: это проверка кода, а не новой способности живой модели.

Итог проверок: перечисленные Go-пакеты прошли, Python — 23/23, `git diff --check`
без ошибок. Для Go разрешены локальные тестовые сокеты. Отдельный diff кода
относительно начала этого продолжения: `docs/classification-subject-20261112.patch`.
Новые тесты и инструмент находятся в отдельных файлах и не включены в этот diff.

Рабочая база, старые метки и настройки моделей не изменены. FreeOnly, безопасность
и запрет автоматической замены старых меток сохранены. Сервис не перезапускался.
Семантические изменения подготовлены в исходниках; не объявлены проверенными
в работающем сервисе. Следующий содержательный контроль должен проверять именно
новый протокол на фиксированном небольшом наборе, включая независимые примеры
двух настоящих тем. Повтор старого запроса не проверит это исправление.
