# Эксплуатация автопилота источников

Автопилот хранит потребности пользователей отдельно по полному профилю темы. Для одинакового публичного профиля используется одна задача; личные фильтры и исключения остаются личными. Фоновые исполнители запускаются вместе с приложением, кроме режима разработки без `POSTA_DEV_PARSERS=1`.

Перед обновлением примените штатную процедуру резервирования и установите миграции приложения. Изменения разработки не применяют миграции к рабочей базе и не запускают публикации. Существующий `auto_add_score` не меняется.

## Включение и наблюдение

В административных настройках раздела «Подбор источников» отдельно разрешаются `autopilot_shadow` и `autopilot_auto`; оба разрешения по умолчанию выключены. Затем пользователь на вкладке источников сохраняет тему, режим, частоту и горизонт. В `shadow` каталог не изменяется. В `auto` предварительно проверенные публичные источники подключаются для испытания и переоцениваются по завершённым наблюдениям. При нулевой частоте автоматическая задача не запускается. Доступны анонимный веб-поиск Telegram, VK и YouTube, поиск групп Одноклассников, новостных RSS, публичных RSS Bluesky и Lemmy, аккаунтов mastodon.social, сообществ Reddit, хабов Хабра и блогов Tumblr. Поддерживаются текстовые и графические оценки и ограниченная проверка видео при наличии необходимых инструментов и моделей; недоступные видео остаются без оценки. Другие площадки не имеют полноценного автоматического цикла.

Завершённые публичные оценки постов повторно проверяются по личным фильтрам и автоматически добавляются в пул каждого включённого владельца, в пределах его цели и ограничений испытания. Доставка не зависит от выбранной на экране темы и не планирует публикации. Изображения и прямые видео доставляются только после полной оценки и сохранения проверенных байтов в локальном кэше; неподтверждённые и недоступные медиа остаются без оценки. Адреса медиа с параметрами запроса и адреса постов с признаками секретов консервативно исключаются из общего автопилота. Обычный сборщик продолжает работать по существующим правилам.

| Источник поиска | Доступ и текущая поддержка auto |
| --- | --- |
| Новости | Публичный поиск RSS, если включён `search_news`; кандидаты проходят проверку ленты. |
| Bluesky, Lemmy | Публичный поиск при включённых `search_bluesky` и `search_lemmy`; в auto принимаются только кандидаты RSS. |
| Mastodon | При `search_mastodon` поиск ограничен публичными аккаунтами mastodon.social; используются только записи с явными `visibility=public` и `sensitive=false`. Интеграционный тест с подставными ответами и PostgreSQL прошёл; реальный проход не подтверждён. |
| Хабр | Публичный поиск хабов при включённом `autopilot_search_habr` (по умолчанию включён). Используется RSS без параметра языка; посты проходят обычные фильтры. Доступность площадки и ленты в реальной сети ещё не подтверждена. |
| Tumblr | Поиск блогов и их публичных RSS при включённом `autopilot_search_tumblr` (по умолчанию включён); запросы учитываются в сетевом бюджете. 15 ноября 2026 года публичная выдача и одна выбранная лента ответили HTTP 200; полноценный проход оценки не выполнялся. |
| Reddit | При включённом `search_reddit` auto анонимно ищет публичные сообщества и читает открытые JSON-ленты в пределах бюджета. Сообщества и посты без явной отрицательной метки `over18`/`over_18` не передаются на оценку; обычный общий кэш Reddit не используется. Доступность анонимного API и результаты на реальной площадке ещё не проверены. |
| Telegram, VK | При включённых `search_telegram` / `search_vk` auto использует анонимный веб-поиск и проверяет публичные страницы без личной авторизации. Требующие входа и проверки страницы откладываются. Содержимое проходит обычную проверку; работа с закрытыми источниками и через подключённые аккаунты в общий auto не входит. Проверка доступности 15 ноября 2026 года вернула HTTP 200 для одной страницы Telegram и HTTP 302 для страницы VK; выдача поиска и полный live-проход не проверялись. |
| YouTube | При `search_youtube` поиск и RSS каналов подключены к испытанию. Поддерживаются публичные MP4 с аудио до 12 МиБ и до 10 минут, включая адреса с подписью `signatureCipher`; подпись и параметр `n` вычисляются локально, каждый HTTP-запрос и перенаправление учитываются в бюджете. Требуется локальный Deno; отдельные аудио/видеодорожки, DRM и недоступные потоки не оцениваются и отправляются на повторную проверку. Один публичный пример успешно скачан за три учитываемых запроса; полноценный проход с моделью не подтверждён. |
| Одноклассники | При `autopilot_search_ok` (по умолчанию включён) публичные группы ищутся через RSS и проходят испытание и персональную доставку. Интеграционный тест использует подставные страницы и PostgreSQL; один публичный поисковый RSS ответил HTTP 200. |
| TikTok | При `autopilot_search_tiktok` (по умолчанию включён) авто ищет публичные аккаунты и индексированные страницы роликов через анонимный Brave; при его недоступности или отсутствии ссылок нужного типа пробует Bing RSS. Прямые и закодированные ссылки Bing проверяются по домену и форме TikTok без сетевого перехода через поисковик. Страницы и медиа запрашиваются с учётом бюджета. Принимаются только явно публичные видео до 3 минут и 12 МиБ; недоступные страницы и ролики не становятся отрицательной оценкой. Загрузчик пробует до трёх адресов с проверенной страницы, включая публичный `downloadAddr`, и отклоняет ответы без видео. В отличие от прежнего поиска здесь не используются Chrome и yt-dlp. Интеграционные тесты с подставными ответами и PostgreSQL прошли; живой Brave вернул HTTP 429, Bing не вернул подходящих ссылок, два адреса видео ответили HTTP 403, третий — HTML. Поэтому работа TikTok на реальной площадке пока не подтверждена. |

Ограниченные профили тем не отправляются в общий публичный поиск. RSS с произвольным регистрозависимым путём автоматически не подключается из-за совместимости старых идентификаторов. Для YouTube новые ключи сохраняют регистр ID; старые неоднозначные исключения и решения учитываются консервативно, пока пользователь не задаст точное личное решение.

Карточка темы показывает запас, количество источников, причину ожидания, остаток тематического бюджета и следующую проверку; история показывает публичные решения для настроенной темы. Повторный запрос повышает приоритет, но не отменяет задержку или суточный бюджет. Личная пауза сохраняется при рестарте. «Исключить для меня» действует только на текущего пользователя. Личное закрепление публичной RSS, Telegram, VK, Одноклассников или TikTok сохраняет источник для владельца, даже если общая проекция позднее удалена; фильтрация отдельных постов остаётся включённой. Выбор `off` останавливает его потребность, не останавливая других подписчиков той же темы.

Глобальное отключение соответствующего режима останавливает новые задачи и отзывает владение текущими при очередной сверке, обычно в течение минуты; ранее подключённые источники и история сохраняются. Для продолжения снова разрешите режим и выберите его для темы. Статусы моделей и сетевые лимиты учитывают повторные попытки; расходы ограничиваются серверным и тематическим дневными лимитами UTC.

Значения по умолчанию для поиска Хабра, Tumblr, Одноклассников и TikTok не перезаписывают сохранённые административные настройки: если площадка ранее явно выключена, её нужно включить в настройках. Порядок обращения к включённым площадкам меняется между проходами, чтобы первый backend не забирал каждый раз весь ограниченный сетевой бюджет.

## Диагностика и восстановление

Если системный DNS временно возвращает ошибки, можно явно задать процессу приложения `POSTA_PUBLIC_DNS_FALLBACK` как IPv4-адрес доверенного DNS-сервера. Он используется для публичных загрузок только после ошибки системного разрешения; системные настройки не меняются, а полученные адреса по-прежнему проверяются на публичность. По умолчанию резервный сервер не задан. Запросы к резервному DNS могут раскрывать ему имена сайтов, в том числе при включённом VPN, поэтому адрес и сетевой маршрут должны соответствовать настройкам владельца.

`source_autopilot_jobs` содержит срок, lease и последнюю ошибку; `source_autopilot_sources` — состояние пары источника и профиля; `source_autopilot_decisions` — историю переходов; таблицы бюджетов и наблюдений — фактические резервации и завершённые оценки. `source_autopilot_query_sources` связывает запросы и найденные источники: при выборе учитывается реальная отдача постов и сохраняется доля исследовательских проходов. Периодические проходы удаляют наблюдения и бюджеты старше 90 дней, решения и связи запросов старше 180 дней. При несовместимости с ручным источником или регистрозависимым путём RSS автопилот не подключает его автоматически.

Не восстанавливайте состояние прямым удалением каталога или пользовательских настроек. Сначала выключите auto, дождитесь завершения текущей работы и рассмотрите историю решений и ручные изменения после даты инцидента. Выборочное восстановление следует выполнять штатными действиями приложения или отдельно проверенной миграцией; универсальная команда отката, сохраняющая все последующие ручные изменения, пока не реализована.

## Степень проверки

Тесты используют отдельную PostgreSQL и подставные публичные ответы. Они проверяют очередь, fencing, ограничения бюджета, изоляцию, владение, оценку и проекцию в каталог. Ограниченный live-smoke 16 ноября 2026 года с явно выбранным резервным DNS выполнил один запрос к Bing News через исполнитель с lease и бюджетом: HTTP 200, три записи в RSS; модели не вызывались. Отдельный opt-in тест одного публичного примера на локальной `qwen3-vl:2b-instruct` не прошёл: модель не вернула ожидаемую тему. `python3 tools/source_autopilot_blind_sample.py --stdout` воспроизводимо готовит 48 неразмеченных примеров из существующих публичных fixtures для четырёх профилей; это материал для слепой разметки, а не оценка качества. Файл с возможной разметкой автоматически не перезаписывается. `python3 tools/source_autopilot_replay.py` суммирует внесённые позже независимые метки и записанные решения baseline и auto; сейчас таких меток и решений нет, знаменатели нулевые. Независимый benchmark с baseline и длительный live-pilot пока не выполнены; поэтому качество поиска в реальных темах не подтверждено.

## Диагностическая воронка (read-only)

В статусе автопилота появилась `audit_funnel`: источники с успешным чтением, завершёнными оценками, пригодными постами и сохранёнными результатами. Категории разрыва взаимоисключающие; пропуски в истории не считаются доказанным отказом. Для локального JSON-отчёта используется `posta autopilot-audit "SMM и блогинг"` (можно не задавать фильтр). Отчёт не отправляется наружу, не вызывает AI и не изменяет БД. Ключ темы берётся из задания, а не из текстового поиска по хэшу. Scope auto/shadow разделены; более старые версии оценки одного поста не суммируются с последней. `fetched_items_including_repeats` включает повторные загрузки; `actual_state_changes` не включает исходное создание источника и проверки без смены статуса. `eligible_without_matching_saved_version` — диагностическое несовпадение сохранённых версий, не доказательство ошибки записи (возможны сроки хранения). `useful_unique_per_source_30d` не дедуплицирован между разными источниками. Прямые поисковые результаты показаны отдельно. Все показатели ограничены историей хранения и не измеряют независимую тематическую точность. Политика допуска не изменена.
