# Радар лидов Postå

Радар читает публичные Telegram-чаты (группы) через личный аккаунт владельца и ищет людей, которым нужен Postå:
тех, кто ищет контент для канала, автопостинг, отложенные посты. Сообщения сначала отсеиваются по ключевым словам,
потом их оценивает локальная модель (`SMART_MODEL` через Ollama). Лиды сохраняются с ссылками на автора и сообщение.

**Радар — инструмент владельца сервиса, не функция для пользователей.** В приложении его нет, всё управление —
в отдельной админке `/posta/admin/`.

## Первый запуск

1. Задайте пароль владельца (дважды, без эха, от 10 символов):
   `php tools/cli.php admin-password`
2. Откройте `https://<домен>/posta/admin/` (локально — `http://localhost/posta/admin/`) и войдите.
3. «Аккаунт»: выберите аккаунт Telegram, подключённый в приложении (Личный кабинет), включите «Радар включён».
4. «Чаты» → «Найти чаты»: поиск публичных групп по запросам (запросы можно править), отметьте подходящие →
   «Добавить отмеченные». Группы меньше 50 участников не показываются. Свой чат можно добавить вручную: `@имя`.
5. «Проверка» → «Проверить сейчас»: в журнале видно, какие чаты прочитаны, сколько сообщений, что ответила модель.
6. «Лиды» — найденные люди (статусы: новые, интересно, ответил, спам, пропустить). «Отсеяно моделью» — что модель
   не сочла лидом, с причиной; «Переоценить» возвращает сообщение в очередь.

Пока админка открыта и радар включён, страница раз в минуту просит проход (сервер запускает его, если с прошлого
прошло больше 10 минут). Круглосуточно — cron:

```
*/10 * * * * /usr/bin/php /var/www/html/posta/tools/cli.php leads-scan --all >/dev/null 2>&1
```

`--all` берёт всех, у кого в настройках радара `enabled = true` (у владельца это выбранный аккаунт). Cron и сайт должны
работать от одного пользователя или с общей группой: блокировка и журнал — файлы `users/.radar-<uid>.lock` и
`users/.radar-<uid>.log`, они должны быть доступны на запись обоим.

## Команды

- `php tools/cli.php admin-password` — задать пароль админки.
- `php tools/cli.php leads-scan <uid> [--log=<файл>]` — один проход; журнал в stdout и в файл
  (по умолчанию тот, что показывает админка). `LEAD_BATCH_OVERRIDE=4` в окружении уменьшает число сообщений для модели.
- `php tools/cli.php leads-scan --all` — для cron.

## Безопасность админки

Вход по паролю (хранится только хэш в `kv`, `admin:password_hash`), своя сессия 12 часов, CSRF-заголовок на всех POST,
5 неверных паролей за 15 минут — блокировка по IP, строгий CSP без инлайн-скриптов. Тексты и имена из Telegram
выводятся только как текст, ссылки собирает сервер. Код админки не создаёт пользователей приложения.

## Ограничения

- Модель работает на CPU: секунды–минута на сообщение; за проход не больше 15 сообщений (`LEAD_BATCH`).
- Отсев по ключевым словам (`LEAD_KEYWORDS`) и признакам запроса: часть настоящих лидов может не дойти до модели.
- Читаются только публичные группы с `@username`; в чаты радар не вступает и ничего не отправляет.
  Закрытые для чтения без вступления чаты показываются с ошибкой.
- Первое чтение чата — последние 30 сообщений, дальше только новые.
- При большом числе чатов Telegram может попросить подождать (FloodWait): такой проход пропускает чат с ошибкой.
