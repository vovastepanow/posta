# Задача: подбор должен брать посты со всех площадок, а не только из Telegram, Двача, 4chan и RSS

Ты работаешь в проекте `/var/www/html/posta` (Posta). Владелец: «Мне надо парсить всё, а парсится сейчас только телега и двач, ну и RSS».
Код парсеров для VK, Одноклассников, TikTok и YouTube в проекте **есть** — посты оттуда не приходят по другим причинам (ниже).
Нужно, чтобы каждая площадка, для которой есть источники по теме, реально давала посты в подбор, а в журнале было видно, почему площадка пустая.

Ничего не коммить. Не трогай `php.ini`, crontab, systemd, Apache, sudo. Модели не менять (анализ — `SMART_MODEL`, быстрая — 2B).

## 1. Что выяснено 2026-10-23 (перепроверять не нужно)

**Что реально попало в быструю оценку** (`screened_cache`, по префиксу источника): `dvach` 1968, `telegram` 550, `4chan` 62, `rss` 15.
**VK, ok, tiktok, youtube — ноль.** Каталог (`catalog_sources`): `2ch_boards` 113, `telegram_channels` 36, `rss_feeds` 21 (только новости и техника,
YouTube-лент нет), `vk_publics` 6 (все «мемы и юмор»), `tiktok_accounts` 1 (тема «тест-видео-источники»), Одноклассников — 0.
Находки автоподбора (`source_suggestions`): Telegram 172, RSS 18, TikTok 2, Одноклассники 1.

Журнал последнего прогона — `users/b34cfe131b9ddea519d4cbd42c831fb5/parser-v3.log` (тема «Абсурдный юмор»). Причины по площадкам:

1. **VK не подключён вообще.** `config.local.php` — шаблон: `VK_REDIRECT_URI = https://ВАШ_ДОМЕН/index.php?action=vk_oauth_callback`,
   `VK_SERVICE_TOKEN` пуст, токенов в `kv('vk_tokens')` нет. `collect_posts_by_platform` (`lib/parser.php:146`) пропускает все паблики VK
   («VK OAuth не подключен»), `discovery_find_vk` — тоже. Сервисный ключ приложения VK (`VK_SERVICE_TOKEN`) уже предусмотрен в конфиге,
   но используется только при обновлении OAuth-токена (`vk_access_token`, `lib/sources.php:411`).
2. **YouTube находится, но не доходит до каталога.** Поиск находит каналы, проверка даёт «по теме 98–99%», но итог —
   «аудитория неизвестна … глубина 0 → 64% — в предложения»: без числа подписчиков оценка проседает, и канал остаётся в `source_suggestions`.
   5 из 11 каналов — «This channel does not have a videos tab» (канал только с шортсами) → «не загрузилось», хотя `lib/youtube.php` шортсы читать умеет.
3. **Находки в подборе почти всегда — Telegram.** Пока у темы мало своих источников, парсер берёт «до 12 находок автоподбора»
   (`lib/parser.php:163–173`) — первые 12 по порядку, а Telegram-находок 172 против 18 остальных. YouTube/TikTok/ОК-находки до сбора не доходят.
4. **TikTok: поиск приносит мёртвые аккаунты.** 16 из 16 отказов: «последний пост 1752 / 2564 / 675 дн назад», «1.8 постов в неделю»,
   «нет слов темы». Поиск аккаунтов (`tiktok_search_users`, `lib/tiktok_search.php`) по запросам вроде «парадоксальные видео» находит
   аккаунты по нику, а не по живому контенту.
5. **Одноклассники:** поиск идёт только по лентам разделов (`discovery_find_ok`, ключевые слова в тексте) — 4 группы, все «известных пропущено».
   Сводка по ОК пишет пустые числа и PHP Warning: `Undefined array key "found"/"checked"/…` в `lib/discovery_finders.php:140`.
6. **RSS** засеян только новостными сайтами (`lib/news_sites.php`) — для юмора лент нет, это нормально.

Не делаем (одной строкой в отчёте): Instagram/Facebook (без входа не читаются), X/Twitter-лента (без входа не отдаётся, есть только импорт твитов по ссылке),
Reddit (403 с сервера), Дзен (нет ленты).

## 2. Что сделать

### A. VK без OAuth — через сервисный ключ
- Открытые сообщества читаются методом `wall.get` с **сервисным ключом приложения** — вход пользователя не нужен. Сделай так:
  `vk_api_token_for_read()` — OAuth-токен, если есть, иначе `VK_SERVICE_TOKEN`. Им пользуются чтение стены, `groups.getById` и предпросмотр
  источника (`build_vk_preview_posts`, `lib/source_add.php:52`). Проверь в документации VK API, какие методы принимают сервисный ключ;
  `groups.search` — требует ключ пользователя: поиск сообществ VK остаётся только при подключённом OAuth (оставь текущее сообщение).
- Сообщение в журнале: нет ни OAuth, ни сервисного ключа → «VK: нет ключа — паблики VK пропущены (добавьте сервисный ключ в config.local.php)».
- **Владельцу (в отчёт, отдельным блоком, по шагам):** создать приложение на `id.vk.com` (тип «Веб»), скопировать «Сервисный ключ доступа»
  в `config.local.php` → `VK_SERVICE_TOKEN`; для OAuth заменить `ВАШ_ДОМЕН` настоящим адресом. Сам ключ не придумывай и в файлы не пиши.
- Без ключа проверить чтение нельзя — напиши код, проверь разбор ответа на сохранённом образце ответа `wall.get` (фикстура в `tools/fixtures`), а живую проверку оставь владельцу.

### B. Честная оценка не-Telegram источников при поиске
- Найди, где считается итог «по теме X%, аудитория …, глубина … → Y%» (`evaluate_source` / `discovery_finish_probe`) и почему неизвестная аудитория
  роняет 98% до 64%. Неизвестная аудитория должна быть **нейтральной**, а не штрафом.
- YouTube: число подписчиков отдаёт yt-dlp (`channel_follower_count` на вкладке канала) — возьми его при проверке, если это не лишний долгий вызов
  (есть уже вызов списка роликов — посмотри, приходит ли оно там же).
- Канал без вкладки «Видео» — пробуй вкладку шортсов (как `lib/youtube.php`), а не «не загрузилось».
- Порог попадания в каталог для всех площадок одинаковый; после правки на том же прогоне «Абсурдного юмора» YouTube-каналы с 98–99% должны
  попадать в каталог (или объясни в отчёте, почему нет).

### C. Находки в подборе — поровну по площадкам
`lib/parser.php:163–173`: вместо «первые 12» — по кругу по площадкам (Telegram, VK, YouTube/RSS, TikTok, ОК), лучшие по `score` внутри площадки.
Там же для поиска уже есть `discovery_balance` — переиспользуй, если подходит.

### D. TikTok — живые аккаунты
- Вместо (или вдобавок к) поиска аккаунтов по нику — авторы **свежих популярных видео** по запросу/хештегу (как YouTube: «авторы шортсов»).
  Посмотри, что отдаёт страница поиска видео/хештега в `lib/tiktok_search.php` (headless Chrome, не больше двух поисков за прогон, пауза при капче — сохрани).
- Запросы для TikTok — короткие, разговорные, хештеги темы (из профиля: `keywords`/`queries`), не «парадоксальные видео».
- Если TikTok отдаёт капчу — честно в журнал и в отчёт; обход капчи не делать.

### E. Одноклассники
- Почини сводку (`discovery_finders.php:140`): отсутствующие счётчики — 0, без Warning.
- Посмотри, почему все 4 найденные группы «известные» (уже в находках или отвергнуты?) — и что будет на теме, где ОК ещё не искали.
  Если поиск по лентам разделов для темы почти ничего не даёт — опиши в отчёте, что ещё возможно без входа (поиск групп ok.ru отдаётся без входа? проверь одним запросом через `rss_get`).

### F. Сводка по площадкам в журнале
В конце `collect_posts_by_platform` — одна строка-итог по **всем** площадкам, даже пустым, с причиной:
`Площадки: Telegram 312 постов (18 каналов) · Двач 501 (4 доски) · 4chan 138 · YouTube 0 — нет источников по теме · VK 0 — нет ключа · TikTok 0 — нет источников · ОК 0 — нет источников · RSS 0 — нет лент по теме.`
Владелец должен по журналу сразу видеть, почему площадка ничего не дала.

## 3. Проверка

- **Не открывай сайт Posta** (`http://localhost/posta/...`) в curl/headless: свежая загрузка создаёт пользователя и запускает парсер, который не остановить.
  Работай из CLI (`php tools/cli.php …`, посмотри доступные команды). Перед запуском парсера проверь, что он не работает у владельца
  (`users/*/parser-v3.lock`, `parser_runtime`).
- `php -l` на каждый изменённый файл; тесты, которые трогают твои места (`tools/test_discovery.php`, `tools/test_video_sources.php`, `tools/test_sources2.php`) — проходят.
- Поиск источников для «Абсурдного юмора» и для «Котики» (или другой темы, где TikTok и YouTube должны быть богатыми): сводка «найдено/проверено/принято»
  по площадкам до и после.
- Один прогон сбора по «Абсурдному юмору»: строка из F; цель — в быструю оценку попадают посты **хотя бы с трёх площадок, кроме Telegram/Двача/4chan**,
  для которых есть источники (YouTube, TikTok, ОК; VK — если владелец уже дал ключ). Посчитай по `screened_cache` префиксы источников до/после.
- Время поиска источников не должно вырасти больше чем на 20% (сейчас ~10 мин на «Абсурдный юмор»).
