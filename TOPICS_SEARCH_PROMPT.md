# Задача: поиск по темам — узкие ниши, «формат» темы, текстовые посты, поиск источников без ухода в сторону

Ты работаешь в PHP-проекте `/var/www/html/posta` (Posta: подбирает контент по теме пользователя из Telegram, VK,
RSS, Двача и др., локальные модели Ollama оценивают посты, пользователь публикует их в свой канал).

Владелец: «поиск по разным темам работает плохо; темы слишком обширные — „Бизнес“, а нужен строительный бизнес,
недвижимость, крипта; нужны хэштеги; у каждой темы свои важные аспекты: для мемов обязательно картинка или видео,
новости — это в основном текст».

**Почему «Бизнес» не работает — цепочка, видна по `source_suggestions` и `discovery.checked_at`:**
1. **Запросы уводят в сторону.** Профиль темы (`topic_profile_build`) дал запросы «пассивный доход», «инвестиции
   новичку», «криптовалюты бизнес», «бизнес идеи 2024» (устаревший год). У «Новостей» — «выборы 2024».
2. **Снежный ком уводит ещё дальше.** «пассивный доход» → канал о недвижимости → «похож на» → «Движ про недвиж» →
   «похож на» → «Новости Москвы» (2,6 млн) → «упомянут в» → «Что там, Москва?», «Московская птичка», «Мэр Москвы
   Собянин», «Защитники Отечества». Все они попали в предложения темы «Бизнес».
3. **Быстрая модель 2B ставит оценку текста слишком щедро:** «Новости Москвы» — 72% «по теме Бизнес», «Защитники
   Отечества» — 74%. При `SOURCE_TEXT_TRUST_SCORE = 70` текст получает вес 0.7, и канал проходит.
4. **Проверка постов в парсере строгая и смотрит на картинку**: посты тех же каналов получают 0–2 (`mosptichka` —
   16 постов, средняя 2; `newsmoscow` — 14 постов, средняя 2). Источник принят, а контента из него нет.
   Оценка источника и оценка поста **не согласованы**.
5. **Профиль темы только про картинку**: промпт `topic_profile_build` — «Тема подбора картинок и видео… что должно
   быть видно на картинке». Для бизнеса, новостей, крипты смысл поста в тексте, а картинка — стоковая иллюстрация.
6. **Посты без картинки не собираются вообще** (`telegram_posts_from_html` — «посты с медиа», RSS и VK пропускают
   посты без картинки, `own_post_item` требует картинку). Новостные и экспертные каналы наполовину текстовые.

## Что делаем

```
Тема = название + место в дереве + ФОРМАТ + ключевые слова (+ уточняющие теги)
           │
           ├─ формат: медиа обязательно? текст обязателен? по чему судить (картинка / текст / оба)?
           │      мемы: медиа обязательно, судим по картинке+подписи
           │      новости, бизнес-ниши: текст обязателен, медиа — нет, судим по тексту
           │
           ├─ поиск источников: запросы строго по теме, без годов; снежный ком только от каналов,
           │   прошедших ключевые слова; оценка источника = доля ЕГО постов, прошедших ту же проверку, что в парсере
           │
           ├─ сбор: текстовые посты собираются, если формат темы их допускает
           │
           └─ отзывы пользователя: канал с плохой долей лайков уходит из подбора темы
```

Делай части по порядку: 0 → A → B → C → D → E → F → G. После каждой — проверка. Не начинай следующую, пока не прошла
предыдущая. Части F и G — **только если A–E прошли**; иначе остановись и напиши, на чём застрял.

## Общие правила

- **Не делай git commit.**
- **Перед первой записью в базу:** `cp data/posta.sqlite data/posta.sqlite.bak-topics2`.
- **НЕ открывай сайт** (`http://localhost/...`) в curl, headless Chrome или Playwright: каждая загрузка без
  куки создаёт пользователя и запускает парсер, который нельзя остановить без sudo. Всё проверяй через `php` в CLI.
- **Модели.** Видеокарта 3 ГБ, на ней работает парсер пользователя. Полный анализ поста — только умная модель
  (`SMART_MODEL` / `ANALYSIS_MODEL`); **не переводи** никакую работу с умной модели на быструю 2B. Быстрая 2B
  (`prescreen_model()`) часто «всё подходит» — **её ответ «по теме» без проверки не принимай**. В проверках вызывай
  модели только там, где это прямо сказано, и с ограничением числа вызовов.
- **Не делай запросов в поиск DuckDuckGo/Bing** — сервер получает капчу. Поиск каналов — Telegram через аккаунт
  (`telegram_user_find_channels`) и VK API, как сейчас. В проверках — не больше 10 запросов поиска Telegram за
  запуск (лимиты аккаунта пользователя).
- **Каталог источников общий для всех пользователей.** В проверках используй темы с префиксом `тест-` и убирай за
  собой (записи каталога, голоса, предложения, `discovery.checked_at` с этим префиксом).
- Код в стиле проекта: короткие функции, комментарии по-русски одной строкой, `RuntimeException` с понятным текстом,
  SQL — через `db_*`. Схему SQLite не меняй без нужды: тема — JSON в `topics.data`, новые поля просто добавляются.
- Тексты для интерфейса — по-русски, понятные владельцу канала, без слов «профиль», «эмбеддинг», «скоринг».

## Часть B. Формат темы — «важные аспекты»

1. В JSON темы — поле `format`:
   ```
   format: {
     media: 'required' | 'optional',          // мемы, котики, арт — required; новости, бизнес-ниши — optional
     text:  'required' | 'optional',          // новости, экспертные ниши — required (min_text символов)
     judge: 'image' | 'text' | 'both',        // по чему решать «по теме»: мемы — both (картинка+подпись), новости — text
     min_text: число,                         // минимум осмысленного текста для text=required (например 120)
     kinds: ['meme','photo','video','text','article', …]  // какие формы постов подходят (есть поле «форма поста» в анализе — см. TOPIC_TREE_PROMPT.md часть B)
   }
   ```
   Функция `topic_format($topic): array` — формат темы; нет поля — по родителю; нет и у родителя — умолчание
   `media=required, text=optional, judge=both` (нынешнее поведение, ничего не ломается).
2. В `lib/topic_tree.php` задай `format` каждой общей ветке (частные наследуют, могут переопределить): юмор,
   животные, арт, косплей, природа, 18+ — `media=required, judge=both`; новости и политика, наука и знания,
   деньги и бизнес (вся новая ветка из части D), технологии, здоровье, цитаты — `media=optional, text=required,
   judge=text`; кино, игры, спорт, музыка, еда — `media=optional, text=optional, judge=both`. Если сомневаешься —
   напиши в отчёте, что выбрал и почему.
3. Для тем пользователя вне дерева формат пишет умная модель вместе с профилем: добавь `format` в схему и промпт
   `topic_profile_build` (с объяснением полей и примерами «мемы» / «новости» / «строительный бизнес»), значения
   проверяй по списку допустимых, мусор → наследование от родителя.
4. **Перепиши промпт профиля под формат**: сейчас он «тема подбора картинок и видео… что должно быть видно на
   картинке». Для `judge=text` — «о чём должен быть текст поста», вопрос — по тексту («Этот пост про …?»);
   для `judge=both` — как сейчас, но с подписью. Подними `TOPIC_PROFILE_VERSION`, чтобы профили пересобрались.
5. В том же промпте — **ключевые слова темы** `keywords`: 10–20 слов и корней по-русски (и 3–5 по-английски),
   по которым тему видно в названии и тексте канала («стро», «ремонт», «застрой», «прораб», «бригад»… для
   строительного бизнеса). И запреты для `queries`: **без годов и дат**, без соседних тем («пассивный доход» —
   не запрос для «Бизнеса»), каждый запрос должен содержать хотя бы одно ключевое слово.
6. В интерфейсе темы (рядом с полем темы или в её описании) — одна строка, как сейчас понята тема:
   «Ищем: посты с картинкой или видео · судим по картинке и подписи» / «Ищем: текстовые посты, картинка не
   обязательна · судим по тексту». Ссылка «Изменить» открывает три переключателя (медиа обязательно, текст
   обязателен, судить по …) — правка сохраняется в теме **для этого пользователя** (в его настройках,
   переопределение поверх формата темы), не в общем реестре.

**Проверка:** `php -r` — `topic_format` для «Мемы и юмор», «Новости и политика», «Бизнес», «Кошки», «Политика»
(наследование). Пересборка профиля «Бизнес» умной моделью (1 вызов): у профиля есть `format` с `judge=text`,
`keywords`, в `queries` нет годов и «пассивного дохода». Покажи профиль целиком в отчёте.

## Часть C. Поиск источников без ухода в сторону

В `lib/discovery.php`:
1. **Ключевые слова — дешёвый фильтр до модели.** `discovery_keyword_hit($topic, $title, $description, $texts)`:
   есть ли хоть одно ключевое слово темы (корень, `mb_stripos`) в названии/описании или **в 2 из последних 8
   подписей**. Нет — канал отклоняется без вызова модели («нет слов темы в канале»). Для тем без `keywords`
   (старый профиль) — фильтр пропускается.
2. **Снежный ком только от своих.** «Похожие на» и «упомянут в» ставятся в очередь **только** от каналов, которые
   прошли (добавлен или предложен) **и** прошли фильтр ключевых слов. Глубина не больше 2 шагов от поиска;
   у кандидата храни `depth`, в журнале показывай. Кандидаты из поиска — первыми.
3. **Оценка источника = оценка его постов тем же способом, что в парсере.** Вместо «средняя быстрых оценок
   картинок + 0.7 текста»: возьми до 6 свежих постов источника, которые **проходят формат темы** (часть B:
   нет медиа при `media=required` — пост не считается), и оцени каждый **той же функцией и тем же порогом**, что
   `prescreen_batch` в парсере для этой темы (для `judge=text` — по тексту, см. часть E). Итог источника — доля
   прошедших постов. Добавлен в каталог — от 50% и минимум 3 прошедших; в предложения — от 30%; иначе отказ.
   Ранний выход: первые 3 поста — 0 прошедших → отказ. Старая оценка по описанию канала (`quick_source_text_score`)
   остаётся только как дешёвый предварительный отсев явно чужих (< 20), не как бонус.
   Если для этого нужен рефакторинг `prescreen_batch` — вынеси оценку одного поста в общую функцию
   `post_topic_prescreen(array $post, string $topic): ?int` и используй её в обоих местах.
4. **Широкая тема ищет через частные.** Если у темы есть дети в дереве (scope `broad`), запросы для поиска — по
   2 лучших запроса каждой частной темы (из их профилей; нет профиля — название и синонимы), а не общие слова
   вида «деньги заработок». Найденный канал привязывается к **частной** теме, которой он соответствует по ключевым
   словам (и к общей, как сейчас, через наследование `topics_are_equivalent` — проверь, что подбор по общей теме
   видит источники частных).
5. **Минимум подписчиков и активность** — как сейчас; но кандидаты поиска сортируй по подписчикам внутри каждого
   запроса.

**Проверка:** тестовая тема `тест-строительный бизнес` (родитель — новая ветка из части D, если она уже есть;
иначе «Деньги и заработок»), `run_source_discovery` с `SOURCE_DISCOVERY_MAX_CHECKS` = 10 (временно, через параметр
функции или константу только на время проверки). В журнале: запросы без годов и без соседних тем, кандидаты с
`depth`, отказ «нет слов темы» для каналов вроде новостей Москвы, найденные — про стройку/ремонт. То же для
`тест-мемы` (не сломалось: мемные каналы проходят). Убери тестовые записи.

   Существующие частные `money.crypto`, `money.invest`, `money.business`, `money.other` **сохрани с теми же ключами**
   (у записей уже стоят такие метки), поменяй только названия, если нужно.
   Порядок веток: 18+ и «Жесть» остаются первыми (модель читает сверху вниз).
2. Засей (`php tools/cli.php seed-topics` или как устроено в `TOPIC_TREE_PROMPT.md`) — проверь, что существующие
   темы пользователей («Бизнес», «Деньги и заработок») не потеряли источники и голоса: тема «Деньги и заработок»
   должна стать синонимом «Бизнес и деньги» (алиас), «Бизнес» — остаться частной темой (`money.business`).
3. **Узкий ввод не должен склеиваться с широким.** Сейчас `topic_resolve` может отдать «строительный бизнес» как
   синоним «Бизнес» (модель сказала match + похожесть по эмбеддингам). Правило: если ввод **длиннее** найденной
   темы и содержит её название плюс уточнение («строительный бизнес», «крипта для новичков», «мемы про
   программистов»), это **новая частная тема** с родителем = найденная тема (или её родитель, если найденная —
   частная), а не синоним. Если среди частных тем дерева есть точное соответствие («строительный бизнес» →
   «Строительство и ремонт») — предложи её в уведомлении `#topic-notice` («Похоже на тему „Строительство и ремонт“ —
   выбрать её?» / «Нет, это другая тема»), как сейчас работает подтверждение.
4. **Уточняющие теги в интерфейсе.** Под полем темы, если выбрана **общая** тема: строка чипов «Уточнить:» с её
   частными темами (до 12, остальное — «ещё…»). Клик по чипу — выбирает частную тему как тему подбора (как будто
   ввели её название). Если выбрана частная тема — чипы её «соседей» и ссылка «← вся тема „Бизнес и деньги“».
   Используй существующие классы чипов из `css/app.css`.
5. **Метки записи как хэштеги.** Метки `tags` (частные темы дерева) уже ставятся полным анализом — после части D
   они станут подробнее сами (больше частных тем). Покажи их на карточке как `#недвижимость #маркетинг` (сейчас —
   найди, как `renderTags` их рисует), клик по хэштегу — «Искать по теме #недвижимость» (меняет тему, с
   подтверждением). При подборе по частной теме карточка, у которой эта тема не среди меток, получает штраф к
   рейтингу (`relevance` − 15) — в `analyze_candidate`, после ответа модели; константа в `config.php`.

**Проверка:** `php -r` — дерево засеяно, «Деньги и заработок» → алиас; `topic_resolve('строительный бизнес')` —
предлагает «Строительство и ремонт» (с `matched`), а `topic_resolve('строительный бизнес', true)` — новая частная тема с
верным родителем; `topic_resolve('мемы про программистов')` — новая частная под «Мемы и юмор», не синоним.
(Классификация вызывает умную модель — не больше 4 вызовов на проверку.) Убери созданные тестовые темы.

## Часть E. Текстовые посты для тем с `text=required` или `media=optional`

1. **Сбор.** `telegram_posts_from_html`, VK (`build_vk_preview_posts`), RSS (`rss_parse`): если пост без медиа, но
   с текстом не короче `min_text` (по умолчанию 120 символов) — возвращай его с `image = ''`, `text_post = true`.
   По умолчанию (без флага) функции работают как раньше; флаг `$with_text` включается в `collect_catalog_source`,
   только если формат **хотя бы одной** темы, к которой привязан источник, допускает текстовые посты.
   Найди всё, что ломается от пустого `image` (`content_image_key`, дедупликация по картинке и `phash`,
   `candidate_is_known`, кэш медиа, `media_cache_*`, карточка, история) — для текстового поста ключ записи —
   `text:` + sha1 нормализованного текста (без ссылок и эмодзи). Проверь каждую точку.
2. **Оценка.** Для текстового поста и для любого поста темы с `judge=text` предварительная проверка и полный
   анализ идут **по тексту**: промпт с текстом поста и критериями профиля, без картинки, **умной моделью**
   (`SMART_MODEL`, только текст — без vision-входа). Схема ответа — та же, что у `content_analysis_schema`
   (оценка, описание, метки `tags`), чтобы дальше всё работало одинаково. Пачкой, как сейчас пачки prescreen,
   чтобы не гонять модели туда-сюда (сначала все текстовые оценки пачкой, потом картинки — см. `ANALYZE_BLOCK`).
3. **Формат как жёсткий фильтр.** В `build_candidate_queue`: пост без медиа при `media=required` — не кандидат;
   пост с текстом короче `min_text` при `text=required` — не кандидат. В журнале — счётчики «отсеяно форматом: N».
4. **Карточка и публикация.** Карточка текстового поста — текст крупно (до 12 строк, «Показать полностью»),
   без пустого места под картинку. Публикация — как пост без медиа (`sendMessage`), редактор поста уже умеет пост
   без медиа? — проверь `openPostEditor` и `handle_telegram_publish`; если нет — добавь.

**Проверка:** тестовая тема `тест-новости` (родитель «Новости и политика», формат текстовый) + 1 публичный
новостной канал в каталоге с этой темой; `collect_catalog_source` возвращает текстовые посты; один проход оценки
(не больше 5 вызовов умной модели) — у текстовых постов есть оценка и метки; для `тест-мемы` текстовые посты
**не** собираются. Тест на пустой `image` в дедупликации: два одинаковых текстовых поста из разных каналов →
второй — «уже известен».

## Часть F. Отзывы пользователя управляют источниками (только если A–E прошли)

1. Доля лайков источника по теме — из истории (`liked` / `disliked` / жалобы `match_error`): функция уже частично
   есть (`source_feedback_stats`, `combined_source_rates`) — разберись, как она влияет на очередь сейчас.
2. Правило: источник с ≥ 10 оценок по теме и долей лайков < 25% (жалоба считается как дизлайк ×2) —
   **выключается для этой темы у этого пользователя** (в его настройках, не в общем каталоге) с записью в журнал
   «@why43my выключен для темы „Мемы и юмор“: 1 лайк из 15». На вкладке «Источники» такой источник показан с
   пометкой «выключен по вашим оценкам» и кнопкой «Включить».
3. Площадка целиком (например, Двач для мемов: 20 лайков на 143 дизлайка и жалобы) — то же правило на уровне
   «площадка × тема × пользователь»: доля постов с неё в очереди снижается до 10%, а не обнуляется (чтобы
   отзывы могли передумать).

**Проверка:** на копии истории тестового пользователя: синтетически 15 оценок источника (1 лайк) → выключен; 15
оценок (10 лайков) → нет; Двач с плохой долей → доля в очереди ≤ 10%.

## Часть G. Итог (только если A–F прошли)

`php tools/topic_report.php > /tmp/topic-report-after.txt`; в отчёте — сравнение «до / после» по темам и
отдельно: что поменялось для «Бизнес», «Новости и политика», «Мемы и юмор».
Учти: «после» сразу после правок почти не изменится (нужны проходы парсера) — опиши, на что смотреть через
день-два работы.
