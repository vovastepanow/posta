# Задача: автоподбор источников работает коряво и не по всем площадкам

Ты работаешь в PHP-проекте `/var/www/html/posta` (Posta). Автоподбор источников — `run_source_discovery_locked()` в `lib/discovery.php` (~стр. 630),
поисковики — `lib/discovery_finders.php`, проверка кандидата — `check_discovery_candidate()` (`lib/discovery.php` ~стр. 328).
Владелец: «коряво и не по всем платформам подбираются источники». Делать сразу, без долгих исследований; старые способы не убирать.

## Что сделать

### A. Больше проверок за то же время

1. Дешёвый предфильтр **до** оценки картинок: язык названия/описания (кириллица или английский; латиница с явно другим языком — индонезийский, польский, итальянский,
   испанский, португальский — отказ без проверки), явные «не те» слова для темы (`exclude` из профиля темы, если есть в `topic_lookup`), ключевые слова
   в названии/описании/текстах постов (`discovery_keyword_hit` уже есть — применяй и к `tg_search`, сейчас для них может проходить `null`).
2. Сортировка очереди внутри группы: сначала кандидаты с совпадением слов темы в названии, с ≥2 упоминаниями (из разных запросов / `refs`), найденные по постам;
   иначе — как сейчас. Круг групп (`DISCOVERY_GROUP_ORDER`) оставь.
3. Оценка картинок: если первые 3 картинки дали по теме < 40% — отказ, остальные не смотреть (найди в `source_images_review`/`evaluate_source`, сколько их сейчас).
4. YouTube: не проверять второй раз тот же канал (лента `channel_id` и `UUSH…` — один кандидат). Проверь, почему `alt_id` не спасает: в `checked_at` есть обе ленты.

### B. Качество поиска Telegram

1. Названия от модели: оставить, но **не больше 3** за прогон (`DISCOVERY_NAMES_PER_RUN`), и только если поиск по запросам дал < 15 каналов.
2. Адреса от модели — без изменений (они проверяются пачкой и дёшево отсеиваются).
3. Результаты `contacts.Search` с названием без кириллицы и без слов темы — в конец очереди (не выбрасывать: англоязычные мемы бывают хорошими).

### C. YouTube — живые каналы

Вместо (или вместе с) выдачи «только каналы» брать **авторов свежих роликов**: выдача видео за неделю (`sp=EgIIAw%3D%3D`) и шортсы (`ytsearch` с «shorts», как сейчас);
каналы, у которых нашёлся свежий ролик, — первыми. Можно переиспользовать `post_search_youtube()` из `lib/post_search.php` — оттуда же авторы.

### D. Одноклассники

Строже фильтр: слово темы должно быть в **названии группы** или минимум в 2 записях группы из ленты; иначе не кандидат. Если после этого кандидатов почти не бывает — пусть так.

### E. Площадки, которых нет

1. **Поиск постов → кандидаты** (часть 5 из `POST_SEARCH_PROMPT.md`): в `run_source_discovery_locked` вызвать адаптеры `lib/post_search.php` по запросам плана,
   авторов постов — в `$add` с `origin_kind = 'post_search'` (подпись в `DISCOVERY_ORIGIN_LABELS`: «нашёлся по постам»), автор с ≥2 постами — `$front = true`.
   И из подбора контента: пост с `found_by`, прошедший полный анализ, автор ещё не источник и не кандидат → в предложения (`store_discovered_source`, причина — «пост прошёл отбор: <ссылка>»).
2. **VK без OAuth**: `groups.search` требует OAuth, но есть сервисный ключ для чтения (`vk_api_token_for_read`, `lib/sources.php`). Если OAuth нет — найди, что можно
   сделать сервисным ключом (например, `groups.getById` для ссылок vk.com из постов Telegram и поиска постов), и подключи это; в журнал — честно, что поиск сообществ без OAuth не работает.
   Если нет и сервисного ключа — одна строка в журнале, как сейчас.
3. **TikTok**: пауза на сутки после одного пустого ответа — слишком жёстко. Сделать паузу нарастающей: 1 ч, потом 6 ч, потом 24 ч (счётчик в `kv tiktok_search_pause`),
   сброс после первого непустого ответа.
4. **VK-посты и TikTok-видео в `lib/post_search.php`** — адаптеры `post_search_vk` (`newsfeed.search`, нужен OAuth — без него пропуск) и `post_search_tiktok`
   (страница поиска видео уже разбирается в `lib/tiktok_search.php` — вернуть видео, а не только авторов). Подключить в `post_search_collect`.
5. **Pinterest / Tumblr**: один пробный запрос (`pinterest.com/search/pins/?q=`, `tumblr.com/tagged/<тег>`); если ответ разбирается без JS — найденные авторы → кандидаты
   (лента через `discovery_feed_url`). Если нет — пропусти и напиши почему.

### F. Сводка в журнале

В конце прогона сводка по площадкам уже есть (`discovery_summary_lines`). Добавь туда строки для поиска постов (`post_search`) и для площадок, которые пропущены, — **с причиной**
(«VK: нет OAuth», «TikTok: пауза до 17:40», «Pinterest: ответ без данных»), чтобы владелец видел, почему площадки нет.

## Ограничения

- **Не открывай приложение в headless-браузере с чистым профилем** — новая загрузка = новый пользователь + парсер, который не остановить.
- Живую базу `data/posta.sqlite` не меняй руками; опыты — на копии.
- DuckDuckGo/Bing с сервера дают капчу — не используй.
- Telegram — личный аккаунт владельца: лимиты из `lib/post_search.php` (`TG_SEARCH_PER_HOUR`) и FloodWait соблюдать.
- Модель анализа не менять на маленькую ради скорости: для этого уже есть переключатель «Только быстрая модель» (админка → «Управление»).
  Новые вызовы модели — только через `smart_model()` / `analysis_model()` / `prescreen_model()` из `lib/ai.php`, не константой `SMART_MODEL`, иначе переключатель их не затронет.
- Стиль кода как в соседних файлах. Не коммить.
