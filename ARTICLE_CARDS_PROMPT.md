# Задача: статьи с сайтов (vc.ru и др.) — нормальные данные и красивая карточка статьи

Ты работаешь в PHP-проекте `/var/www/html/posta`. Проект подбирает посты из соцсетей и сайтов по теме пользователя
и показывает их карточками. Статьи с новостных сайтов (RSS, список в `lib/news_sites.php`) сейчас выглядят плохо:
мусор в тексте, вместо фото — картинка-заглушка с заголовком, длинная статья не помещается, карточка сделана под мем.

Цель: **(1)** доставать из статей чистые данные (заголовок, анонс, настоящая обложка, структура текста),
**(2)** сделать отдельный вид карточки «статья», **(3)** заодно навести порядок в общей структуре карточки,
чтобы все виды (картинка/видео, текст, статья) были собраны из одних блоков.

## Что выяснено (2026-10-23, по базе и живым запросам к vc.ru — перепроверять не нужно)

**Данные.**
- Лента `https://vc.ru/rss` отдаёт в записи: `title`, `description` (1–2 предложения анонса + `<img>` обложки),
  `enclosure` (обложка, бывает не у всех), `guid` = числовой id статьи (он же число в адресе:
  `vc.ru/services/3209892-...`), `dc:creator` — автор.
- `article_enrich()` (`lib/article.php`), если текст короче `ARTICLE_SHORT_TEXT`, дописывает в текст
  `og:description` страницы. **У vc.ru `og:description` — это SEO-список через запятую**, например
  «Атаки на сайты из-за уязвимости PHP, Cloudflare сообщает о миллионах попыток, ограничения от Битрикс24…».
  В базе у записей vc.ru третья строка текста — именно этот мусор.
- `og:image` у vc.ru — **сгенерированная обложка с заголовком текстом** (`https://api.vc.ru/v2.9/cover/fb/c/<id>/.../cover.jpg`).
  Если в RSS нет `enclosure`, запись получает её вместо фото. Модель анализа описывает такую запись как
  «Скриншот новости с текстом», в карточке это выглядит как картинка текста.
- `article_main_text()` на vc.ru не работает: блоки текста вложены (`block-text` → `andropov-media`), регулярка
  берёт только первый абзац (`article_text` = 141 символ, по сути анонс). На странице есть и чужие статьи.
- **У vc.ru есть открытый API платформы Osnova** (на ней же `dtf.ru`):
  `GET https://api.vc.ru/v2.10/content?id=<id>` → `result` с полями `title`, `blocks`, `ogDescription`,
  `summaryContent`, `isExistSummaryContent`, `counters`, `author`, `subsite` (рубрика), `date`, `url`.
  `blocks` — массив `{type, cover, hidden, data}`; встречаются `text` (`data.text` — HTML `<p>`),
  `header`, `media` (`data.items[].image.data.uuid`, `width`, `height`, `title` — подпись), `list`
  (`data.items` — HTML-строки), `quote`, `video`, `osnovaEmbed` (карточка другой статьи), последний `text`
  бывает просто `#новости`. Картинка: `https://leonardo.osnova.io/<uuid>/`, уменьшенная —
  `https://leonardo.osnova.io/<uuid>/-/resize/1300/`. Для dtf.ru то же самое на `api.dtf.ru`.
  Сохрани один ответ API как фикстуру `tools/fixtures/vc_article.json` (для стенда и проверок), найди и сохрани
  ещё одну **длинную** статью vc.ru (блог, 8+ экранов, с заголовками, списками, цитатой, несколькими картинками)
  как `tools/fixtures/vc_longread.json`.

**Показ.** Карточка записи рисуется в нескольких местах, и все они думают, что запись — это мем с подписью:
- главная карточка: `js/content.js` — `itemSlides`, `renderSlide`, `renderCard`, `applyTextMode`,
  `textPostBlock`; разметка `#item-card-wrapper` в `index.html`; стили `.card` (`min-height: 620px`),
  `.media-shell`, `.item-text` (`max-height: 220px; overflow-y: auto` — длинный текст в маленьком окне со
  своей прокруткой);
- «Предложка»: `js/tabs.js` — `proposalCard`, `mediaTile` (текст режется на 220 символах посреди слова);
- календарь: `js/calendar-pool.js`, `js/calendar-phone.js` (текст режется на 90 символах — для статьи это
  половина заголовка);
- предпросмотр источника: `js/sources.js`; редактор поста: `js/editor.js` (`newsUrl`, выжимка `news_excerpt`).
- Подпись новости для публикации уже есть: `news_caption()` в `lib/news.php` (заголовок + до 3 предложений +
  «Источник: сайт — ссылка»). **Полный текст статьи в пост не публикуется** (авторское право) — это правило
  остаётся.
- Дизайн приложения — вариант **K «День / Эфир»** (`DESIGN_K_PROMPT.md`, уже применён в `css/app.css`):
  светлая «телемагазинная» дневная тема и тёмная «вечерний эфир», переключатель в шапке. Шрифты и цвета — только
  из существующих CSS-переменных, толстые обводки и жёсткие тени как у остальных карточек. **Не уводи в
  монохром и не придумывай новую палитру.**

## Общие правила

- **Не делай git commit.**
- **Перед первой записью в базу:** `cp data/posta.sqlite data/posta.sqlite.bak-articles`.
- **НЕ открывай сайт** (`http://localhost/...`) ни curl, ни headless Chrome: каждая загрузка без куки создаёт
  пользователя и запускает парсер, который нельзя остановить без sudo. Интерфейс проверяй на **стенде** —
  отдельной HTML-странице в каталоге `tools/stand/articles/` (см. часть D), открытой как `file://`.
- **Модели** (Ollama) в этой задаче почти не нужны. Вызывай их только там, где сказано, и с лимитом.
  Полный анализ — только умная модель, на быструю 2B ничего не переводи.
- **Запросы к vc.ru/dtf.ru:** только через `fetch_public` (как в `article_enrich`), `host_throttle` 1 запрос в
  секунду на хост, кэш через `kv_*` на `ARTICLE_CACHE_SECONDS`. В проверках — не больше 30 запросов за запуск.
- Не трогай файлы, которые не названы в задаче (в рабочем дереве много чужих незакоммиченных правок).
- Код в стиле проекта: короткие функции, комментарии по-русски одной строкой, без классов и фреймворков,
  DOM через `el()` из `js/core.js`. Тексты интерфейса — по-русски, понятные владельцу канала.

## Часть A. Чистые данные статьи (без моделей)

1. **`lib/osnova.php`**: `osnova_article(string $url): ?array` для хостов `vc.ru` и `dtf.ru` (список хостов —
   константа). id статьи — число из пути адреса. Ответ API приводится к общему виду **статьи**:
   ```
   ['title', 'lead', 'cover' => ['src', 'width', 'height'] | null, 'rubric', 'author', 'published',
    'words', 'minutes', 'counters' => ['views', 'comments', 'likes'],
    'blocks' => [['type' => 'p'|'h'|'list'|'quote'|'image'|'video'|'embed', ...]]]
   ```
   - `lead` — первый текстовый блок с `cover: true`, иначе первый абзац; не длиннее 400 символов.
   - `cover` — первая картинка из блока `media` с `cover: true`, иначе первая картинка статьи; **никогда**
     сгенерированная обложка `/cover/fb/`.
   - Текст блоков — **чистый текст** (теги убраны, `&nbsp;` и сущности раскодированы); ссылки внутри абзаца
     сохраняй списком `links` у блока (`[текст, адрес]`), адреса вида `api.vc.ru/.../redirect?to=` раскодируй в
     настоящий адрес. HTML из чужого сайта на клиент **не отдаётся никогда**.
   - Блок, который только из хэштегов (`#новости`), выбрасывается. `osnovaEmbed` → `embed` с заголовком и адресом.
   - `minutes` = слова / 180, не меньше 1.
   - Кэш `kv` по адресу, как в `article_enrich`; неудача — `null`, кэш неудачи час.
2. **Остальные сайты.** `article_parse()` тоже возвращает статью общего вида: сначала `application/ld+json`
   (`articleBody`, `headline`, `image`), иначе текущий `article_main_text` (абзацы → блоки `p`).
   `og:description` добавляй в `lead`, **только если это предложение**, а не список: функция
   `article_is_keyword_list()` — нет точки/!/? в конце и ≥ 3 запятых при средней длине куска < 6 слов (подбери
   на фикстуре vc.ru и на двух других сайтах из `NEWS_SITES`).
3. **Сгенерированные обложки.** `article_image()` и выбор картинки в `article_enrich` пропускают обложки-заглушки:
   `/cover/fb/` и `/cover/` на `api.vc.ru` / `api.dtf.ru` (константа-список шаблонов). Нет настоящей картинки —
   запись становится **текстовой статьёй** (без картинки), а не отбрасывается: проверь, как
   `news_enrich_posts` отбрасывает записи без картинки (`конвейер работает с картинками`), и пропускай статью,
   если тема допускает текстовые посты (`topics_accept_text` / формат темы — смотри как сделано в
   `TOPICS_SEARCH_PROMPT.md`, часть E). Тема требует картинку — отбрасывай, как сейчас.
4. **Что хранится в записи.** В записи (пул, история) — только маленький объект `article`:
   `title, lead, cover, rubric, author, minutes, words, site` (без `blocks`). `text` записи =
   `title + "\n" + lead` — **без** SEO-списка. Полные `blocks` живут только в кэше `kv` и отдаются по запросу.
   Счётчики (`counters`) → существующее поле `engagement` в том виде, в каком его ждёт `renderEngagement`.
   `article_text` для выжимки (`news_excerpt`) собирается из блоков `p/h/list/quote`, лимит прежний.
5. **Чтение статьи.** Действие `article_read` в `handlers/content.php` (только чтение, без побочных эффектов,
   без запуска парсера): по `url` записи из пула/истории пользователя → статья с `blocks` (из кэша, при
   необходимости одна загрузка с `host_throttle`). Чужие адреса (не из записей пользователя) — отказ.
6. **Старые записи.** CLI `php tools/cli.php articles-refresh [--limit=N]` (по умолчанию 40): записи
   `news: true` в пуле и истории без `article` → перезапросить, обновить `text`, `image` (если была заглушка),
   `article`, `engagement`. Без моделей. Печатает, сколько обновлено, сколько стало текстовыми.

**Проверка A:** `php -r` на фикстурах: `title`, `lead` без SEO-списка, `cover` = `leonardo.osnova.io/...`,
блоки длинной статьи по типам (сколько `p/h/list/quote/image`), `minutes`. Живой запуск
`articles-refresh --limit=10` — до/после по трём записям vc.ru (текст, картинка). `article_is_keyword_list` на
og:description vc.ru → true, на обычном анонсе lenta.ru/habr → false.

## Часть B. Общая структура карточки (вёрстка и JS, без моделей)

Сейчас карточка — медиа сверху, под ним текст в окошке с прокруткой, ниже простыня служебного: источник, дата,
проценты, метки, «Почему по теме», «Описание ИИ». Пересобери её из одинаковых блоков для всех видов:

```
┌ card-head ──────────────────────────────┐  площадка/сайт · рубрика · «2 ч назад» · «Свежак»
├ card-body (вид) ────────────────────────┤  media | text | article — см. ниже
├ card-chips ─────────────────────────────┤  метки ИИ, «По теме: 85%», активность у источника
├ card-ai (свёрнуто) ─────────────────────┤  «Почему ИИ выбрал ▾» → почему по теме + описание ИИ
└ card-actions ───────────────────────────┘  существующие кнопки (лайк/дизлайк/жалоба/🚀/открыть источник)
```

1. **Вид записи** — одна функция `cardKind(item)`: `article` (есть `item.article`), `text` (текстовый пост без
   медиа), `media` (остальное). Все места показа (главная карточка, предложка, календарь, предпросмотр
   источника) используют её, а не свои проверки.
2. **`media`**: как сейчас, но текст поста под медиа — не окошко с прокруткой, а 6 строк с
   «Показать полностью» (как `textPostBlock`; вынеси общий `clampText(text, lines)`).
3. **`text`**: как сейчас `textPostBlock`.
4. **`card-ai`** свёрнут по умолчанию (`<details>`), состояние запоминается (`localStorage` в try/catch).
   Для жалобы «ошибка подбора» объяснение ИИ должно оставаться доступным — проверь.
5. Убери `min-height: 620px` у карточки: высоту задаёт содержимое, медиа ограничено как сейчас. Проверь, что
   кнопки не прыгают при смене записи (зарезервируй высоту области медиа, а не всей карточки).
6. Ничего из существующего не теряется: все `id` элементов, на которые ссылается JS (`item-rating`,
   `item-source`, `item-date`, `item-engagement`, `item-source-link`, `item-relevance`, `item-tags`,
   `item-why-text`, `item-desc`, `item-translate`, `item-rocket`, кнопки голосов), остаются или переносятся
   осознанно — `grep` по каждому.

## Часть C. Карточка статьи

1. **`article` в главной карточке** (`card-body`):
   - сверху обложка 16:9, `object-fit: cover`, высота ограничена (около 45% ширины, не выше 300 px), клик —
     просмотрщик как у картинок; нет обложки — полоса-плашка цвета темы с названием сайта (не пустое место);
   - мета-строка: значок сайта (первая буква в кружке, цвет — из переменных), `vc.ru · Сервисы`, автор,
     `⏱ 3 мин`;
   - заголовок — шрифт заголовков темы K, 20–24 px, до 3 строк;
   - анонс — 16 px, до 4 строк;
   - кнопка **«Читать статью»** и строка «В пост пойдёт: заголовок, выжимка и ссылка на источник».
2. **Читалка.** «Читать статью» открывает панель поверх приложения (на телефоне — на весь экран, на ПК —
   колонка ~680 px по центру с затемнением), запрос `article_read`, пока грузится — скелет. Блоки:
   `h` — подзаголовок, `p` — абзац с ссылками (ссылки — `<a target=_blank rel=noopener>` из `links`, текст
   через `textContent`, **никакого `innerHTML` с данными сайта**), `list`, `quote` — с толстой линией слева,
   `image` — ленивая загрузка, подпись, клик — просмотрщик, `video` — превью-ссылка на источник,
   `embed` — мини-карточка ссылки. Внизу: «Открыть на vc.ru ↗» и «🚀 Запостить». Закрытие — ✕, Esc, свайп
   вниз на телефоне, «назад» браузера. Позиция прокрутки и фокус возвращаются к карточке.
3. **Предложка** (`proposalCard`): для статьи — обложка (или плашка), заголовок до 2 строк, `сайт · ⏱ N мин`,
   анонс до 3 строк; текст не режется посреди слова (общая функция `shortText(text, chars)` по границе слова).
4. **Календарь** (`calendar-pool`, `calendar-phone`): для статьи — заголовок вместо начала текста;
   в «телефоне» пост статьи выглядит как будущий пост в Telegram: картинка, **жирный заголовок**, выжимка,
   ссылка «Источник».
5. **Редактор** (`js/editor.js`): для статьи текст по умолчанию — `news_caption()` (уже есть на сервере, отдай
   его с записью как `caption_default` или используй существующий путь), картинка — настоящая обложка, кнопка
   выжимки ИИ — как сейчас. Без обложки — пост без медиа (как текстовый пост).
6. Обе темы (день/эфир), ширины 390 px и 1280 px. Длинный заголовок без пробелов (URL) не ломает вёрстку
   (`overflow-wrap: anywhere`). Нет горизонтальной прокрутки.
