# Задача: поиск постов встроенными поисками площадок — для подбора контента и для поиска источников

Ты работаешь в PHP-проекте `/var/www/html/posta` (Posta). Владелец хочет **максимально использовать встроенные поиски площадок**:
искать не только каналы (это уже есть), но и **посты** по теме, и брать их и в подбор контента, и как сигнал для новых источников.
Делать сразу, без долгих исследований: на каждую площадку — один-два пробных запроса, чтобы убедиться, что ответ разбирается, и дальше код.
Старые способы **не убирать** — поиск постов идёт параллельно.

## Что уже есть (прочитано 2026-10-24)

**Поиск источников** — `run_source_discovery_locked()` в `lib/discovery.php` (~стр. 630), поисковики — `lib/discovery_finders.php`:
- Telegram — поиск каналов через личный аккаунт (`tools/tg_user.py`, действия `search_channels`, `similar_channels`; PHP — `telegram_user_find_channels`, `lib/telegram.php`);
- VK — `groups.search` (`vk_search_groups`, `lib/sources.php`; `vk_api_request`, нужен OAuth — `vk_is_connected()`);
- YouTube — выдача «только каналы» и `ytsearch10:` через yt-dlp (`discovery_find_youtube`, `discovery_youtube_rows`);
- TikTok — авторы из поиска по видео (`tiktok_search_videos`, `lib/tiktok_search.php`);
- ОК — общие ленты разделов с фильтром по словам (`discovery_find_ok`).
Кандидат добавляется через замыкание `$add($platform, $id, $origin, $info, $depth, $front, $origin_kind)`; подписи `origin_kind` — `DISCOVERY_ORIGIN_LABELS` (`lib/discovery.php` ~стр. 565).
Запросы темы — `discovery_ai_plan($topic)['queries']`, слова темы — `discovery_topic_keywords($topic)`.

**Подбор контента** — `run_collector()` → `collect_posts_by_platform($db, $topic)` (`lib/parser.php`): посты источников собираются в
`$by[PLATFORM_*]`, дальше `build_candidate_queue` (дедупликация, рейтинги источников по `content_source_key`), быстрая оценка, полный анализ, пул.
Формат поста — как в `youtube_post()` (`lib/youtube.php`) и `telegram_posts_from_html`: `image, images, gallery, video, text, source, post_id, posted_at, url,
video_unavailable, engagement, views` (+ `video_via`/`video_page` для роликов, которые качает очередь yt-dlp) и `source_key`/`source_url` — как в `collect_catalog_source` (стр. ~108).
Уточнение запроса пользователя — `current_query()` (если не пусто — искать именно это).

Нигде сейчас **не используется поиск по постам**.

## Что сделать

### 1. Новый файл `lib/post_search.php` — адаптеры поиска постов

Одна функция на площадку, все с одинаковой формой: `post_search_<площадка>(string $query, int $limit): array` → посты в обычном формате выше,
с правильным `source_key` настоящего автора (канал/сообщество/канал YouTube/аккаунт TikTok) и полем `found_by = "поиск <площадка> «<запрос>»"`.
Ошибка/капча/пустой ответ → `[]` и строка в журнал (`cli_echo`), исключения наружу не пускать. Подключить файл в `bootstrap.php`.

Общее:
- **кэш** ответа на (площадка, запрос) — 1 час в `kv` (`post_search:<хэш>`), чтобы соседние проходы не долбили площадку;
- **бюджет** на проход: константы `POST_SEARCH_SECONDS` (60 с на весь поиск постов за проход), `POST_SEARCH_QUERIES` (3 запроса на площадку), `POST_SEARCH_LIMIT` (30 постов на запрос);
- посты старше `CONTENT_MAX_AGE_DAYS` выкидывать сразу.

Площадки и их возможности (по памяти — проверь одним запросом и поправь; итог запиши таблицей в комментарий в начале файла: что работает, операторы, лимиты):

| Площадка | Как искать посты | Приёмы |
|---|---|---|
| **YouTube** | yt-dlp `--flat-playlist -j` по адресу выдачи `https://www.youtube.com/results?search_query=…&sp=…` и по `https://www.youtube.com/hashtag/<тег>/shorts` | фильтры `sp`: за неделю `EgIIAw%3D%3D`, короче 4 мин `EgIYAQ%3D%3D`, сортировка по просмотрам `CAM%3D` (комбинации кодируются protobuf — если не выходит собрать, бери «за неделю»). Операторы в запросе: `"фраза"`, `-слово`, `#тег`. Шортсы → `youtube_post(..., true)` (у них будет `video_via`), обычные ролики — `youtube_post(..., false)` |
| **VK** | `newsfeed.search` (`q`, `count` до 200, `start_time` = сейчас − 7 дней, `extended=1` — имена сообществ) через `vk_api_request`; только при `vk_is_connected()` | `#хэштег` в `q`; брать только записи сообществ (`owner_id < 0`), с фото/видео во вложениях; разбор вложений — переиспользуй то, чем сейчас читаются стены VK в `lib/sources.php` |
| **Telegram** | новое действие `search_posts` в `tools/tg_user.py` + PHP-обёртка `telegram_user_search_posts()` в `lib/telegram.php` (по образцу `telegram_user_find_channels`). Внутри — `channels.SearchPostsRequest` (глобальный поиск публичных постов): по **хэштегу** бесплатно; по словам — только если `channels.CheckSearchPostsFloodRequest` говорит, что бесплатный запрос есть. Если в установленной версии Telethon этих запросов нет — обнови Telethon в окружении `tg_user.py`; не вышло — только хэштеги или пропуск с понятной строкой в журнале | **это личный аккаунт владельца**: не больше 5 поисков в час на аккаунт (счётчик в `kv`), на `FloodWait` — прекратить поиск Telegram до конца часа. Из найденного брать только каналы с публичным `username`; пост превращать в обычный пост Telegram (ссылка `https://t.me/<канал>/<номер>`, картинка — как в `telegram_posts_from_html`; проще всего — подтянуть страницу канала `fetch_telegram_channel_page` и взять из неё пост с этим номером) |
| **TikTok** | `lib/tiktok_search.php` уже разбирает страницу поиска видео — сделай вариант, который возвращает **видео** (а не только авторов): `url` = `https://www.tiktok.com/@автор/video/<id>`, `video_via = 'ytdlp'`, `video_page` = тот же адрес, обложка — `image` | хэштеги: страница `https://www.tiktok.com/tag/<тег>`, если отдаётся без JS |
| **Двач / 4chan** | поиска нет; каталог досок (JSON) уже читается — добавь фильтр тредов каталога по словам темы (см. п. 3) по **всем** доскам, а не только по выбранным для темы | — |
| **Pinterest, Tumblr** | один пробный запрос (`pinterest.com/search/pins/?q=`, `tumblr.com/tagged/<тег>`). Если без JS отдаётся разбираемый ответ — адаптер; если нет — пропусти и напиши в таблицу почему | — |

Регулярных выражений эти поиски не поддерживают — регулярки применяем **у себя** (п. 3).

### 2. Запросы

Функция `post_search_queries($topic): array` — короткие запросы: `current_query()` (если задано — первым и главным), слова темы `discovery_topic_keywords($topic)`,
первые запросы `discovery_ai_plan($topic)['queries']` (без стоп-слов «канал», «паблик» — `discovery_clean_query`), плюс хэштег-варианты (`#слово` без пробелов) для
Telegram/VK/YouTube/TikTok. Ротация между проходами, как `discovery_rotate` с номером прохода — чтобы каждый проход пробовал другие запросы.

### 3. Локальный фильтр по словам (вместо «регэкспов на площадке»)

`post_search_matches($topic, array $post): bool` — регулярка из основ слов темы и уточнения (основа = слово без 1–2 последних букв, как в `discovery_find_ok`;
регистронезависимо, `u`), по тексту поста. Применяй к результатам поиска постов и к каталогам Двача/4chan **до** быстрой оценки моделью.
Для тем, где смысл в картинке (мемы и т.п.: `topic_lookup()['format']`, см. `lib/topic_tree.php`), подпись может ничего не говорить — там фильтр не отбрасывает,
а только поднимает совпавшие посты выше в очереди.

### 4. Подбор контента

В `collect_posts_by_platform` после сбора постов источников — блок «поиск постов»: прогнать адаптеры в пределах бюджета, отфильтровать (п. 3),
добавить в `$by[<площадка>]`. Дальше всё как обычно (дедупликация, оценка, пул). В журнал — сводная строка по площадкам, как `platform_summary_line`:
`Поиск постов: YouTube 12 (запросов 3), VK 30, Telegram 5, TikTok 8 — после фильтра 41.`
Посты из заблокированных/отклонённых пользователем источников не брать (те же проверки, что для постов источников — найди их в `build_candidate_queue`).

### 5. Поиск источников

1. В `run_source_discovery_locked` — те же адаптеры по запросам плана; авторов найденных постов — в кандидаты через `$add` с новым `origin_kind = 'post_search'`
   (подпись в `DISCOVERY_ORIGIN_LABELS`: «нашёлся по постам»), `origin` — «посты по «запрос»». Автор с ≥2 найденными постами — в начало очереди (`$front = true`).
   Для YouTube кандидат — лента канала `https://www.youtube.com/feeds/videos.xml?channel_id=…` (как в `discovery_find_youtube`), для VK/Telegram/TikTok — как в существующих поисках.
2. **Из подбора контента:** если пост, найденный поиском (`found_by`), прошёл полный анализ и автор ещё не источник и не кандидат — добавить автора в предложения
   (`store_discovered_source` или тот механизм, которым discovery кладёт находки; `origin_kind = 'post_search'`, причина — «пост прошёл отбор: <ссылка>»). Это самый ценный сигнал.

### 6. Интерфейс

Минимум: в карточке поста пула и в карточке кандидата видно происхождение — `found_by` / подпись `post_search` выводятся там, где сейчас выводится источник/происхождение
(найди, где показывается `origin`/`DISCOVERY_ORIGIN_LABELS`). Никаких новых настроек.

## Ограничения

- **Не открывай приложение в headless-браузере с чистым профилем** — новая загрузка = новый пользователь + парсер, который не остановить.
- Живую базу `data/posta.sqlite` не меняй руками; опыты — на копии.
- Обычные веб-поисковики (DuckDuckGo, Bing) с этого сервера дают капчу — не используй их.
- Парсер работает под apache2 с его ограничениями (Node без JIT, Chrome без песочницы): если адаптеру нужен Chrome/Node — запуск как в существующем коде TikTok/yt-dlp.
- Пиши код в стиле соседнего: русские комментарии, короткие функции, константы рядом с другими.
- Не коммить.

## Проверка (быстро)

- `php -l` на изменённых PHP; `python3 -m py_compile tools/tg_user.py`.
- Маленький скрипт в scratch-папке: для одной темы (например «мемы про котов» и «бизнес») вызвать каждый адаптер с одним запросом и напечатать число постов и 2 примера (`url`, `source_key`, начало текста).
