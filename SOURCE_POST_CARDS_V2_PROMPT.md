# Задача: лента постов кандидата в источники — компактно, много постов на экране

Продолжение `SOURCE_POST_CARDS_PROMPT.md` (уже сделан: лента `#source-posts`, карточки `sourcePostCard`,
просмотрщик `js/post-viewer.js`, стенд `tools/stand/source-posts/`). **Просмотрщик постов и данные с сервера
не трогай** — они работают. Переделываем только **вид ленты в карточке кандидата**.

Пользователь: «карточка с карточками никуда не годится; уменьшить медиа в карточке поста, чтобы их много
поместилось на одном экране. Текст поста — в таком же объёме, информация по посту — остаётся».

## Что выяснено (2026-10-23, по коду — перепроверять не нужно)

- **Главная причина — ширина.** `#source-card-wrapper` использует ту же раскладку, что карточка мема
  `#item-card-wrapper` (`css/app.css`, ~строки 510–523):
  от 1240 px — `#source-tab { max-width: 770px }` и колонка карточки до 840 px; **от 1700 px — колонка карточки
  `minmax(0, 420px)`**. В 420 px сетка `.source-posts` (`repeat(auto-fill, minmax(220px, 1fr))`) даёт
  **одну колонку**, и каждый пост — это картинка 4:3 во всю ширину (`.sp-picture { aspect-ratio: 4 / 3 }`) или
  квадратный альбом (`.sp-album { aspect-ratio: 1 }`). На экране 1920×1080 видно полтора поста.
- Карточка поста вертикальная: медиа сверху, под ним текст (`.sp-text`: 4 строки, `shortText(post.text, 220)`;
  у текстового поста `.sp-text-big`: 8 строк, 600 символов, крупнее), внизу `.sp-meta` (дата, 👁, ❤, 💬,
  «альбом · N», ↗). **Объём текста и состав `.sp-meta` сохраняются как есть.**
- Сначала показывается `FEED_FIRST = 6` постов, остальное — по кнопке «Ещё N постов».
- Сведения об источнике (`.info`: имя, площадка, `#source-stats`, `#source-coverage`, «Почему показан»,
  описание) стоят **под** лентой — чтобы понять, что это за канал, надо прокрутить все посты.
- Видео в ленте играют сами без звука, пока видны (`observeFeedVideo`, до 3 сразу).
- Кнопки решения (`.controls`: 💩 ✋ 🤷 🗿, жалоба) — справа от карточки на широком экране, снизу на узком.
- Стенд: `php tools/stand/source-posts/make_stand.php` собирает `tools/stand/source-posts/index.html` из
  `index.html` приложения и фикстур `tools/fixtures/source_preview_*.json` (мемы, текстовый канал, RSS);
  `phone.html` — телефон через `iframe width=390`.

## Общие правила

- **Не делай git commit.**
- **НЕ открывай сайт** (`http://localhost/...`) ни curl, ни headless Chrome: каждая загрузка без куки создаёт
  пользователя и запускает парсер, который нельзя остановить без sudo. Только стенд по `file://`.
- Модели и запросы к площадкам не нужны.
- Трогай `css/app.css` (блок «Посты кандидата в источники» и правила `#source-card-wrapper` / `#source-tab`),
  `js/sources.js` (`sourcePostCard`, `postMediaBlock`, `showFeed`, `renderFeed`, константы ленты),
  разметку `#source-card-wrapper` в `index.html`, стенд. **Не меняй** раскладку `#item-card-wrapper` (карточка
  мема на «Подборе») — разведи правила для двух обёрток.
- Дизайн K «День / Эфир»: только существующие CSS-переменные, обе темы. Стиль проекта: короткие функции,
  комментарии по-русски одной строкой, DOM через `el()`, текст площадок — только `textContent`.

## Часть A. Карточка поста — строкой, медиа маленькое

`sourcePostCard` становится **горизонтальной строкой**:

```
┌────────┬──────────────────────────────────────────────┐
│ медиа  │ текст поста — те же 4 строки / 220 символов   │
│ 96×96  │ …                                             │
│  ▶ 0:35│ 3 ч назад · 👁 12,4K · ❤ 230 · альбом · 5   ↗ │
└────────┴──────────────────────────────────────────────┘
```

1. **Миниатюра** слева, квадрат **96 px** (телефон — **72 px**), `object-fit: cover`, скругление из переменных.
   - одна картинка — миниатюра;
   - **альбом** — первая картинка и плашка «1/5» в углу (мини-мозаику 2×2 в 96 px не делай — нечитаемо);
   - **видео** — постер, значок ▶ и длительность, если известна. **В ленте видео не играют** (на 96 px это
     только нагрузка): убери `observeFeedVideo`/очередь из ленты; если у видео нет постера — `<video
     preload="metadata">` без воспроизведения, чтобы показался первый кадр. Ролик, который докачивается, и
     внешнее видео — маленькая плашка в миниатюре («⏳», «↗») с тем же пояснением в `title`;
   - файл недоступен — серая миниатюра с «—», строка поста остаётся.
2. **Текст** справа: ровно как сейчас — `shortText(post.text, 220)`, 4 строки, 14 px. Текста нет — строка
   «Без текста» приглушённым цветом (чтобы строка не была пустой).
3. **`.sp-meta`** — без изменений по составу, одной строкой под текстом, лишнее переносится.
4. **Текстовый пост без медиа** — строка без миниатюры на всю ширину, текст — как сейчас (`.sp-text-big`:
   600 символов, 8 строк), но шрифт 15 px и подложка `--surface-2`, чтобы такие посты не были вдвое выше
   соседних без нужды.
5. Высота строки с медиа ≈ высоте миниатюры (96 px + отступы); текст не выходит за 4 строки.
6. Клик по строке — `openFeedPost(index)` (как сейчас), клик по ↗ — пост на площадке, Enter/пробел — открыть,
   фокус виден. Наведение (ПК) — лёгкая подсветка строки.

## Часть B. Лента и карточка кандидата

1. **Ширина.** Карточке кандидата нужна ширина, а не колонка мема. Для `#source-card-wrapper` (не для
   `#item-card-wrapper`): от 1240 px — карточка `minmax(0, 1fr)` + колонка кнопок 330 px, вкладка
   `#source-tab` до ~1240 px по центру (сейчас она 770 px); от 1700 px — то же, без колонки 420 px.
   Проверь, что фильтры площадок, «Источники темы», «Добавить источник» на вкладке не разъехались
   (у них свои `max-width`).
2. **Колонки ленты:** `grid-template-columns: repeat(auto-fill, minmax(380px, 1fr))` — 1 колонка до ~800 px
   ширины ленты, 2 на обычном ПК, 3 на очень широком. Зазор 8 px, у строки — тонкая обводка, тень меньше,
   чем у больших карточек (это примеры постов внутри карточки).
3. **Сколько показывать:** `FEED_FIRST = 12`; «Ещё N постов» — остальные.
4. **Сведения об источнике — наверх.** Шапка карточки над лентой, компактно: аватар/имя со ссылкой,
   площадка, `#source-score`, чипы `#source-stats` одной строкой; «Почему показан» и описание — одной-двумя
   строками с «ещё» (`<details>` или обрезка), `#source-coverage` — мелко под лентой, рядом с «Ещё N постов».
   Все `id`, на которые ссылается `renderSource`, сохрани (`grep` по каждому).
5. **Кнопки решения** на ПК остаются справа и **прилипают** (`position: sticky; top: …`), чтобы при прокрутке
   длинной ленты решать, не возвращаясь наверх. На телефоне — как сейчас.

## Часть C. Проверка на стенде (без сайта)

1. Пересобери стенд (`make_stand.php`), если менял `index.html`.
2. **Плотность — числом.** Добавь в стенд параметр `?measure=1`: после загрузки скрипт считает строки
   `.sp-card`, целиком видимые в окне без прокрутки страницы, и пишет число в `document.title`
   (снимай через `--dump-dom`, проверяй 3 раза). Требования для фикстуры мемов:
   | Окно | Видно постов целиком (не меньше) |
   |---|---|
   | 1920×1080 | 12 |
   | 1440×900 | 8 |
   | телефон 390×844 (`phone.html`) | 4 |
   Не выходит — уменьшай отступы и шапку, а **не** текст поста и не `.sp-meta`.
3. Снимки `google-chrome --headless=new --screenshot` — 1920×1080, 1440×900, телефон; фикстуры мемы / текст /
   RSS; обе темы. Посмотри снимки сам (Read) и поправь до 3 итераций: миниатюры одного размера, текст
   выровнен по верху, мета не налезает на ↗, длинные слова не ломают строку, нет горизонтальной прокрутки.
4. Регрессия: просмотрщик открывается кликом по строке на нужном посте, ← / → листают, Esc закрывает, фокус
   возвращается на строку; карточка мема на вкладке «Подбор» на 1280 и 1920 выглядит как раньше
   (снимок до/после — сделай «до» **перед** правкой CSS).
5. `node --check js/sources.js`.
