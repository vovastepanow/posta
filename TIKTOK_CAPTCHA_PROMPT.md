# Задача: капча TikTok — пользователь решает её в окне приложения («удалённый браузер»)

Ты работаешь в PHP-проекте `/var/www/html/posta` (Posta: подбирает контент по теме, источники ищет автоподбор).

## Зачем

Поиск аккаунтов TikTok (`lib/tiktok_search.php`, функция `tiktok_search_users`) открывает страницу поиска в headless Chrome с постоянным
профилем `data/chrome-tiktok`. TikTok иногда показывает капчу; после трёх пустых ответов подряд поиск встаёт на паузу на сутки
(`kv tiktok_search_pause`) и на вкладке «Источники» пользователь видит «TikTok не отдаёт поиск (похоже, капча)».

Капча привязана к сессии **того Chrome, который сидит на сервере**, поэтому открыть страницу TikTok у пользователя в браузере
бесполезно (и iframe закрыт заголовками). Единственный способ дать человеку решить её — **удалённый браузер в окне**:
сервер держит Chrome с этим же профилем, сайт показывает его скриншот, а клики и протягивание слайдера пользователь делает
на скриншоте, сайт пересылает их в Chrome. Пройденная капча остаётся в профиле (куки), следующие автоматические поиски идут без неё.

Решение владельца: **окно доступно любому пользователю** сайта (не только владельцу). Поэтому ниже — жёсткие меры безопасности: это
управляемый чужими людьми Chrome на сервере владельца.

## Что нужно сделать (по частям, A → E; не начинай следующую, пока проверка предыдущей не прошла)

### A. Chrome с отладочным портом и скрипт CDP: `tools/cdp.mjs`

Node 22 (`/usr/bin/node`) уже есть, в нём есть глобальный `WebSocket`; **библиотек не ставь** (puppeteer, ws и т. п. нельзя). Google Chrome 156 (`google-chrome`).

1. **Запуск Chrome** (функция PHP в новом файле `lib/tiktok_captcha.php`, подключи по образцу других `lib/*.php`, посмотри как
   подключается `lib/tiktok_search.php`): фоновый процесс, отвязанный от запроса (`proc_open` с `/dev/null`, как `ytdp_kick_worker` в
   `lib/ytdlp.php`), аргументы массивом, без оболочки:
   `env HOME=<data/chrome-tiktok-home> google-chrome --headless=new --disable-gpu --no-first-run --user-data-dir=<data/chrome-tiktok>
   --remote-debugging-port=<порт> --remote-debugging-address=127.0.0.1 --window-size=1100,760 --user-agent=<TIKTOK_SEARCH_UA> about:blank`.
   Порт — `TIKTOK_CAPTCHA_PORT = 9333` (константа в `lib/tiktok_captcha.php`). Профиль и HOME — те же, что у поиска (`lib/tiktok_search.php`).
   **Один Chrome на профиль:** перед запуском возьми ту же блокировку, что поиск (`try_lock(YTDLP_CACHE_DIR . '/.chrome-tiktok.lock')`),
   и держи её, пока идёт сессия капчи (блокировка снимается при остановке). Если поиск идёт — сессию не запускай, ответь «поиск ещё идёт, подождите минуту».
2. **`tools/cdp.mjs <команда> [json-аргументы]`** — одноразовый клиент: подключается к `http://127.0.0.1:<порт>/json` (найти вкладку типа `page`),
   открывает её `webSocketDebuggerUrl`, выполняет ОДНО действие, печатает JSON в stdout и выходит (таймаут 10 с на всё). Команды:
   - `goto <url>` — `Page.navigate` (только `https://www.tiktok.com/...`, иначе ошибка);
   - `shot` — `Page.captureScreenshot` формата jpeg quality 55, отдаёт `{ "jpeg": "<base64>", "w": 1100, "h": 760, "url": "<текущий адрес>" }`;
   - `mouse` — аргумент `{"events":[{"t":"move|down|up","x":..,"y":..}]}`: для каждого события `Input.dispatchMouseEvent`
     (`mouseMoved` / `mousePressed` с `button:'left', clickCount:1` / `mouseReleased`); координаты — в пикселях окна (0..w, 0..h), лишние отбрасывать;
     не больше 60 событий за вызов;
   - `state` — `Runtime.evaluate` с выражением, возвращающим `{url, captcha: <есть ли на странице капча>, results: <есть ли ссылки «/@имя»>}`.
     Капча — любой из: `document.querySelector('#captcha-verify-container, .captcha_verify_container, [id*=captcha], [class*=captcha]')`,
     iframe с `captcha` в src. Результаты — `document.querySelectorAll('a[href^="/@"]').length > 0`.
3. **Защита от ухода со страницы** (в `cdp.mjs` перед КАЖДЫМ действием, кроме `goto`): прочитать адрес вкладки; если хост не `tiktok.com`
   или не заканчивается на `.tiktok.com`, — `Page.navigate` обратно на `https://www.tiktok.com/search/user?q=<запрос сессии>` (запрос передаёт PHP
   в аргументе). Ещё при запуске включить `Network.setBlockedURLs` (через отдельную команду `harden`, вызывается один раз после старта) для
   `*://localhost/*`, `*://127.*/*`, `*://10.*/*`, `*://192.168.*/*`, `*://172.16.*/*`…`172.31.*`, `*://169.254.*/*`, `file://*`, `ftp://*`:
   клики по ссылкам не должны выводить Chrome во внутреннюю сеть сервера. **Клавиатуру в `cdp.mjs` НЕ реализуй вообще** (только мышь): капче не нужен ввод,
   а набор текста — риск.

Проверка части A: запусти Chrome из PHP-CLI (`php -r`), `node tools/cdp.mjs goto ...`, `shot` — в ответе есть base64 (сохрани в файл
в `/tmp/claude-.../scratchpad`-подобную папку, убедись, что это картинка), `state` отвечает. Потом останови Chrome. Сайт TikTok открывай один раз и
коротко: не гоняй его десятки раз (получим настоящую капчу и паузу).

### B. Сессия капчи на сервере (`lib/tiktok_captcha.php`)

Функции, все короткие, комментарии по-русски, в стиле проекта:
- `tiktok_captcha_start(string $query): array` — запуск Chrome (часть A), `harden`, `goto` страницы поиска `https://www.tiktok.com/search/user?q=<запрос>`,
  запись сессии в `kv` (`tiktok_captcha_session` = `{started_at, last_seen, query, owner: app_user_id()}`). Не больше **одной сессии на сервер**:
  если она есть и жива (`last_seen` не старше 60 с) — вернуть её же («капчу сейчас решает другой пользователь» — для чужого пользователя ошибка 409 с понятным русским текстом).
- `tiktok_captcha_shot(): array` — вызывает `cdp.mjs shot` и `state` через `proc_open` (массив аргументов, без оболочки, таймаут 12 с; возьми
  готовый `ytdlp_exec` из `lib/ytdlp.php`). Обновляет `last_seen`. Возвращает `{jpeg, w, h, captcha, results, url}`.
- `tiktok_captcha_input(array $events): void` — проверка и `cdp.mjs mouse` (максимум 60 событий, числа приведи к int и обрежь по окну).
- `tiktok_captcha_stop(string $reason): void` — убить Chrome (запомни pid в kv при старте и завершай `posix_kill`/`proc_terminate`, SIGTERM, потом SIGKILL через 3 с), снять блокировку, очистить kv.
- **Автостоп:** сессия живёт не дольше 5 минут (`TIKTOK_CAPTCHA_MAX_SECONDS = 300`) и закрывается, если 60 с не было запросов; любой вызов
  `tiktok_captcha_*` сначала вызывает проверку «просрочена ли сессия — остановить». Плюс `tools/cli.php tiktok-captcha-stop` (команда и строка в справке сверху файла) для ручной остановки.
- **Капча пройдена:** когда `state` показывает `captcha:false` и `results:true` — `kv_update('tiktok_search_pause', fn() => 0)`, `kv_update('tiktok_search_empty', fn() => 0)`,
  `tiktok_captcha_stop('решена')`, и ответ `{solved:true}`.

### C. API (`handlers/sources.php` + `index.php`)

Образец регистрации — как у `suggest_sources` / `adult_allow` (списки `GET` и `POST` в `index.php`, функция `handle_<действие>`). Все — для любого вошедшего/куки-пользователя, но:
- `tiktok_captcha_start` (POST, `{query?}`): запрос по умолчанию — тема пользователя через `current_topic()`; ответ `{ok, w, h}`;
- `tiktok_captcha_frame` (GET): `json_response(tiktok_captcha_shot())`; если сессии нет — `{closed:true}`;
- `tiktok_captcha_input` (POST, `{events:[…]}`): передать в `tiktok_captcha_input`; ответ `{ok:true}`;
- `tiktok_captcha_stop` (POST): `tiktok_captcha_stop('закрыто пользователем')`.
Только сессия самого пользователя: кто не начинал сессию (`owner` в kv) — получает 403. **Ограничение частоты**: кадр не чаще 4 раз в секунду на пользователя,
ввод — не чаще 10 запросов в секунду (простой счётчик во временном файле или в `kv`, как сделано в других местах проекта; найди готовое:
`grep -rn "rate\|throttle" lib/core.php lib/auth.php`).
В `handle_suggest_sources` в двух местах, где сейчас говорится про паузу и «капча» (поиск `tiktok_search_pause` и `tiktok_search_error`),
добавь в ответ `'action' => 'tiktok_captcha'` (вместо `add_link`, а `add_link` оставь вторым вариантом кнопки) — фронтенд покажет кнопку «Решить капчу».

### D. Окно в интерфейсе (`index.html`, `js/sources.js`, `css/app.css`)

- Кнопка «Решить капчу TikTok» в блоке пустого состояния (`#source-empty`, рядом с «Добавить ссылку» и «Проверить ещё раз»; посмотри `setEmptyActions`
  и как показываются `source-empty-discover` / `source-empty-add`). Кнопка видна при `action === 'tiktok_captcha'`.
- Модальное окно в стиле приложения (образец — `.dtp-overlay`/`.dtp-window` из `js/editor.js`/`css/app.css`, жёсткие рамки, `--accent`): заголовок
  «Капча TikTok», пояснение «Это окно показывает браузер сервера. Пройдите проверку: двигайте ползунок или кликайте по картинке, как на самом сайте», `<img>` скриншота,
  строка статуса, кнопка «Закрыть». Картинка масштабируется под ширину окна (макс. 1100 px, `max-width:100%`, `touch-action:none`, `user-select:none`, курсор `crosshair`).
- Кадры: пока окно открыто — запрос `tiktok_captcha_frame` каждые 450 мс (следующий запрос — только после ответа предыдущего, без накопления), картинка
  `src = 'data:image/jpeg;base64,' + jpeg`. Если `solved` — «Готово!», закрыть окно через секунду, вызвать `loadNextSource()` (поиск повторится сам).
  Если `closed` или ошибка — сообщение и закрытие. Опрос прекращается при закрытии окна, при уходе со вкладки и `pagehide` (отправь `tiktok_captcha_stop`
  через `fetch(..., {keepalive:true})` как в `core.js` для `tab_close`).
- Ввод: `pointerdown/pointermove/pointerup` на `<img>` с `setPointerCapture`; координаты переводи в пиксели окна Chrome: `x = (clientX - rect.left) * (w / rect.width)`
  (`w`, `h` приходят в кадре). События копятся и отправляются пачкой раз в 60 мс (`tiktok_captcha_input`, не больше 60 событий в пачке, `move` без нажатой кнопки не посылать,
  у `move` при нажатой — прореживать до 1 на 16 мс). Тач работает так же (pointer events).
- Всё текстовое — только через `textContent`/`el()`, никакого `innerHTML` с данными сервера. Тёмная и светлая тема — только переменные темы. На телефоне окно на весь экран.
- Подсказка пользователю прямо в окне: «Окно закроется само через 5 минут».

### E. Проверка и отчёт

- `php -l` для всех изменённых PHP, `node --check tools/cdp.mjs js/sources.js`.
- Тест `tools/test_tiktok_captcha.php` без сети: чистые функции (обрезка координат, лимит событий, проверка хоста для защиты), просрочка сессии по kv
  (подставь `started_at` в прошлом → `tiktok_captcha_stop` вызывается), разбор ответа `state`. Образец оформления — `tools/test_news_4chan.php`.
- **Живая проверка:** один раз запусти сессию, получи кадр, убедись, что координаты клика попадают в нужное место (кликни по полю поиска TikTok и
  сделай второй кадр), и остановись. Если в кадре **реальная капча** — сообщи в отчёте и пришли путь к сохранённому кадру, ничего не пытайся решать сам.
- **Не запускай парсер и модели. Не открывай сайт Posta в безголовом браузере и не дёргай `curl` без куки** (каждый заход без куки создаёт нового пользователя
  и может запустить фоновый парсер). Для проверки интерфейса используй изолированную страницу, как сделано для просмотрщика в этой сессии:
  статичный `http.server` из своей папки в `scratchpad` с `index.html` и симлинками на `js/` и `css/` (PHP при этом не работает — API подменяй).
- Не делай `git commit`. Не трогай файлы, не названные в задаче (минимальные правки допустимы — перечисли их в отчёте).

## Что НЕ делать

- Не пытайся решать капчу автоматически (никаких моделей, сервисов распознавания, подделки поведения): решает только человек.
- Не добавляй ввод с клавиатуры, прокрутку колесом и произвольную навигацию из интерфейса.
- Не ставь пакеты (npm/pip). Не меняй `lib/tiktok_search.php`, кроме явно нужного (если ему мешает общая блокировка — опиши в отчёте, а не переписывай).
- Не снимай защиту «только tiktok.com» и блокировку внутренних адресов — окно доступно любому пользователю сайта.
