# Календарь: вертикальный сдвиг по часам + перетаскивание из Предложки

Две фичи для вкладки «Календарь» (десктоп, вид «сетка»). Телефон (`calendar-phone.js`) и вид «Список» не трогаем.

Файлы: `js/calendar.js`, `js/calendar-drag.js`, `js/calendar-pool.js`, `js/calendar-model.js`, `css/app.css`.
Стиль кода — как в этих файлах: ES-модули, `el()` из `core.js`, короткие русские комментарии `/** … */` над функциями, без новых библиотек.

---

## Как сейчас устроено (прочитай перед правкой)

- `computeGeo()` в `calendar.js` берёт окно часов `[sh, eh]` из `visibleHours()` → `hourWindow()` (`calendar-model.js`): по постам/слотам, минимум 8 часов, или `[0, 24]` при «Круглых сутках» / зуме ≤ 1 дня. Всё окно **вписывается** в высоту `.cal-body` (`ppm = height / ((eh - sh) * 60)`), вертикальной прокрутки нет.
- `state.frozenHours` замораживает окно на время жеста зума (`aimZoom`), сбрасывается в `settleZoom`.
- `bindGestures()` в `calendar-drag.js` — фон сетки: сдвиг по дням мышью/пальцем (`pan`, только `dx`) и щипок. Карточки, `.cal-free`, `.cal-stack`, кнопки исключены.
- `startDrag()` в `calendar-drag.js` — перенос карточки поста. Цель считается в `update(d)`: день — `host.columnAt(x, y)`, время — `d.origin + dy / ppm`, затем `snapTarget()`; отметки `showMarks`, плашка `showGhost`, линия `showTrail`, автосдвиг у края `edge`. На отпускании — `host.commit(post, at, copy)` → `commitDrop`.
- Колонка «Предложка» слева — `renderPoolColumn()` в `calendar-pool.js`: элементы `button.cal-pool-item`, по клику `ctx.draft(item)` (черновик в панели). В колонке уже написано «Перетащите пост в слот…», но перетаскивания **нет**.
- Постановка поста из Предложки на конкретное время уже есть на бэкенде: `api('calendar_fill_apply', { body: { items: [{ slot_at, channel, image, text }] } })` — так работает «Заполнить дыры». Отмена 30 с — `undoable()` в `calendar-pool.js` (сейчас не экспортирована).
- Внимание: ресурсы тяжёлые. **Не открывай приложение headless-браузером** (каждая новая загрузка создаёт пользователя и запускает парсер) — проверяй логику через чистые функции в `calendar-model.js` и `node --check`.

## Фича 1. Сдвиг сетки по часам мышью (вертикально)

Сейчас тянуть фон можно только влево-вправо. Нужно: тянешь фон вверх-вниз — окно часов едет (как прокрутка), т.е. видно 06–14 вместо 08–16 и т.п.

### Модель (`calendar-model.js`)
1. Добавь чистую функцию, например:
   ```js
   /** Окно часов, сдвинутое на offsetH часов и зажатое в [0, 24] с сохранением длины. */
   export function shiftHourWindow([sh, eh], offsetH) { … }
   ```
   Длина `eh - sh` сохраняется, края не выходят за 0 и 24. Дробные часы допустимы (плавный сдвиг), округлять не надо.

### Состояние (`calendar.js`)
2. Новое поле `state.hourShift = 0` (часы, дробное). В `computeGeo()` после получения `[sh, eh]` (и из `frozenHours`, и из `visibleHours`) применяй `shiftHourWindow([sh, eh], state.hourShift)`. Сохраняй фактический сдвиг после зажатия (если упёрлись в 0/24 — `hourShift` подрезается, чтобы не копился «мёртвый» запас).
3. При «Круглых сутках» на весь экран (окно уже `[0, 24]`) сдвиг ничего не делает — это нормально, курсор не меняй.
4. Сбрасывай `hourShift = 0` при: переключении «Круглые сутки», кнопке «Сегодня», пресетах День/Неделя/Месяц. При зуме колесом — **не** сбрасывай (зум горизонтальный).
5. Пока идёт вертикальный сдвиг, окно часов не должно «дышать» от пересчёта по постам: используй ту же идею, что `frozenHours` (заморозь базовое окно на время жеста, отпусти на `pointerup`).

### Жест (`calendar-drag.js`, `bindGestures`)
6. В объекте `pan` храни ещё `y0` и стартовый `hourShift` (через новый `host.hourShift()`). На `pointermove`:
   - определяй ось один раз, когда сдвиг превысил `PAN_START_PX`: если `|dy| > |dx|` — вертикальный режим, иначе горизонтальный (как сейчас). Ось не меняется до отпускания — без диагональной «каши».
   - вертикальный режим: `host.panHours(startShift, dy)` → в `calendar.js`: `state.hourShift = startShift - dy / (geo.ppm * 60)` (тянешь вниз — видны более ранние часы, как в Google Calendar), затем `scheduleRender()`.
   - `host.markMoved()` как у горизонтального, чтобы отпускание не считалось кликом.
7. Палец (`pointerType === 'touch'`) — то же самое (на десктопе с тачскрином). На телефоне сетки нет, ничего не ломается.
8. Курсор: при наведении на пустой фон `.cal-days` — `cursor: grab`, во время сдвига — `grabbing` (класс на `body`/`.cal-body`, например `is-panning`). Проверь, что карточкам курсор не перебили.

### Колесо (по желанию, маленькое)
9. В `onWheel` сейчас обычное колесо = зум, Shift = сдвиг по дням. Добавь: **Alt + колесо** = сдвиг по часам (`state.hourShift += dy / (ppm*60)`). Обновить строку подсказки в `showHint()` (десктопный список) и `.cal-wheel-hint` в `index.html`: «тяните фон вверх-вниз — другие часы».

### Перенос карточки
10. Во время `startDrag` у верхнего/нижнего края `.cal-body` (по аналогии с `edge()` для левого/правого) окно часов должно само ехать: `EDGE_PX` от верха/низа → `host.panHours` на 0.5 ч раз в `EDGE_STEP_MS`, потом `host.flush(); update(d)`. Без этого нельзя перетащить пост с 10:00 на 22:00, если 22:00 за окном.
    - Важно: `update(d)` считает время как `d.origin + (clientY - d.y0) / ppm`. При сдвиге окна это уже неверно. Переделай расчёт времени на **абсолютный**: время = `dayMs + (sh*60 + (clientY - colTop) / ppm) минут`, где `colTop` — верх `.cal-col` под указателем (`hit.area.getBoundingClientRect().top`). Если колонки под указателем нет — оставь старый относительный расчёт как запасной. Проверь, что плашка «сдвиг на …» (`shiftLabel`) и отметки остаются правильными.

## Фича 2. Перетаскивание поста из Предложки на время/дату

### Что видит пользователь
- Хватает карточку в левой колонке «Предложка» мышью → после сдвига на 5 px появляется та же «летящая» карточка, плашка времени и отметки 10 мин / часов / слотов, что при переносе поста в сетке.
- Над колонкой дня — плашка «Пт 23 окт, 14:10 · прилипло к слоту» и метка в колонке; вне сетки — плашка «Отпустите на день и время».
- Отпустил на сетке → пост ставится в очередь на это время в канал. Статус: «Пост из Предложки запланирован на …» + кнопка «Отменить (30 с)». Календарь перезагружается, пост исчезает из колонки Предложки.
- Отпустил мимо / Esc → ничего не происходит, «Перенос отменён».
- Простой клик (без сдвига) — как сейчас, открывает черновик.

### Канал
- Если включён (`!state.disabled.has(id)`) ровно один канал — его.
- Если несколько — канал по **дорожке/цвету под курсором**, если сетка разбита по каналам (посмотри, как `laneOf()`/`layoutDay` раскладывают каналы; если колонка дня не делится по каналам — берём первый включённый, как `openDraft`). В плашке при переносе показывай название канала цветной точкой (`laneOf(id).color`), чтобы было видно, куда упадёт.
- Свободные слоты для прилипания — `host.freeSlots(channelId, dayMs)` этого канала.

### Реализация
1. **`calendar-drag.js`**: не дублируй код. Обобщи `startDrag` так, чтобы он принимал «источник»:
   - сейчас: `{ post, card }` с `post.at` (origin);
   - новое: `startPoolDrag(event, item, node, host)` → внутри тот же `drag`, но `d.kind = 'pool'`, `d.item = item`, `d.origin = null`.
   Для `kind === 'pool'`:
   - статус-фильтр `['queued','failed']` не применяется;
   - нет «было: hh:mm» (`d.was`), нет линии-траектории (`showTrail`) — или линия от карточки в колонке, если просто сделать;
   - `shiftLabel(origin, at)` в плашке заменить на крупное время «14:10» (origin нет);
   - копия с Ctrl/Alt не имеет смысла — игнорировать;
   - время считается только абсолютным способом (см. п.10 фичи 1); если указатель не над колонкой дня — `d.target = null`;
   - автосдвиг у краёв (`edge`) работает так же: у **левого** края сетки — но колонка Предложки сама слева, поэтому зона левого края — это левые 48 px `.cal-body`, а не колонка.
   - отпускание: проверки «не раньше чем через минуту» те же; затем `await host.commitPool(item, target.at, channelId)`.
2. **`calendar-pool.js`**:
   - в `renderPoolColumn` у `button.cal-pool-item` добавь `pointerdown` → `ctx.startDrag?.(event, item, button)`; `click` должен игнорироваться, если был перенос (`ctx.justDropped?.()` — та же идея, что `justDropped()` в `calendar.js`).
   - картинке внутри поставь `draggable = false`, кнопке `touch-action: none` только на десктопе, чтобы браузер не начинал свой нативный drag картинки / прокрутку списка мышью.
   - экспортируй `undoable` (или сделай маленькую экспортируемую обёртку) для отмены 30 с.
   - удали `pickSlot`-ветку только если она мешает; телефон не трогаем.
3. **`calendar.js`**:
   - в `poolContext()` добавь `startDrag: (event, item, node) => startPoolDrag(event, item, node, host)` и `justDropped`.
   - `host.commitPool(item, at, channelId)`: 
     ```js
     const result = await api('calendar_fill_apply', { body: { items: [{ slot_at: unix(at), channel: channelId, image: item.image, text: item.text || '' }] } });
     ```
     Ошибки — из `result.errors[0].error` в `setStatus(…, true)`. Успех — статус + отмена (`undoable(result.posted, …)`), `loadCalendar()` и перерисовка колонки Предложки (`renderPoolColumn`).
   - Пока ждём ответ сервера — оптимистично нарисуй призрачную карточку на месте (можно через уже существующий `state.ghosts`, как план «Заполнить дыры»), убери после `loadCalendar()`.
   - `bindGestures` висит на `#cal-body` (`calendar.js:1010`), колонка Предложки — соседний `aside`, поэтому её `pointerdown` фон не перехватит. Но `pointermove` у `bindGestures` слушается на `document` — проверь, что во время переноса из Предложки он молчит (`host.isDragging()` должен возвращать true и для `kind === 'pool'`).
4. **Видео и тексты из Предложки.** `calendar_fill_apply` (`lib/calendar_fill.php`) готовит медиа как `[['src' => image, 'name' => 'фото']]`. Проверь на реальном элементе Предложки с `format === 'video'` (через `php tools/cli.php` или прямой вызов функции, **не** через браузер), уходит ли видео. Если нет — для `video` при отпускании не ставь сразу, а открой редактор с этим временем: `postItemToTelegram(item, { scheduledTs: unix(at), channel: channelId, onDone: loadCalendar })` (так уже делает `openDraft`). Для `format === 'text'` без картинки — то же, если `calendar_fill_apply` падает на пустом `image`. Опиши в отчёте, что выбрал.
5. **CSS**: `.cal-pool-item` — `cursor: grab`; во время переноса исходный элемент полупрозрачный (`.is-dragging` уже есть для карточек — переиспользуй). Летящая карточка из Предложки шире/уже карточки сетки — задай ей ширину как у карточки в колонке дня текущего масштаба (возьми из `CARD_H`/ширины дорожки) или фиксированные 180 px, чтобы не закрывала полэкрана.
6. Обнови текст в колонке: «Перетащите пост на нужный день и время или заполните все дыры одной кнопкой.» И строку в десктопной подсказке `showHint()`: «Перетащите пост из Предложки на день и время — он встанет в очередь».
