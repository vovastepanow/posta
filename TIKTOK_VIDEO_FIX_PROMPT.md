# Задача: вместо видео TikTok / YouTube Shorts везде показываются картинки-обложки

Ты работаешь в PHP-проекте `/var/www/html/posta`. Владелец: «по-прежнему открываются картинки вместо видео из TikTok
в предложке источников и, наверное, повсеместно».


## Что выяснено (2026-10-23, перепроверять не нужно)

1. **Так задумано:** пост TikTok и YouTube Shorts приходит **только с обложкой**: `tiktok_post_from_item`
   (`lib/tiktok.php:57`) отдаёт `'video' => ''`, `'video_via' => 'ytdlp'`, `'video_page' => https://www.tiktok.com/@…/video/…`
   (адреса файлов TikTok протухают и требуют заголовков, прямую ссылку отдавать нельзя). Ролик скачивается **потом**
   очередью `ytdlp_queue` (`lib/ytdlp.php`: `ytdlp_enqueue` → воркер `tools/ytdlp_worker.php` → `ytdlp_run_job` →
   `ytdlp_download` → `ytdlp_h264` → `cache_downloaded_video` → `ytdlp_attach`). Скачивание само по себе работает
   (≈20 с на ролик).
2. **Превью нигде не просит скачать ролик.** Мозаика кандидата на вкладке «Источники» (`build_source_preview` →
   `tiktok_preview_posts`, `js/sources.js::mosaicItems`), превью источников темы, сетка «Лучшие посты», окно
   просмотра (`js/viewer.js`) — у TikTok/Shorts там всегда обложка. Для **больших видео Telegram** механизм «скачать
   по кнопке» уже есть: `handle_telegram_video_fetch` / `handle_telegram_video_status` (`handlers/sources.php:436`),
   состояние в `kv` `tgu_video:<хэш>` (`tgu_preview_status/save`, `tgu_preview_key` = `preview:<хэш>`,
   `tgu_preview_keep_names` защищает файл от очистки сутки), кнопка в `js/viewer.js:110` (`item.tguPost`).
   TikTok и Shorts к нему **не подключены**.
3. **Не все пути в пул ставят ролик в очередь.** `ytdlp_enqueue` вызывается только в `add_item_to_pool_safely`
   (`lib/parser.php:298`) и в импорте X (`lib/x_posts.php:103`). `own_add_to_pool` (`lib/own_content.php:33`) — через
   него идут «Лучшие посты» (забрать в подборку), «Зеркало», импорт — **ролик не ставит**: такие записи остаются
   обложкой навсегда.
4. **Воркер очереди умирает после первой неудачи.** `tools/ytdlp_worker.php` берёт одну задачу и перезапускает себя,
   только если `ytdlp_next_job()` вернула задачу **прямо сейчас**. Неудачная задача ждёт повтора 60 с (`next_at`) →
   воркер выходит → **никто его больше не запускает** (запуск — только из `ytdlp_enqueue`). Сейчас в `kv: ytdlp_queue`
   висит задача `{"page":"https://t.me/belaya_kaska/39420","via":null,"tries":2,"next_at":<прошло>}` — воркер не
   работает, задача не повторяется и не снимается. Плюс `via: null` (старый баг, уже исправлен в `ytdlp_enqueue`):
   `($job['via'] ?? 'ytdlp')` превращает `null` в `'ytdlp'` и пытается качать пост Telegram через yt-dlp.
5. **Основная карточка «Подбор»** (`js/content.js`) не знает про «видео ещё качается»: показывает обложку как обычную
   картинку и сама не обновляется, когда ролик готов. Пометка «Видео загружается…» есть только на плитке «Предложки»
   (`js/tabs.js:55`), но и она без самообновления.
6. Сейчас в пуле нет TikTok-записей — проблема видна в первую очередь в превью кандидатов, но после частей A–B она
   проявится и в «Подборе», если их не сделать.

## Общие правила

- **Не делай git commit.** Перед записью в базу: `cp data/posta.sqlite data/posta.sqlite.bak-ttvideo`.
- **НЕ открывай сайт Posta** (`http://localhost/...`) ни curl, ни браузером: каждая загрузка без куки создаёт
  пользователя и запускает парсер. Фронт проверяй на стенде (как в `SOURCE_PREVIEW_PROMPT.md`, «Как проверять
  фронтенд безопасно»: Python-заглушка API с фикстурами из CLI). **Картинки и видео стенда — сгенерированные**
  (`ffmpeg -f lavfi`), не из кэша медиа проекта (там бывает 18+).
- **`node --check` недостаточно** — каждую правку JS проверяй загрузкой стенда в Chrome без ошибок `CONSOLE`.
- Воркер и yt-dlp работают в окружении Apache (`MemoryDenyWriteExecute`, `RestrictNamespaces`). Проверки со
  скачиванием запускай так же: `systemd-run --user --quiet --pipe --wait -p MemoryDenyWriteExecute=yes
  -p RestrictNamespaces=yes <команда>`.
- Сеть: не больше 3 скачиваний TikTok за всю проверку; **поиск аккаунтов TikTok через Chrome не запускай** (капча).
- Модели (Ollama) не нужны — не вызывай. Парсер не запускай.
- Не отдавай прямые адреса файлов TikTok — только скачанные в кэш медиа. Лимиты длительности (`TIKTOK_MAX_SECONDS`)
  и размера (`TELEGRAM_UPLOAD_MAX_BYTES`) не снимай. Блокировку «одно скачивание на сервер» не обходи.
- Стиль проекта: короткие функции, комментарии по-русски одной строкой; тексты источников — только `textContent`.

Части по порядку: A → B → C → D → E. После каждой — проверка. Не начинай следующую, пока не прошла предыдущая.

## Часть A. Очередь роликов не должна умирать

1. **Воркер дожидается ближних задач:** в `tools/ytdlp_worker.php` после задачи — если в очереди есть задача с
   `next_at` в ближайшие 90 с, подождать её (`sleep` до `next_at`, в пределах общего времени жизни запуска) и взять;
   выходя, если в очереди остались задачи — оставь «будильник»: `ytdlp_kick_worker()` при следующем удобном случае
   (пункт 2), а не только при `ytdlp_enqueue`.
2. **Будить воркер не только при постановке:** вызов `ytdlp_kick_worker()` (он дешёвый: проверяет блокировку) —
   в начале каждого прохода парсера (найди точку в `run_collector`), в `tools/publisher.php` (он запускается регулярно),
   и в обработчиках опроса статуса видео (часть C, D). Если в очереди есть просроченные задачи, а `.worker.lock`
   свободен — значит воркер мёртв; запусти.
3. **`via`:** при чтении задачи `via` берётся из адреса, если поле пустое: `t.me/…` → `tgu`, иначе `ytdlp`
   (функция `ytdlp_job_via($job)`), а `ytdlp_enqueue` не принимает `null`. Висящую задачу `belaya_kaska/39420`
   обработает исправленный воркер (или честно снимет после попыток) — проверь и напиши в отчёте, чем кончилось.
4. **Видно, что происходит:** `ytdlp_job_failed` — строка в `error_log` (`ytdlp: <страница>: <причина>`);
   `php tools/cli.php ytdlp-queue [--clear-failed]` (добавь в справку в начале `tools/cli.php`): очередь (uid[:8],
   страница, via, попытки, когда следующая), снятие исчерпавших попытки.

**Проверка:** в ограниченном окружении — задача, которая падает (несуществующий ролик), повторяется через 60 с **без**
новой постановки и снимается после `YTDLP_TRIES`; задача, поставленная во время ожидания, выполняется тем же
воркером; `ytdlp-queue` печатает очередь.

## Часть B. Любая запись с роликом в пуле ставит его в очередь

1. Одна функция `pool_items_enqueue_videos(array $items, $uid)`: для записей с `video_via` ∈ {`ytdlp`, `tgu`} и пустым
   `video` — `ytdlp_enqueue(..., content_image_key($item), $item['video_page'], $item['video_via'])`.
2. Вызывай её **везде, где записи попадают в пул**: `add_item_to_pool_safely` (замени текущий вызов), `own_add_to_pool`,
   импорт X (замени свой цикл), и проверь остальные места: `grep -rn "pool_update(" lib handlers tools` — все,
   что добавляют записи («Лучшие посты», «Зеркало», «Свой контент», календарь-автозаполнение, если есть).
3. Shorts: убедись, что у постов YouTube Shorts (`lib/youtube.php`, `lib/rss.php`) те же поля
   (`video_via='ytdlp'`, `video_page`) и что `ytdlp_format_for()` выбирает для них H.264.

**Проверка:** тестовый пользователь, `own_add_to_pool` с TikTok-записью (из `tiktok_fetch_posts` одного аккаунта или
фикстуры) → задача в очереди; после воркера у записи `video` = адрес кэша, кодек `h264`. Удали тестовые данные.

## Часть C. Превью: ролики TikTok и Shorts по кнопке и первые — сами

1. **Обобщи механизм «скачать по кнопке»** с Telegram на TikTok и Shorts, не делая второй: `handle_video_fetch` /
   `handle_video_status` (новые действия в `POST`/`GET` `index.php`; старые `telegram_video_fetch/status` оставь
   как обёртки). Принимаются только:
   `https://t.me/<канал>/<номер>` (via `tgu`, нужен аккаунт — как сейчас),
   `https://www.tiktok.com/@<имя>/video/<5–25 цифр>` (имя — `is_valid_tiktok_user`, via `ytdlp`),
   `https://www.youtube.com/shorts/<11 символов>` (via `ytdlp`).
   Состояние, лимит задач на пользователя (подними до 3 для TikTok/Shorts), защита файла от очистки сутки — общие
   (`tgu_preview_*` переименуй в `video_preview_*`, поправив все вызовы).
2. **Посты превью получают `video_page`:** `tiktok_preview_posts`, превью Shorts, «Лучшие посты» — в ответе у таких
   постов `video_page`, `video_via`, а если файл уже скачан (состояние `done`) — сразу `video` = адрес кэша.
3. **Первые 3 ролика кандидата — сами:** когда собирается превью кандидата TikTok/Shorts (`build_source_preview`),
   поставь в очередь первые 3 ролика (если ещё нет состояния `done`/`queued`); у этих постов `video_pending: true`.
4. **Окно просмотра** (`js/viewer.js`): обобщи `item.tguPost` → `item.videoPage` (для Telegram — как было). Для
   TikTok/Shorts без видео — обложка с кнопкой «Загрузить видео» (как для больших видео Telegram) и «Видео
   загружается…» с опросом статуса; готово — элемент сменяется на `<video>` с тем же индексом.

## Часть D. Фронт: «Видео загружается…» и самообновление везде

1. Общий модуль `js/video-pending.js`: `watchVideo({page | image}, onReady, onFail)` — опрос раз в 3–4 с, не дольше
   5 минут, не больше 3 одновременных опросов на страницу, остановка при уходе с вкладки.
2. **Мозаика кандидата** (`js/sources.js`, `renderMosaic`): тайл с `video_pending` — обложка, значок видео и
   «Видео загружается…»; готово — `<video autoplay muted loop playsinline>` как у готовых видео (используй
   существующую очередь «не больше 3 качаются сразу»). Остальные TikTok-тайлы — значок видео; клик → окно просмотра
   с кнопкой «Загрузить видео».
3. **Карточка «Подбор»** (`js/content.js`, `renderCard`/`renderSlide`): запись с `video_via` ∈ {`ytdlp`,`tgu`} без
   `video` — оверлей «Видео загружается…» со спиннером (стиль — как `.proposal-pending`). Новое лёгкое действие
   `get_item_video` (GET `image`) отдаёт `{video, video_local, display_video, video_unavailable}` из пула **без**
   предпроверок публикации (они ходят в сеть). Появилось `video` — карточка перерисовывается на том же месте;
   `video_unavailable` — запись уходит из показа (`pool_without_lost_video`) и показывается следующая.
   Кнопку «Запостить» для такой записи уже блокирует сервер — убедись, что подсказка понятна: «Видео ещё загружается,
   попробуйте через минуту».
4. **«Предложка»** (`js/tabs.js:55`) и **«Лучшие посты»** — то же самообновление через `video-pending.js`.
