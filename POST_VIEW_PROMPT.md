# Задача: единый просмотрщик постов Posta (+ цветные эмодзи)

Ты работаешь в проекте `/var/www/html/posta` (Posta). Нужен **один** просмотрщик поста, который открывается из любого места приложения и
одинаково хорошо показывает что угодно: от поста без текста с 20 картинками до длинной статьи с vc.ru. Дизайн — сплав двух вещей, которые
владельцу уже нравятся: **просмотрщик медиа** (`js/viewer.js`: тёмная сцена, окно облегает медиа, колесо — зум) и **карточка поста**
(главная карточка `js/content.js` + `js/card.js`: источник, дата, охват, реакции, текст, статья). Плюс цветные эмодзи во всём приложении.

Делай по этапам, после каждого — проверка на стенде (раздел 7). Ничего не коммить.

## 1. Что есть сейчас (выяснено 2026-10-23, перепроверять не нужно)

| Файл | Что делает | Судьба |
|---|---|---|
| `js/post-viewer.js` + `#post-viewer` в `index.html:745` + `css/app.css:2013–2064` | посты кандидата в источники (`sources.js:103`): сцена слева, колонка справа, ←/→ посты, ↑/↓ медиа, точки альбома, плашки «видео загружается / большое видео» | **заменяется** новым просмотрщиком; плашки, докачку (`video-pending.js`), свайпы и ловушку фокуса — перенести |
| `js/viewer.js` | зум картинки/видео, галерея, кнопка 🚀 | **остаётся** как «во весь экран» поверх просмотрщика поста |
| `js/article.js` (`openArticleReader`, `renderArticle`, `blockNode`) | читалка статьи: блоки из `api('article_read', {url})` (только свои записи), обложка, мета | рендер блоков **переиспользовать** (экспортировать `renderArticle`/`blockNode`), отдельную панель читалки потом заменить просмотрщиком |
| `js/card.js` | `cardKind`, `articleCover`, `articleMeta`, `siteBadge`, `clampText`, `shortText` | переиспользовать |
| `js/content.js` `recordGallery(item)`, `itemSlides(item)` | медиа записи (картинки, видео, `display_*`, `fallback*`, `captions[i]`) | адаптер записи строится на них |

Форма данных в разных местах разная: пост источника — `{text, media: [{kind, src, poster, page, pending, unavailable}], posted_at, views, reactions, comments, url}`;
запись подбора — `item` (`image`, `images[]`, `video`, `display_image`, `captions[]`, `text_post`, `article`, `url`, реакции по эмодзи — см. `content.js:186`);
пост очереди календаря — `{id, text/full_text, status, at, article, thumb, channel_title}` (картинка — `api outbox_media?id=`, сейчас только первая);
журнал опубликованных — `{text, media: N, url, at}`. Опрос в очереди — `post.poll`.

## 2. Модель: один формат поста, адаптеры на входе

Новый модуль `js/post-view.js` принимает **только нормализованный пост** (без DOM-зависимостей от места вызова):

```js
{
  key,                       // для листания и кэша
  source: { name, url, badge },          // badge — буква/цвет как siteBadge; аватара нет — буква
  date,                      // unix-секунды; подпись «3 ч назад» через formatAgo, в title — полная дата
  url,                       // ссылка «Открыть в источнике» (только через safeSourcePostUrl)
  text,                      // простой текст (переносы строк сохраняются)
  media: [{ kind: 'image'|'video', src, poster, width, height, duration, fallback, page, pending, unavailable }],
  article: null | { title, lead, site, rubric, author, minutes, cover, readUrl },   // readUrl — можно ли грузить блоки через article_read
  poll: null | { question, options: [...] },
  stats: { views, comments, reactions: [[emoji, n], ...] | number },
  badge: null | { text, tone },          // «в очереди», «опубликован», «не вышел» — из календаря/очереди
}
```

и опции открытия `openPostView(posts, index, { actions, loadMore, onClose, title })`:
- `actions(post)` → массив кнопок `{ label, icon, primary, run }` — место вызова само решает, что можно: «🚀 В пост», «В расписание»,
  «Перенести», «Удалить из очереди», «В источники», «Скрыть»… Просмотрщик кнопок не придумывает; их состояние «занято» — пока `run()` не завершился.
- `loadMore()` — для ленты: когда пользователь дошёл до последнего поста, подгрузить ещё (необязательно).

Адаптеры — рядом, в `js/post-adapters.js`: `fromSourcePost(post, source)`, `fromRecord(item)` (через `itemSlides`/`recordGallery`),
`fromQueuePost(p, channel)`, `fromPublished(e)`. Вся «грязь» форматов — только там. Покрой адаптеры проверкой на Node
(`tools/test_post_view.mjs`: на вход — образцы из фикстур, на выход — нормализованный пост).

## 3. Раскладки (выбираются по содержимому, не по месту вызова)

Общая рамка — как у текущего `.post-viewer-sheet`: модальное окно до 1180×860, на телефоне (< 900 px) — весь экран. Шапка: счётчик
«Пост 3 из 24», ‹ › по постам, ✕. Цвета, рамки, тени, шрифты — **только токены темы** (`var(--surface)`, `--line-strong`, `--accent`, `--radius-card`,
`--shadow-card`…): приложение в теме «День / Эфир», просмотрщик обязан выглядеть родным в обеих.

**A. Медиа-пост** (есть хоть одно медиа). Слева — тёмная сцена (как в `viewer.js`), справа — колонка-карточка 340–400 px:
источник со значком и датой, бейдж статуса, охват/комментарии/реакции чипами (как `eng-chip` в главной карточке), **полный** текст
со своей прокруткой, внизу колонки — закреплённая полоса действий `actions` и «Открыть в источнике ↗».
- Сцена: медиа вписано целиком (`object-fit: contain`), без прыжка вёрстки при листании — место резервируется по `width/height`, пока
  картинка грузится (скелетон в пропорции). Клик по картинке или ⤢ — `openViewerGallery` по всем картинкам поста, с текущей (зум, 0 — 1:1).
- **Альбом 2–10**: стрелки на сцене, счётчик «3 / 7», под сценой — **лента миниатюр** (64 px, текущая обведена `--accent`), а не точки.
- **Альбом 11+ (до 20 и больше)**: та же лента (прокручивается, миниатюры — `loading=lazy`), плюс кнопка «▦ Все 20» — сцена переключается
  в **сетку** всех медиа (как сетка главной карточки: 3–4 колонки, видео с меткой длительности); клик по плитке — обратно в одиночный вид на этом файле.
- **Пост без текста**: колонка не пустеет — источник, дата, статистика, действия; вместо текста — тихая строка «Без подписи».
- Видео: постер, звук по кнопке/первому запуску (громкость 0.33, как сейчас), при листании и закрытии — пауза и `removeAttribute('src')`.
  Плашки «загружается», «большое видео» (`BIG_VIDEO_NOTE`), «смотреть на сайте ↗» — перенести из `post-viewer.js` как есть.
- Длинный текст (5000+ символов) + одна картинка: сцена не сжимается, текст прокручивается в колонке; узкая сцена не бывает уже 55 % окна.

**B. Текстовый пост** (медиа нет, не статья). Одна колонка для чтения шириной ~640 px по центру светлой (`--surface`) области:
шапка источника, текст, статистика, действия. Короткий текст (≤ 280 символов) — крупно (22–26 px, как `post-viewer-bigtext`),
длинный — обычным размером чтения (17–18 px, межстрочный 1.55). Опрос — вопрос и варианты строками-полосками (без голосования).

**C. Статья** (`article` есть). Тот же центр шириной ~680 px, макет читалки: обложка 16:9 (`articleCover`), мета (`articleMeta`),
заголовок, анонс; затем блоки статьи (`article_read`, если `readUrl` разрешён) — со скелетоном, пока грузятся. Нельзя загрузить блоки
(чужая запись, ошибка) — анонс, текст поста и кнопка «Читать на сайте ↗». Картинки внутри статьи открываются в `viewer.js` галереей.
Действия статьи (например «🚀 В пост: заголовок, выжимка и ссылка») — той же закреплённой полосой.

**Телефон (< 900 px)** для всех трёх: весь экран, шапка сверху, содержимое одной прокруткой: медиа (свайп по сцене — медиа поста,
тап по половинам — тоже), под ним карточка с текстом; полоса действий закреплена снизу (с учётом `env(safe-area-inset-bottom)`).
Листание постов — кнопки ‹ › в шапке и свайп по шапке/карточке (не по сцене, чтобы не путать с альбомом).

## 4. Текст поста

- Только `textContent`/узлы — никакого `innerHTML` с текстом площадок.
- Переносы строк сохраняются (`white-space: pre-wrap`), длинные слова и ссылки переносятся (`overflow-wrap: anywhere`).
- Ссылки `https?://…` → `<a target=_blank rel="noopener noreferrer">` (только http/https), `#хэштеги` и `@имена` — выделены цветом, без перехода.
- `**жирный**` (так пишет `articleCaption`) — жирным; остальная разметка — как есть.
- Кнопка «Копировать текст» в колонке (`navigator.clipboard`, при ошибке — выделить текст).

## 5. Эмодзи

Решение (2026-10-23): **эмодзи Apple на сайте использовать нельзя** — шрифт Apple Color Emoji лицензирован только для устройств Apple,
выкладывать его файлы или картинки на сервер нельзя. Поэтому:
- На устройствах Apple браузер и так рисует системные эмодзи Apple — их и оставляем (локальный шрифт пользователя, ничего не раздаём).
- Всем остальным — **Noto Color Emoji** (Google, лицензия SIL OFL 1.1 — можно раздавать и встраивать), **со своего сервера**, как остальные шрифты.

Как сделать:
1. Скачай Noto Color Emoji в виде woff2-кусков с `unicode-range` (как их отдаёт Google Fonts: запроси
   `https://fonts.googleapis.com/css2?family=Noto+Color+Emoji&display=swap` с заголовком `User-Agent` современного Chrome — в ответе
   `@font-face` с `unicode-range` и ссылками на woff2; скачай все куски). Положи в `fonts/NotoColorEmoji-<n>.woff2`, `@font-face`
   — в начало `css/app.css` рядом с остальными (`font-display: swap`). Файл лицензии `OFL.txt` — в `fonts/`.
   Браузер грузит только куски с теми эмодзи, что встретились на странице. Запиши в отчёт общий размер и сколько кусков.
2. Стек шрифтов: эмодзи-семейство идёт **после** текстового (`'Rubik', …, 'Apple Color Emoji', 'Noto Color Emoji', sans-serif`), иначе
   цифры, `#` и `*` (они есть в диапазонах эмодзи) возьмутся из эмодзи-шрифта. Пропиши стек в базовых переменных шрифтов приложения
   (`--font-*` или где он задан), а не точечно — эмодзи должны быть цветными везде: карточки, реакции (`.eng-emoji`), календарь,
   редактор, журнал.
3. Проверь в Chrome (Linux — там своих цветных эмодзи может не быть): 😀 👍🏽 (оттенок кожи) 👨‍👩‍👧 (ZWJ-последовательность) 🇷🇺 (флаг)
   ❤️ (с VS16) 1️⃣ (keycap) 🫠 (Unicode 14) — все цветные, одной картинкой, не распадаются на части; рядом цифры «2026» и «#тег» — обычным
   текстовым шрифтом. Если ZWJ-последовательности распадаются из-за того, что текстовый шрифт содержит U+200D, — напиши в отчёте
   и предложи правку `unicode-range` текстового шрифта.
4. Firefox и Chrome поддерживают цветной формат Noto (COLRv1); Safari — нет, но на Apple сработает пункт про системные эмодзи.

## 6. Где подключить (по этапам)

1. **Этап 1** — сам просмотрщик + адаптер `fromSourcePost`: заменить `post-viewer.js` в превью источника (`sources.js:103`). Старый модуль
   и разметку удалить, когда новый проверен. Эмодзи (раздел 5) — тоже на этом этапе.
2. **Этап 2** — запись подбора: главная карточка (клик по медиа/тексту/«Читать статью» → просмотрщик вместо `openArticleReader`), Предложка
   (`tabs.js` `proposalCard`), инспектор записей БД. Действия: «🚀 В пост» (тот же `postItemToTelegram`), «Скрыть» — где есть.
   Листание — по списку, из которого открыли.
3. **Этап 3** — календарь и очередь: пост календаря (панель поста — кнопка «Открыть пост»), «Очередь» и «Опубликованные» в личном кабинете.
   Для этого `handle_outbox_media` (`handlers/account.php`) должен отдавать **n-й** файл поста (`?id=&n=`; сейчас всегда первый; проверка
   индекса и пути — как сейчас), а `handle_calendar` — число и виды файлов поста (`media: [{kind, width, height}]`), без путей.
   Действия: «Перенести», «Копия», «Удалить из очереди», «Повторить» — те же функции, что в панели календаря.
4. `article.js` после этапа 2 остаётся только как рендер блоков (панель `#article-reader` удалить, если больше никто не открывает).

Общие требования ко всем этапам: `history.pushState` — «назад» закрывает просмотрщик; Esc закрывает (если открыт зум `viewer.js` —
сначала его); фокус в ловушке, после закрытия — на элемент, с которого открыли, прокрутка страницы на месте; ←/→ — посты, ↑/↓ — медиа;
соседние посты — предзагрузка первой картинки; `prefers-reduced-motion` — без анимаций.
