# Исправить: «Видео слишком большое: Telegram не отдаёт его в веб-версии» в превью источника

Ошибка повторяется постоянно, пользователь её видит в окне просмотра на вкладке «Источники» (карточка кандидата, мозаика постов канала Telegram). Нужно, чтобы большие видео из Telegram **сами скачивались через личный аккаунт** и показывались, а не просили нажимать кнопку каждый раз.

## Причина (уже найдена, перепроверь по коду)

1. `lib/sources.php` → `telegram_posts_from_html()` ставит посту `video_unavailable = true`, если на странице есть плеер без файла (большое видео). `video_page` у такого поста **не задаётся**.
2. В подборе (парсер) это уже решено: `lib/parser.php` ~строка 90–92 — если подключён личный аккаунт (`telegram_user_connection() !== null`), пост превращается в `['video_unavailable' => false, 'video_via' => 'tgu', 'video_page' => $p['url']]` и ролик докачивается очередью.
3. В **превью источника** этого шага нет: `handlers/sources.php` → `first_previewable()` вызывает `video_preview_prepare($p['posts'], …)` (`lib/ytdlp.php` ~323), но тот пропускает посты без `video_page`. Поэтому:
   - большие видео Telegram в превью никогда не ставятся в очередь сами;
   - даже после ручного «Скачать через мой Telegram» (видео реально скачивается — в `kv` есть `video_preview:*` со `status: done`) при следующем открытии превью `video_preview_apply()` снова не находит `video_page` → плитка опять «слишком большое», окно опять показывает ошибку.
4. Фронт (`js/sources.js` ~71, ~94, ~110–118) для `unavailable` всегда вешает `note` «Видео слишком большое…» и значок; окно (`js/viewer.js` ~194) показывает этот `note`. После успешного скачивания из окна (`swapToVideo`) плитка в мозаике не обновляется — повторное открытие снова просит скачать.

## Что сделать

### Бэкенд
1. Вынеси преобразование из `lib/parser.php:92` в общую функцию, например в `lib/ytdlp.php`:
   ```php
   /** Большие видео Telegram без файла: при подключённом личном аккаунте их докачивает очередь (video_via = tgu, video_page = адрес поста). */
   function telegram_big_videos_via_account(array $posts, $uid = null): array { … }
   ```
   Условия те же: площадка Telegram, `telegram_user_connection($uid) !== null`, `!empty($p['video_unavailable'])`, непустой `url`, и `video_page_via($p['url']) === 'tgu'`.
2. Используй её в `lib/parser.php` вместо встроенного `array_map` (поведение парсера не меняется) и в `handlers/sources.php` → `first_previewable()` **перед** `video_preview_prepare()` — только для `PLATFORM_TELEGRAM`.
   Итог: первые `VIDEO_PREVIEW_FIRST` роликов превью ставятся в очередь сами (на плитке «Видео загружается…»), уже скачанные сразу приходят с `video` (через `video_preview_apply`), остальные — «Видео — нажмите, чтобы загрузить».
3. Без подключённого личного аккаунта всё остаётся как есть (`video_unavailable`), это единственный случай, когда показываем пояснение.

### Фронт
4. `js/sources.js`: ветка `item.unavailable` теперь срабатывает только без аккаунта. Поменяй текст `note`/`title` на честный: «Большое видео: Telegram не отдаёт его в веб-версии. Подключите личный аккаунт Telegram, и оно будет скачиваться само.» Кнопка в окне при этом уже ведёт в «Личный кабинет → Соцсети» (ответ 409 в `fetchVideo`) — проверь, что так и есть.
5. Когда ролик скачался из окна просмотра (`swapToVideo` в `js/viewer.js`), обнови исходную плитку: проставь `dataset.video`, убери `dataset.tooBig`, `dataset.pending`, значок `.is-external` и подпись `.tile-pending` — как это уже делает `watchPending()` в `sources.js` (~173–185). Сделай это через событие, а не прямой импорт: например `window.dispatchEvent(new CustomEvent('video-ready', { detail: { page: item.videoPage, local } }))` в viewer, слушатель в `sources.js` ищет плитку по `dataset.videoPage` (и в Подборе / Предложке, если там есть такие же плитки — проверь `content.js`, там `videoFields()`).
6. Окно (`viewer.js` ~194): если у элемента есть `videoPage` и он `videoPending`, не показывать `note` — показывать «Скачиваю видео…» (уже делает `fetchVideo`).

## Проверка (без браузера!)
- **Не открывай приложение headless-браузером**: каждая загрузка создаёт пользователя и запускает парсер.
- `php -l` на все изменённые PHP, `node --check` на JS.
- Прогон функции на массиве: пост `['url' => 'https://t.me/somechannel/123', 'video' => '', 'video_unavailable' => true]` → при подключённом аккаунте пользователя (uid владельца, см. `connections_load`) получается `video_via=tgu`, `video_page=url`, `video_unavailable=false`; при `uid` без аккаунта — без изменений.
- Проверь, что `video_preview_apply()` для поста с `video_page`, у которого в `kv` `video_preview:*` = `done`, возвращает `video` = локальный путь (возьми любой существующий done-ключ: `sqlite3 data/posta.sqlite "SELECT key,value FROM kv WHERE key LIKE 'video_preview:%' LIMIT 3"`).
- Парсер после рефакторинга ведёт себя так же: сообщение «больших видео без файла пропущено» появляется только без аккаунта.
- Не коммить. Короткий отчёт: что поменял, что проверено, что пользователю проверить глазами (открыть превью Telegram-канала с большими видео).
