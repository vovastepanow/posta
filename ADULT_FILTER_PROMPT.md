# Задача: фильтр 18+ и «Жести»

Ты работаешь в PHP-проекте `/var/www/html/posta` (Posta: ИИ подбирает контент по теме и публикует в Telegram).

Лендинг обещает: «18+ Posta отсеивает сам». На деле — нет. Любой пользователь может выбрать тему «Порно», получить
такой пул и опубликовать его в канал через сервис. Это нарушает правила Telegram и VK, закон РФ и правила платёжных
систем (магазин заблокируют). Нужно:

1. **По умолчанию 18+ и «Жесть» недоступны никому:** такие темы нельзя выбрать и не видно в списках, такие записи не
   попадают в пул и не показываются, опубликовать их через сервис нельзя.
2. **Доступ по флагу:** администратор может включить 18+ конкретному пользователю командой в CLI (владелец сайта
   пользуется темой «Порно» сам). Включить себе из интерфейса нельзя — проверить возраст сайт не может.

Делай части по порядку: A → B → C → D → E → F. Не начинай следующую, пока проверка предыдущей не прошла.

## Что уже есть в коде (используй, не дублируй)

- **Дерево тем** `lib/topic_tree.php`: ветки с `'nsfw' => true` — `adult` («Для взрослых 18+»: эротика, порно, фап,
  хентай, пошлый юмор) и `shock` («Жесть»). Частные темы наследуют флаг ветки.
- **`topic_is_nsfw($text)`** в `lib/topics.php` — тема 18+ или шок по реестру. Сейчас **нигде не вызывается**.
- **`topic_is_adult($topic)`** в `lib/discovery.php` — по словам (`TOPIC_ADULT_WORDS`) в названии, описании и синонимах.
  Ловит то, чего нет в реестре (новая тема, введённая словами).
- **Метки записей:** полный анализ кладёт в запись `'tags'` — список ключей дерева (`adult.porn`, `humor.jokes`…).
  `content_tag_catalog()[$key]['nsfw']` говорит, из 18+/шок-ветки ли метка. У старых записей поля `tags` нет вовсе.
- **Доски Двача:** `dvach_board_tags($board)` и `DVACH_ADULT_TAG = '18+'` в `lib/sources.php` (`hc`, `gg`, `sex`…).
  У записей с Двача есть поле `board`.
- **Тема записи:** поле `topic` — тема, под которую запись нашли.

## Часть A. Флаг доступа

1. **Миграция:** в `lib/db.php` добавь миграцию со **следующим свободным номером** (посмотри наибольший в массиве

   ```php
   /** Разрешён ли пользователю контент 18+ и «Жесть» (флаг ставит администратор: tools/cli.php adult-allow). */
   function user_adult_allowed($uid = null) { ... }   // static-кэш на процесс по $uid: функцию зовут на каждую запись
   ```
3. **Команда** в `tools/cli.php`: `adult-allow <id> on|off` — проверяет, что пользователь есть, ставит флаг, печатает
   `<первые 8 символов id>: 18+ разрешено` / `запрещено`. Строку справки добавь в начало файла, как у других команд.


## Часть B. Что считать 18+

В тот же раздел `lib/content.php`:

```php
/** Тема 18+ или «Жесть»: по реестру (topic_is_nsfw) или по словам (topic_is_adult). Пустая тема — нет. */
function topic_is_restricted($topic) { ... }

/** Запись 18+ или «Жесть». Порядок проверок важен: сначала самое надёжное. */
function content_is_adult(array $r) { ... }
```

`content_is_adult` возвращает true, если **хоть одно** верно:
1. в `tags` есть метка, у которой `content_tag_catalog()[$key]['nsfw']` true;
2. `topic_is_restricted($r['topic'] ?? '')`;
3. у записи есть `board` и в `dvach_board_tags($r['board'])` есть `DVACH_ADULT_TAG`.

Иначе false: запись без меток из обычной темы считаем допустимой (старые записи модель не размечала).

Также функция для публикации:

```php
/** Запись пользователя (пул или история), у которой этот адрес — картинка, видео или их локальная копия. null — не нашли. */
function content_record_by_media($src, $uid = null) { ... }
```
- Сравнивай `$src` с полями `image`, `image_local`, `video`, `video_local` записи и тех же полей у каждого элемента
  `gallery` (это список объектов `{image, video, image_local?, video_local?}` — у многокартиночных постов Двача).
- Ищи по `pool_load($uid)` и всем коллекциям `history_load($uid)`. Пустой `$src` → null.

**Проверка:**
```
php -l lib/content.php
php -r 'require "bootstrap.php";
  foreach ([["tags" => ["adult.porn"]], ["topic" => "Порно"], ["board" => "hc"], ["tags" => ["humor.jokes"], "topic" => "Мемы и юмор"], []] as $r)
    echo json_encode($r, JSON_UNESCAPED_UNICODE), " → ", content_is_adult($r) ? "18+" : "ок", "\n";'
```
Ожидается: 18+, 18+, 18+, ок, ок.

## Часть C. Темы

Для пользователя без флага (`!user_adult_allowed()`):

1. **Выбор темы:** в `handle_save_topic` и `handle_save_second_topic` — до любого сохранения и до запуска парсера:
   если `topic_is_restricted(введённое)` → `DomainException('Темы 18+ и «Жесть» недоступны.')`. После того как тема
   определена (сопоставлена с реестром или создана) — проверь ещё раз уже итоговую тему: введённое слово может быть
   безобидным, а тема, к которой его отнесли, — из ветки 18+. Тогда тоже отказ, и **настройки пользователя не должны
   измениться**: посмотри, в какой момент функция сохраняет тему, и проверяй до этого момента.
2. **Списки тем:** `handle_topics` не отдаёт темы, для которых `topic_is_restricted` true (и ветки `adult`/`shock`
   целиком). Проверь, откуда берут список меню темы в шапке (`renderTopicSwitch` в `js/content.js`), дерево
   (`js/tabs.js`) и подсказки ввода (`topic-options`, `tree-options`) — все должны получать отфильтрованный список с
   сервера; на клиенте ничего не фильтруй.
3. **Текущая тема уже 18+** (пользователь выбрал её раньше): не меняй её молча. `handle_get_current_item` вместо записи
   возвращает `json_response(['status' => 'empty', 'message' => 'Тема «…» недоступна: выберите другую тему.'])` (посмотри,
   какой формат «пусто» уже понимает `js/content.js`, и используй его же). Парсер для такой темы не запускается: найди,
   где `handle_get_current_item` и `tab_session_heartbeat` запускают сборщик, и не запускай его, если тема запрещена.

## Часть D. Пул и показ

1. **Парсер не добавляет 18+ в пул пользователю без флага.** В `lib/parser.php` в месте, где запись принимается после
   полного анализа (рядом с `cli_echo("-> Принято: …")`), если у пользователя нет флага и собранная запись
   `content_is_adult` — не добавляй её, напиши в журнал `-> Отклонено: 18+ или «Жесть».` и учти как отклонённую так
   же, как соседний код учитывает отклонения (посмотри, как считается строка «Отклонено» в итогах). Пользователь
   парсера — `app_user_id()`, он привязан из аргумента командной строки.
2. **Показ — страховка для старых записей.** Добавь условие в **одно** место — `pool_item_in_topic` в
   `handlers/content.php`: запись не проходит, если у пользователя нет флага и `content_is_adult($i)`. Эта функция уже
   используется подбором, архивом 🔥 и «Базами данных», так что фильтр будет единым. Убедись поиском
   (`grep -n "pool_item_in_topic\|pool_topic_positions" -r handlers lib`), что других путей показа пула нет.
3. **«Предложка»:** найди, как `handle_proposals` выбирает записи истории, и отфильтруй так же
   (`content_is_adult` при отсутствии флага). Если там уже вызывается `pool_item_in_topic` — ничего не добавляй.
4. Записи из базы **не удаляй**: при включении флага они снова видны.

## Часть E. Публикация

В `handle_telegram_publish` (`handlers/account.php`) — до подготовки медиа и до списания лимитов:
- для каждого элемента медиа без загрузки (`upload` пустой) найди запись `content_record_by_media($item['src'])`;
- если пользователь без флага и запись найдена и `content_is_adult` →
  `json_error('В посте есть материал 18+ или «Жесть» — такое через Posta публиковать нельзя.', 422)`.
- Файлы, которые пользователь загрузил сам (`upload` задан), и ссылки, не найденные среди его записей, не проверяй:
  за свои файлы отвечает он сам (это будет в оферте). Напиши об этом комментарий в коде.

## Часть F. Проверка без браузера и моделей

Создай `tools/test_adult.php` (только CLI, как `tools/cli.php`) и запусти его **на копии проекта**, потому что путь к
базе — константа от папки проекта:

```
T=$(mktemp -d) && cp -r bootstrap.php config.php config.local.php secret.key.php lib handlers tools "$T"/ \
  && mkdir "$T/data" "$T/users" "$T/media" && sqlite3 data/posta.sqlite ".backup $T/data/posta.sqlite" \
  && POSTA_MEDIA_CACHE_DIR="$T/media" php "$T/tools/test_adult.php"; rm -rf "$T"
```

Скрипт печатает `OK …` / `FAIL …` и в конце число провалов. Обработчики вызывают `json_response` / `exit`, поэтому
тестируй функции, а не обработчики: вынеси проверки из частей C и E в функции (`topic_save_denied($topic)`,
`publish_media_denied(array $items)` — возвращают текст отказа или null) и вызывай их и из обработчиков, и из теста.

Сценарии (тестовый пользователь — новый id, созданный в скрипте; флаг ставь прямым `UPDATE` и сбрасывай static-кэш
`user_adult_allowed` — предусмотри для этого второй аргумент или отдельную функцию сброса):
1. `content_is_adult` — пять случаев из части B.
2. Без флага: `topic_save_denied('Порно')` — отказ; `topic_save_denied('порнуха')` (синоним из дерева) — отказ;
   `topic_save_denied('Мемы и юмор')` — null.
3. С флагом: `topic_save_denied('Порно')` — null.
4. Без флага: в списке, который отдаёт `handle_topics` (вынеси сборку списка в функцию), нет тем ветвей `adult` и `shock`.
5. Без флага: пул из двух записей (обычная и с `tags: ["adult.porn"]`) — `pool_topic_positions` возвращает одну.
   С флагом — две.
6. Без флага: `publish_media_denied([['src' => <image_local записи 18+ из пула>]])` — отказ;
   для обычной записи — null; для `['upload' => '0', 'src' => '']` — null.
7. В конце удали тестового пользователя.

Плюс `php -l` всех изменённых файлов и `node --check` для изменённых JS.

## Отчёт пользователю

1. Включить 18+ себе: `php tools/cli.php adult-allow b34cfe131b9ddea519d4cbd42c831fb5 on` — иначе ваши записи и
   «Предложка» по теме «Порно» скроются (из базы ничего не удалено).
2. Открыть сайт в своём браузере и проверить: в меню тем нет веток 18+ (с выключенным флагом), подбор по обычной
   теме работает.
3. Старые записи без меток определяются только по теме и доске. Для точности можно разметить их моделью:
   `php tools/cli.php tag-content 50` (запускает модель — делайте, когда видеокарта свободна).
