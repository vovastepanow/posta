# Задача (срочно, до CALENDAR_CARDS_FINISH_PROMPT.md): посты из очереди теряют файлы, в подпись уходит «Пост без текста», у карточек нет миниатюр

Ты работаешь в проекте `/var/www/html/posta` (Posta). На снимке календаря владельца (2026-10-23 20:50) карточки совсем не похожи на макет
`tools/stand/calendar/cards-mock.html`: **вместо миниатюр везде значок камеры**, а текст — «Без текста» / «Пост без текста». Разбор показал, что
это не вёрстка, а три бага в данных. Один из них ломает публикацию.

Ничего не коммить. Живую страницу Posta в headless не открывать (свежая загрузка создаёт пользователя и запускает парсер).

## 1. Что выяснено (перепроверять не нужно)

### 1.1 Пост в очереди теряет файл — и не выходит («Файлы поста не найдены»)
- Пост на 20:10 23.10 не вышел с ошибкой «Файлы поста не найдены.». Пост на 22:00 (`id 65573b0a1038`) не выйдет по той же причине:
  папки `data/outbox/65573b0a1038/` и `data/outbox/65e4fe63b6cb/` **пустые**, а в записи очереди `media[0].path` указывает на файл внутри них.
- Причина — `outbox_media_move()` (`lib/telegram.php:~655`) переносит **только содержимое временной папки `$work`**, а потом всем файлам переписывает
  `path` на папку поста. Но `telegram_prepare_media()` (`:234`) для картинки из кэша сайта берёт файл **прямо из кэша** (`media_cache_path($src)`,
  `/var/lib/posta/media/…`), а `telegram_prepare_photo()` (`:170`) возвращает тот же путь, если картинку не нужно пережимать. Файл в `$work` не попадает,
  в папку поста не переносится, а путь уже переписан. Так ломаются все посты, поставленные в очередь из «Предложки»/«Подбора» с подходящей JPEG/PNG
  (перенос в календарь, «Заполнить дыры» — `lib/calendar_fill.php:131–133`, обычная отложка через нашу очередь).
- Файлы в кэше есть: `media/a64fe92b376b58634360911219d412b4.jpg` и `media/537202f7e448934d47f34269cfe473ff.jpg` → `/var/lib/posta/media/…` — существуют.

### 1.2 В подпись поста уходит заглушка «Пост без текста»
- У поста на 22:00 в очереди `text = 'Пост без текста'`. Это заглушка сервера (`EMPTY_POST_TEXT`, `lib/sources.php:14`; список заглушек — `NO_TEXT` в `js/core.js:29`,
  ещё `'Текст к посту отсутствует'`). Она попала в подпись при переносе записи в календарь: `js/calendar.js:~1231` шлёт `text: item.text || ''`,
  `lib/calendar_fill.php:56` берёт `$cand['text']` как есть. Опубликовался бы пост с подписью «Пост без текста».

### 1.3 У карточек нет миниатюр
`handle_calendar` (`handlers/account.php:~594`):
- опубликованные посты (`published_load`) — `'thumb' => false` всегда: в журнале публикаций нет ни картинки, ни ссылки на неё;
- посты в «Отложенных» Telegram (`status telegram`) — `thumb` всегда `false`, и `handle_outbox_media` (`:666`) их не отдаёт;
- посты, где первый файл — видео, — `thumb` только для `kind === 'photo'`, у видео камера;
- остальные — `thumb` есть, но файл пропал (1.1) → 404 → камера.

## 2. Что сделать

### A. Файлы очереди (главное)
1. `outbox_media_move()`: каждый файл, чей `path` **не** внутри `$from`, — **скопировать** в папку поста (кэш сайта трогать нельзя: он общий и чистится сам).
   Ошибка копирования → исключение и откат, как сейчас. То же проверь в `outbox_duplicate_post()` и везде, где путь переписывается (`grep -n "outbox_media_dir\|'path' =>" lib/telegram.php`).
2. Перед постановкой в очередь — проверка: каждый `path` подготовленных медиа существует **в папке поста**; нет — ошибка сразу при постановке
   («Не удалось сохранить файлы поста»), а не в момент публикации.
3. **Починить уже стоящие посты**: CLI `php tools/cli.php outbox-repair` — для постов `queued`/`failed` с отсутствующими файлами: по `media[].src` взять файл из кэша
   (`media_cache_path`) или скачать по исходной ссылке (`fetch_public_media`), положить в папку поста; `failed` с ошибкой «Файлы поста не найдены» после починки — снова `queued`
   **только если время ещё не прошло**; прошедшие — оставить `failed` и написать в отчёте. Сначала `--dry-run` — список без изменений. Запускать на боевой базе — **только `--dry-run`**,
   настоящий запуск — владелец (команду дай в отчёте).

### B. Заглушки не уходят в подпись
1. Одна серверная функция `post_caption_clean(string $text): string` — убирает заглушки (`EMPTY_POST_TEXT`, «Текст к посту отсутствует» и т.п. — один список на сервере,
   синхронный с `NO_TEXT` клиента), `trim`. Вызывать в `handle_telegram_publish`, `calendar_fill_apply` и везде, где текст идёт в `outbox_queue_post` / отправку в Telegram.
2. Клиент: перенос в календарь (`calendar.js:~1231`), «Заполнить дыры» (`calendar-pool.js:36`, `:53`) — тоже не слать заглушку (защита с двух сторон).
3. `outbox-repair` из A заодно чистит заглушку в `text` стоящих постов (в `--dry-run` — показывает).

### C. Миниатюра у каждой карточки
1. При постановке в очередь (наша очередь **и** «Отложенные» Telegram) и при публикации сразу — сохранять **маленькую миниатюру** поста: JPEG ~160 px по большей стороне,
   из первой картинки, а для видео — кадр (`ffmpeg`, уже используется в `telegram.php`; постер, если он есть у записи). Хранить отдельно от файлов поста, чтобы она жила
   после публикации и после удаления папки поста: например `data/thumbs/<id>.jpg` (не в webroot-доступной папке без проверки — отдавать через обработчик с проверкой владельца,
   как `handle_outbox_media`). В записи очереди и в записи журнала публикаций — поле `thumb_id`.
2. `handle_calendar`: `thumb` = есть миниатюра (для всех статусов, включая `telegram` и опубликованные). Обработчик `outbox_media` (или новый `post_thumb`) отдаёт миниатюру по `thumb_id`
   только своему пользователю.
3. Для уже опубликованных постов без миниатюры — ничего не выдумывать: карточка без миниатюры (см. D).
4. Чистка: миниатюры старше 90 дней и без ссылок из очереди/журнала — удалять (туда же, где чистится остальное).

### D. Пост без текста и без миниатюры — как выглядит карточка
- Нет текста — вторая строка **не** «Без текста»: показать тип содержимого тихим текстом `--muted`: «фото», «видео 0:42», «альбом · 4», «опрос» (данные `media`, `duration` уже есть или добавь в `telegram_post_summary`).
- Нет миниатюры (старые опубликованные) — вместо камеры кавычка/значок типа на тонированном фоне цвета канала, как пост без медиа в макете, но со значком типа (фото/видео) вместо «“».
- Сверь с макетом: карточка должна читаться как пост, а не как «камера + Без текста».
