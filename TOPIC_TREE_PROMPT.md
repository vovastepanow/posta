# Задача: встроить готовое дерево тем в проект Posta

Ты работаешь в PHP-проекте `/var/www/html/posta`. Проект подбирает картинки и видео из соцсетей по теме,
которую выбирает пользователь. Локальные модели (Ollama, qwen) оценивают каждую запись по теме.

Нужно сделать две вещи:

1. **Часть A.** Засеять в реестр тем готовое дерево: 20 общих тем и 72 частные.
2. **Часть B.** Добавить в анализ записи поле «форма поста»: мем, фото, видео, текст или рисунок.

Делай части по порядку. Не начинай часть B, пока часть A не проверена.

## Общие правила

- **Сначала прочитай файлы целиком:** `lib/topics.php`, `lib/sources.php` (функции `load_source_db`,
  `update_source_db`, `normalize_source_db`), `lib/db_access.php` (функции `catalog_load`, `catalog_update`),
  `lib/ai.php` (функции `content_analysis_schema`, `content_analysis_prompt`, `analyze_content_with_vision`),
  `tools/cli.php`, `config.php`.
- **Схему SQLite не меняй.** Темы лежат в таблице `topics` как JSON в колонке `data`. Новые поля темы просто
  добавляются в этот JSON. Миграция в `lib/db.php` не нужна.
- **Не трогай файлы, которые не названы в задаче.** В рабочем дереве много чужих незакоммиченных правок.
- **Не делай git commit.** Пользователь проверит изменения сам.
- **Пиши в стиле проекта.** Короткие функции, комментарии по-русски, без лишних абстракций и классов.
- **Перед любым запуском, который пишет в базу, сделай копию:**
  ```
  cp data/posta.sqlite data/posta.sqlite.bak-topics
  ```

## Как сейчас устроены темы

Это нужно понимать, чтобы не сломать существующее.

- У темы есть `id` вида `t` плюс 8 hex-символов. Он считается так: `topic_id_for($title)`, то есть от
  нормализованного названия. Одинаковое название всегда даёт одинаковый `id`.
- `scope` бывает `broad` (общая тема) или `narrow` (частная). У частной темы `parent` равен `id` общей.
  Глубина ровно два уровня. Частная тема не может быть родителем.
- **`topic_normalize_entry()` выбрасывает все поля, которых нет в её списке.** Если ты добавишь в тему новое
  поле и не добавишь его туда, оно молча пропадёт при первом же сохранении.
- `about` идёт прямо в промпты оценки записи. Поэтому он должен описывать, что видно на картинке.
- Профиль темы (`profile`) умная модель пишет сама при первом подборе по теме. Засевать профили не нужно.
- `DEFAULT_TOPIC` в `config.php` равен «мемы и юмор». Тема с таким названием должна остаться общей.
- В базе сейчас три общие темы, созданные пользователем: «Мемы и юмор», «Порно», «Фап контент».
  К ним могут быть привязаны источники и записи. Их `id` менять нельзя.

## Слияние со старыми темами

Пользователь хочет, чтобы существующие темы и всё, что к ним привязано, влились в новое дерево, а не
потерялись. Вот как это устроено и почему это безопасно.

**Данные ссылаются на темы строкой, а не по `id`.** Строка сравнивается с названием и синонимами темы через
`topic_norm()`. Вот какие строки сейчас лежат в базе:

| Где хранится | Строки тем |
|---|---|
| `catalog_sources`, поле `topics` у каналов и пабликов | «мемы и юмор», «мемы и приколы» |
| `source_suggestions`, поле `topic` | «Мемы и юмор» |
| `history_items` и `pool_items`, поле `topic` | «Мемы и юмор», «мемы и приколы», «Порно», «Фап контент» |
| `screened_cache`, колонка `topic` | «Мемы и юмор», «Порно» |

Отсюда правила слияния:

1. **Старое название темы никогда не меняется.** «Мемы и юмор», «Порно», «Фап контент» остаются названиями
   (`title`) как есть. В дереве они уже стоят под этими названиями.
2. **Старые синонимы никогда не удаляются.** У «Мемы и юмор» есть синоним «мемы и приколы», на него
   ссылаются 14 каналов и 127 записей истории. Синонимы дерева только добавляются к старым.
3. **`id` старых тем не меняется.** Он и так совпадёт, потому что считается от названия.
4. **Записи в истории, пуле, кэше и источниках не переписывай.** Они продолжат находить свою тему по строке.
5. **«Порно» и «Фап контент» не объединяй в одну тему.** Под каждой из них своя история оценок. Обе
   становятся частными темами внутри «Для взрослых 18+».
6. **Пользовательские темы вне дерева** не удаляются. Модель переложит их под подходящую общую тему из
   дерева, см. пункт 6 в A3.

После слияния выбор общей темы «Для взрослых 18+» сам подтянет источники «Порно» и «Фап контент». Это делает
`topic_related_norms()`: для общей темы она добавляет названия всех её частных тем. Так же «Мемы и юмор»
подтянет источники своих новых частных тем.

## Часть A. Дерево тем

(строка с `foreach (['db', 'db_access', 'core', ...`). Добавь `'topic_tree'` в этот список прямо перед `'topics'`.

### A2. Новые поля темы

В `topic_normalize_entry()` в `lib/topics.php` добавь три поля:

- `key` — строка из `TOPIC_TREE` или пустая строка. Принимай только значения по шаблону
  `/^[a-z_]+(\.[a-z_]+)?$/`.
- `seed` — `true`, если тема пришла из дерева.
- `nsfw` — `true` для веток `adult` и `shock` и их частных тем.

В `topic_public()` отдай `key` и `nsfw` в интерфейс. Больше интерфейс не трогай.

Добавь функцию `topic_is_nsfw($topic)`. Она находит тему через `topic_lookup()` и возвращает `nsfw` самой
темы или её родителя. Она пригодится позже для фильтров. Сейчас её никто не вызывает, это нормально.

### A3. Засев дерева

Добавь в `lib/topics.php` функцию `topic_tree_seed(): array`. Она возвращает счётчики
`['created' => n, 'updated' => n, 'moved' => n, 'skipped' => n]`.

Правила:

1. **Всё за один вызов `update_source_db()`.** Не вызывай `topic_save()` в цикле: каждый вызов переписывает
   весь каталог целиком.
2. **Ищи существующую тему по названию и синонимам дерева** через `topic_norm()`. Нашлась — обнови её,
   сохранив `id`, `aliases` пользователя, `profile`, `created_at`. Добавь синонимы из дерева к имеющимся.
   Поставь `key`, `seed`, `nsfw`. Если `about` пустой или тема не `smart`, замени `about` на текст дерева.
3. **Не нашлась — создай** с `id = topic_id_for($title)`, `classified => true`, `smart => true`,
   `seed => true`. Флаг `smart` нужен, чтобы `topic_classify_pending()` не переписала тему моделью.
4. **Место темы.** Общая тема дерева получает `scope = broad`, `parent = null`. Частная получает
   `scope = narrow` и `parent` равный `id` своей общей. Исключение: если у существующей темы стоит
   `manual = true`, её `scope` и `parent` не трогай и увеличь `skipped`.
5. **Существующая общая тема становится частной.** Так будет с «Порно» и «Фап контент», они уходят в
   «Для взрослых 18+». Это разрешено, только если у неё нет дочерних тем. Если дочерние есть, оставь её
   общей, увеличь `skipped` и выведи предупреждение через `cli_echo()`.
6. **Пользовательские темы, которых нет в дереве,** не удаляй. Если у такой темы нет `manual` и нет дочерних
   тем, сбрось ей `classified = false`. Тогда `topic_classify_pending()` заново подберёт ей родителя уже
   среди новых общих тем.
7. **Повторный запуск ничего не меняет.** Второй вызов должен вернуть `created = 0` и не изменить ни одного
   `id`, `parent` или `scope`.

### A4. Команда CLI

В `tools/cli.php` добавь команду `seed-topics` в том же стиле, что остальные `case`. Она вызывает
`topic_tree_seed()` и печатает счётчики одной строкой по-русски. Затем она печатает дерево: общая тема,
под ней частные с отступом. Возле nsfw-веток ставится пометка `[18+]`.

### A5. Подсказка для классификации новых тем

В `topic_ai_classify()` в `lib/topics.php` модель видит список всех тем. Добавь в правила одну строку:
если тема пользователя подходит под общую тему из списка, родителем надо выбрать её, а не придумывать новую
общую тему. Больше промпт не меняй. Маленькая модель и так склонна всё сводить к «Мемы и юмор», и длинные
правила ей мешают.

### A6. Проверка части A

Выполни по порядку и покажи вывод каждой команды в отчёте:

```
php -l lib/topic_tree.php

cp data/posta.sqlite data/posta.sqlite.bak-topics

sqlite3 data/posta.sqlite "select id, json_extract(data,'$.title'), json_extract(data,'$.parent') from topics where json_extract(data,'$.title') in ('Мемы и юмор','Порно','Фап контент')"
```

Ожидаемый результат:

- Второй запуск печатает `created = 0`.
- «Мемы и юмор» общая и сохранила `id` `t911dcb32`.
- «Порно» сохранила `id` `tcf1e4489`, «Фап контент» сохранила `id` `t0fe5642e`. Обе стали частными внутри
  «Для взрослых 18+».
- У «Мемы и юмор» среди синонимов по-прежнему есть «мемы и приколы».

Затем проверь, что каждая старая строка темы по-прежнему находит свою тему:

```

```

Все пять строк должны найти тему. «мемы и юмор» и «мемы и приколы» дают `t911dcb32`. «Порно» даёт
`tcf1e4489`. Обе строки «Фап контент» дают `t0fe5642e`.

Если хоть что-то не совпало, восстанови базу из копии и исправляй код:

```

```

## Часть B. Форма поста

Это отдельная ось. Она не зависит от темы. Мем с котом имеет форму `meme` и тему «Кошки».

### B1. Константа

В `config.php` рядом с другими константами анализа добавь:

```php
const CONTENT_FORMATS = [
    'meme'  => 'картинка или видео с наложенным текстом-шуткой',
    'photo' => 'обычное фото без текста-шутки',
    'video' => 'обычное видео без текста-шутки',
    'text'  => 'в основном текст: скриншот переписки, цитата, пост',
    'art'   => 'рисунок, комикс, 3D или сгенерированная картинка',
];
```

### B2. Схема и промпт анализа

В `lib/ai.php`:

- В `content_analysis_schema()` добавь поле `format` со `enum` из ключей `CONTENT_FORMATS`. Добавь его в
  `required`.
- В `content_analysis_prompt()` добавь одну строку после строки про `description`. В ней перечисли варианты
  из `CONTENT_FORMATS` в виде «ключ — описание». Добавь правило: для одной картинки не выбирать `video`.
  Не трогай начало промпта и порядок блоков: начало промпта общее для всех записей, и Ollama переиспользует
  его кэш.
- В `analyze_content_with_vision()` верни `format` в результате. Если модель вернула значение не из списка,
  ставь `video` для видео и `photo` для картинки.

### B3. Сохранение

Найди в `lib/parser.php` место, где результат анализа складывается в запись. Там уже есть
`'relevance' => $a['relevance'], 'rating' => $a['rating']`. Добавь рядом `'format' => $a['format']`.
Найди в `lib/content.php` функцию, которая отдаёт запись в интерфейс. Там есть строка с `'topic' =>`.
Добавь рядом `'format' => $item['format'] ?? ''`. Старые записи без поля должны работать как раньше.

Интерфейс и фильтры по форме не делай. Это следующий шаг, его пользователь решит сам.

### B4. Проверка части B

```

php -l lib/parser.php
php -l lib/content.php
grep -rn "content_analysis_schema\|analyze_content_with_vision" lib handlers tools
```

По выводу grep проверь, что все места, которые читают результат анализа, не ломаются от нового поля.

не падает на новом поле. Модель сам не запускай: она идёт на слабой видеокарте и занимает минуты.
