# Задача: вкладка «Календарь» — график «каналы × время» с карточками постов

Ты работаешь в PHP-проекте `/var/www/html/posta` (Posta: ИИ подбирает контент и публикует в Telegram; своя очередь
публикаций уже есть — см. `SCHEDULE_PROMPT.md`). Фронтенд — ES-модули без сборки, комментарии и тексты интерфейса по-русски.

**Бэкенд уже готов, его не трогай** (кроме пункта «Демо-режим» ниже). Твоя работа — фронтенд: новая вкладка,
файл `js/calendar.js`, разметка в `index.html`, стили в `css/app.css`, подключение в `js/main.js`.

## Что хочет пользователь (его слова, сжато)

Календарь — главное визуальное преимущество продукта. Это **график X/Y**: по X — время, по Y — «линии» ресурсов
(каналов), на линиях — точки-посты в виде **карточек**. Зум **колесом мыши**, и пользователя надо об этом
уведомить. Если карточек на графике много (мелкий масштаб) — они складываются в **каскад**; при большом зуме
раскладываются красиво. Перетаскивание поста на другое время меняет его время; **с зажатой клавишей — создаёт копию**
(быстрое дублирование тайм-слота). Каналы различаются цветом.

## Готовый API (не меняй)

Все вызовы — через `api(action, { body, params })` из `js/core.js`.

- `api('calendar')` (GET) →
  `{ connected, now, channels: [{id, title, username, schedule: {tz, jitter, slots: {"1": ["10:00","14:00"], …"7": […]}}, default, …}], posts: [...] }`.
  Пост: `{ id, at, status, channel, channel_title, text, full_text, media, error, thumb, url? }`.
  - `at` — unix-секунды (время публикации; у отправленных — запланированное время).
  - `status`: `queued` (ждёт нашей очереди), `sending`, `failed`, `telegram` (стоит в «Отложенных» самого Telegram),
    `sent` (уже опубликован, есть `url`).
  - `thumb: true` — есть картинка: `apiUrl('outbox_media', { id })` (функция `apiUrl` экспортируется из `core.js`) → `<img src>`.
    Без `thumb` рисуй иконку (📷/🎞 по смыслу — просто значок и число файлов `media`).
  - `id` у отправленных (`sent`) пустой — это не ошибка.
- `api('telegram_reschedule', { body: { id, publish_at } })` — перенести `queued`-пост на время (unix-секунды, не раньше
  чем через минуту, не дальше 60 дней — ошибки приходят как `Error.message` на русском, показывай их как есть).
  Также `{ id, slot: true }` — в ближайший свободный слот канала.
- `api('telegram_duplicate', { body: { id, publish_at } })` — копия `queued`/`failed` поста на другое время.
- `api('telegram_retry', { body: { id } })` — повторить `failed`.
- `api('telegram_cancel', { body: { id } })` — отменить/удалить пост (для `telegram` убирает и из «Отложенных»).
- `pickDateTime({ value: Date })` из `js/editor.js` — окно выбора даты/времени → `Date`, `null` («сразу») или `undefined` (закрыли).
- Образец, как это уже вызывается: `loadTelegramQueue()` в `js/account.js` (около строки 215).

Перетаскивать (двигать) можно **только `queued`**. Копировать — `queued` и `failed`. Остальные (`sending`, `telegram`,
`sent`) — без перетаскивания, только просмотр и кнопки в попапе.

## Раскладка

```
[ Календарь ]   [Сегодня] [День] [Неделя] [Месяц]  [−] [+]      подсказка в одну строку
┌────────────┬──────────────────────────────────────────────────────────────┐
│            │ линейка времени: дни / часы, сегодня выделено                 │
│ ● Канал А  │ ─────○────●───────▮card▮────────────────  (линия канала)      │
│   3 в очер.│                      ▮card▮ (каскад ниже)                      │
│ ● Канал Б  │ ──────────────────────●────────────────                       │
└────────────┴──────────────────────────────────────────────────────────────┘
```

- Слева колонка подписей линий (ширина 150px): цветная точка, название канала, «N в очереди». Справа «сцена» —
  `overflow: hidden`, `touch-action: none`, **вся геометрия — абсолютное позиционирование** в пикселях, пересчитывается
  функцией `render()` (через `requestAnimationFrame`) при любом изменении вида.
- Каждая линия канала — блок высотой ~170px: тонкая горизонтальная линия на высоте 26px от верха, карточки висят под ней.
- Вид задаётся двумя числами: `left` (время левого края, мс) и `pxPerHour` (зум). `x = (t - left) / 3600000 * pxPerHour`.
  Границы зума: от 0.8 px/час (виден квартал) до 900 px/час (видны минуты). Начальный вид: 8 px/час, левый край — сутки назад.
- **Линейка**: шаг делений выбирай из `[15м, 1ч, 3ч, 6ч, 12ч, 1д, 7д, месяц]`, чтобы между подписями было ≥ 70px. Подписи
  «14:00» при шаге < 1д, плюс подпись дня («Сб 25 окт») на границе суток; при шаге ≥ 1д — даты. Сутки с выходными
  (сб, вс) слегка затенены на линиях, если день шире 24px. Линия «сейчас» — красная вертикаль с меткой.
- **Слоты расписания** (`channel.schedule.slots`, ключ — день недели 1=пн…7=вс, значения «ЧЧ:ММ»): пустые полые кружки на
  линии канала в будущем, только когда `pxPerHour ≥ 3`. Слот, где уже стоит пост (±1 мин), не рисуй. Время слота считай в поясе
  канала `schedule.tz` (через `Intl.DateTimeFormat` с `timeZone`; аккуратно с переходом на летнее время — достаточно одной
  поправки на смещение пояса). Слоты — цели «примагничивания» при перетаскивании.
- Прошедшие посты (`sent`, а также всё, что раньше «сейчас») — приглушены (opacity ~0.6), с галочкой у `sent`.
- Статусы карточки: `failed` — красная рамка и «⚠»; `sending` — «…»; `telegram` — метка «в Отложенных Telegram».

## Карточки и каскад (главное)

Карточка 160×62px: цветная полоса канала сверху; **верхняя строка 20px — «шапка»: время «14:00» и начало текста в одну
строку с многоточием**; ниже тело: миниатюра (если `thumb`) или значок + 2 строки текста. Шапка нужна, чтобы
перекрытая карточка оставалась читаемой в каскаде. От точки на линии (в момент `at`) к карточке идёт тонкая «ножка».

Алгоритм раскладки для одной линии (напиши отдельной чистой функцией `layoutLane(posts, view)` → список элементов):

1. Отсортируй посты по `at`, посчитай `x`.
2. **Кластеры**: идём по порядку, новый кластер начинается, если `x − x_предыдущего ≥ 0.6 × ширина карточки` или
   `x − x_первого_в_кластере > 2.5 × ширина карточки`.
3. Кластер из **5 и более** постов → **стопка**: одна карточка-«кипа» (сзади две смещённые тени-слоя по 5px, бейдж «×N»,
   сверху — первый по времени пост; цвет `failed`-красный, если в стопке есть неудачный). Кластеры из 1–4 постов остаются
   отдельными карточками.
4. **Каскад**: все элементы (карточки и стопки) раскладываются по «ярусам» жадно: ярусов 4, у каждого запоминаем правый край
   последней карточки; элемент идёт на первый ярус, где `правый_край ≤ x_элемента − 4`. Сдвиг по вертикали — `ярус × 20px`
   (ярусы перекрываются вертикально — это и есть каскад, поэтому шапка 20px). Выше ярус — выше `z-index`. Если свободных
   ярусов нет, ставь на последний (перекрытие допустимо).
5. Результат: при малом зуме всё схлопывается в стопки и аккуратные каскады, при увеличении кластеры сами распадаются на
   отдельные карточки по ярусам — **без анимационных скачков**: добавь `transition: transform .15s` на позицию карточек
   (но отключай transition во время перетаскивания и панорамирования).
6. **Клик по стопке**: если можно увеличить масштаб ещё хотя бы вдвое — плавно приблизь вид так, чтобы кластер занял
   ~60% ширины сцены (анимация 250мс, `requestAnimationFrame` и интерполяция `left`/`pxPerHour`); если зум уже на пределе —
   открой попап со списком постов стопки.

## Управление

- **Колесо мыши над сценой — зум** вокруг курсора (время под курсором остаётся на месте):
  `pxPerHour *= Math.exp(-deltaY * 0.0015)`, затем поправь `left`. `preventDefault()` — слушатель добавлять с
  `{ passive: false }`. **Shift+колесо** или горизонтальное колесо (`deltaX`) — сдвиг по времени.
- **Тянуть за пустое место сцены** — панорамирование (pointer events + `setPointerCapture`); курсор `grab`/`grabbing`.
- Кнопки: «Сегодня» (центрировать на «сейчас» с анимацией), «День» (~120 px/час), «Неделя» (~12), «Месяц» (~3), «−»/«+»
  (зум ×0.6/×1.6 вокруг центра).
- Клавиши: `+`/`-` — зум, `←`/`→` — сдвиг на четверть экрана, пока фокус на сцене (`tabindex="0"`).
- **Уведомление о зуме**: сверху сцены плашка-подсказка «Колесо мыши — масштаб · перетащите фон — сдвиг · Ctrl или Alt +
  перетаскивание карточки — копия» с крестиком; показывать, пока пользователь не закроет (запомнить в `localStorage`, ключ
  `postaCalendarHint`, чтение/запись в `try/catch`). Кроме того, при каждом изменении зума на 1.2 секунды показывай в углу
  сцены текущий масштаб текстом: «масштаб: квартал / месяц / неделя / сутки / часы / минуты» (по `pxPerHour`).
- Заголовок под тулбаром: видимый диапазон текстом («23 окт — 30 окт 2026»), обновляется при движении.

## Перетаскивание карточки

Только для `queued`, через pointer events (работает и с тачем), порог начала — 5px.

- Во время перетаскивания карточка следует за указателем **по обеим осям визуально, но время меняется только по X**
  (по Y можно двигать для красоты ±12px, не больше). Пока тянем — не панорамируем и не зумим.
- Показывай **призрак**: вертикальную пунктирную линию на целевом времени через все линии и всплывающую подпись
  у курсора «Сб 25 окт, 19:00». Если зажат **Ctrl или Alt** (проверяй `event.ctrlKey || event.altKey` на каждом движении
  и на `keydown`/`keyup`) — подпись «⧉ копия · Сб 25 окт, 19:00», у карточки значок «+»; оригинал остаётся на месте и
  не гаснет.
- **Привязка**: целевое время карточки = время под её левым краем + смещение. Если в пределах 14px от слота канала
  (из расписания, не занятого) — прилипаем к слоту (подсвети слот); иначе округляем до 5 минут при `pxPerHour ≥ 40`, до
  15 минут при ≥ 12, до часа иначе.
- **Автопрокрутка**: указатель в 40px от края сцены — вид сдвигается 8px за кадр в ту сторону.
- **Отпускание**: если целевое время раньше «сейчас + 1 минута» — вернуть карточку на место (анимацией) и показать
  ошибку в статусной строке календаря. Иначе вызвать `telegram_reschedule` (обычное) или `telegram_duplicate` (с Ctrl/Alt),
  на время запроса карточка полупрозрачная; после ответа — перезагрузить данные (`loadCalendar()`), в статусной строке
  «Пост перенесён на …» / «Копия создана на …». Ошибка сервера → показать `error.message`, вернуть карточку на место.
- Нажатие `Escape` во время перетаскивания отменяет его.

## Попап карточки (клик без перетаскивания)

Небольшое окно рядом с карточкой (не выходи за край экрана), закрывается кликом вне, `Escape`, крестиком. Содержимое:
канал (с цветной точкой), время «Сб 25 окт, 19:00», статус словами, полный текст (`full_text`, `textContent`, с переносами),
миниатюра, текст ошибки у `failed`. Кнопки по статусу (готовые тексты бери из `loadTelegramQueue`):
- `queued`: «В слот» (`slot: true`), «Перенести…» (`pickDateTime`), «Копировать…» (`pickDateTime` → `telegram_duplicate`), «Отменить»;
- `failed`: «Повторить», «Копировать…», «Удалить» (`telegram_cancel`);
- `telegram`: «Отменить» (с `confirm`);
- `sent`: ссылка «Открыть в Telegram ↗» (`target="_blank" rel="noopener noreferrer"`, только если `url` начинается с `https://`);
- `sending`: просто «Отправляется…».
Для стопки — список постов (время + начало текста), клик по строке открывает попап этого поста.
После любого действия — `loadCalendar()` и сообщение в статусной строке. Удаление/отмену спрашивай через `confirm`.

## Данные и обновление

- `loadCalendar()` — запрашивает `api('calendar')`, кладёт в состояние, вызывает `render()`. Вызывается при открытии
  вкладки (`onTabOpen('calendar-tab', …)`), после каждого действия и раз в 60 секунд, пока вкладка открыта
  (используй `isTabActive` из `core.js`; не обновлять во время перетаскивания).
- Если `connected === false` или каналов нет: вместо графика — пояснение «Подключите Telegram-канал в «Личный кабинет» →
  «Соцсети», и здесь появится календарь» (без ошибок и пустого графика).
- Если каналы есть, но постов нет: график со слотами и пустой подсказкой по центру «Пока ничего не запланировано. Подберите
  контент на вкладке «Подбор» и нажмите «Запостить» → «Когда»».
- Один пост на линии своего канала: определи линию по `post.channel`; если канал поста не найден среди `channels` (удалён) —
  отдельная серая линия «Другие».
- Никаких `console.log`; ошибки сети — в статусную строку календаря (`role="status"`, `aria-live="polite"`).
